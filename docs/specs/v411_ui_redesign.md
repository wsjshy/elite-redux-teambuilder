## 0. 背景与目标

### 0.1 痛点（用户原话）

| # | 用户原话要点 | 暴露的问题 |
|---|---|---|
| P1 | 点进宝可梦详情「根本找不到重点，所有分析都堆在一起」 | 信息无层级，引擎分析与玩家结论混排 |
| P2 | 「首先要有精灵基础信息的介绍，基础信息都可以点击获取详细信息，比如特性究竟是作用」 | 基础信息只读、不可点；特性作用不可即查 |
| P3 | 「然后是各个流派的玩法和队伍推荐：流派要怎么玩、有什么设计亮点、队友要选哪些（肯定要有备选的）、队伍要怎么配招、特性如何、努力值如何分配——这些都直接给出来」 | 玩法 / 亮点 / 配招 / 特性 / 努力值 / 队友应前置直给，且队友必须有备选 |
| P4 | 「具体引擎是怎么分析得来的，可以隐藏起来」 | 引擎推导应默认折叠，不占玩家视野 |
| P5 | 「最终目的：玩家一眼就能看到想要的信息，没有冗余；对玩家完全没意义的内容不放」 | 需要一次「减法」重构：删冗余、升重点、藏推导 |

### 0.2 三层策略一句话

**把 v4.10 详情页的「一锅堆」重构为三层信息架构——L1 基础信息层（可点即查）→ L2 流派玩法层（核心直给：玩法 / 亮点 / 配招 / 特性 / 性格 / 努力值 / 道具 / 队友）→ L3 引擎细节层（默认折叠为「引擎视角」，只留可展开溯源）；用「默认只显示一层、点击就地展开」的减法，实现玩家一眼可见重点、零冗余。**

### 0.3 必须继承的既有裁定

| 裁定 | 内容 | 约束范围 |
|---|---|---|
| 多图少文 | 信息以卡片 / 徽章 / 条形图 / 图标承载，文字只做一句话结论 | 全文所有区块 |
| 响应式 | PC 横版 + 手机竖版双形态 | 见 §4 |
| 两段式交互 | 先概览、后详情 | 见 §3.1 |
| 就地展开 | **禁止全屏弹窗遮挡** | 见 §3.2 |
| 一层展开 | 信息默认只显示一层，点击展开 | 见 §3.3 |
| 机制溯源 | 机制解读的 combo 来源仍可查（展开态） | 见 §1.3.1、§2 第 12·13 行 |

### 0.4 本轮边界

- 只做**详情页**的信息架构与呈现减法；**不改变配招引擎的推荐结果本身**（唯一例外：v4.11 新增「努力值分配」输出，见 §5.1）。
- 不做视觉稿 / 代码实现，不做架构重构，**不改动数据层既有字段语义**。
- 引擎算得对的内容**不删除，只降级到 L3 或改写为玩家话术**——即「隐藏 ≠ 丢弃」，溯源仍可展开。

## 1. 详情页三层信息架构

### 1.0 总体结构

```text
详情页
├── L1 基础信息层（始终可见；全部基础信息均可点击获取详情）
│    精灵大图 · 名字 · 全国编号 · 属性徽章 · 种族值六维条形图（含总值）
│    特性 chip ──点击──▶ 内联展开「作用详情」（ER 机制解读 + 触发条件 + 可反查）
│    天性 chip ──点击──▶ 内联展开「天性说明」
│    属性克制 ──点击──▶ 就地展开「攻 / 防」两视角
│
├── L2 流派玩法层（核心；流派 tab / 卡片切换，不堆叠）
│    每流派一张卡，固定 8 字段 + 可选注意点：
│      ① 玩法一句话   ② 设计亮点   ③ 推荐配招   ④ 特性选择
│      ⑤ 性格        ⑥ 努力值分配 ⑦ 道具      ⑧ 队友推荐
│      ⑨（可选）注意点一句话
│
└── L3 引擎细节层（默认折叠「引擎视角 ▸」）
     ├─ 保留可展开：机制溯源 combo URL · 口径表 · 结论式「为什么这样推荐」
     └─ [隐藏] 引擎内部逻辑：评分过程 / 轴引擎推导 / 机制覆盖内部逻辑（见 §1.3.2）
```

### 1.1 L1 基础信息层

> **硬性规则：L1 内的一切基础信息都必须可点击获取详情。** 凡有「是什么 / 怎么算 / 起什么作用」的疑问，都能就地点击展开，**绝不跳走、不遮挡**。

| 字段 | 内容 | 呈现 | 点击详情（点击后展开的内容） | 数据来源（既有） |
|---|---|---|---|---|
| 精灵大图 | 资源图 | PC 居左 / 移动居上 | — | 精灵图相对路径（既有） |
| 名字 | 中文名（可含英文名） | 大字号 | — | 图鉴数据 |
| 全国编号 | #0xxx | 小字徽章 | — | 图鉴数据 |
| 属性徽章 | 单 / 双属性色块 | 徽章组 | 点击 → 属性间关系（可并入克制展开） | 图鉴数据 |
| 种族值六维 | HP / 物攻 / 物防 / 特攻 / 特防 / 速度 + **总值** | **横向条形图**（含总值行） | 点击某维 → 该维含义 / 分位说明 | 图鉴数据 |
| 特性 chip | 特性名（可多个） | chip | **「作用详情」**：ER 机制解读 + 触发条件 + 可反查（作用对象 / 相关招 / 相关道具） | `abiDescZh`（118 条中文 desc）/ `abiTags`（约 95 条）/ `glossary`（40 条口径） |
| 天性 chip | 天性名 | chip | 「天性说明」：该天性对属性的修正含义 | 天性档位数据 |
| 属性克制 | 攻 / 防两视角网格 | 网格 | **就地展开**：攻方「可打哪些」、防方「怕哪些」；**倍率口径说明下沉 L3** | `matchupSp`（18 属性 / 15,809 格 / 1,904 物种） |
| 概要道具 / 特性 | 概要层道具、特性 | 小字 | 与 L2 字段一致，反查保留 | `info.item` / `info.abi` |

**交互细则**

- 特性 chip 点击 → **就地展开**（优先）；仅当内容极长（词条解释）时使用**轻量 modal**（既有裁定）——小尺寸、可关闭，且不遮挡主信息。
- 特性 / 天性 / 属性克制三处均可一键收起；展开状态随会话记忆（同一宝可梦内切 tab 不重置，离开详情页重置）。
- **无数据不输出空壳**（如无天性则不显示天性 chip），维持「零冗余」。
- 六维条形图**始终可见**，不折叠（基础信息属第一层）。

### 1.2 L2 流派玩法层（核心）

**布局规则**

- 该宝可梦有几个流派就出几张卡；**通过流派 tab / 卡片切换查看，不纵向堆叠**（直接解决 P1「所有分析都堆在一起」）。
- PC：tab 横排；移动端：tab 横滑 + sticky（见 §4.3）。
- 每卡**固定 8 字段**，顺序固定（形成阅读肌肉记忆）；字段缺失则跳过、不占位。

**L2 流派卡 · schema 逐字段定义**

| 序 | 字段 | 定义（玩家可见最终形态） | v4.10 来源 | 呈现 | 交互 | 硬性约束 |
|---|---|---|---|---|---|---|
| ① | **玩法一句话** | 一句话说清「这个流派怎么玩」（玩家话术） | 流派卡「一句话简介」改写 | 卡首高亮行 | — | **禁止出现 P1 / P4 等原则引用**；原则引用一律折叠进 L3 |
| ② | **设计亮点** | 该玩法的机制亮点（好在哪 / 强在哪），**带溯源** | v4.10 机制解读徽标（`badge-mech`）+ 可配合组合区块 + 15 轴联动说明 | 要点列表（1–3 条） | 每条可展开「溯源」（combo URL / 机制解读） | 溯源属 L2 按需展开；**不带**内部判定标签 |
| ③ | **推荐配招** | 4 招 + 每招作用（一句话） | 引擎候选池 + 覆盖贪心结果（`bd.mv` 等） | 4 张招卡（图标 + 招式名 + 作用） | 点招式 → 招式详情（既有） | 数量固定 4；作用 ≤ 1 句 |
| ④ | **特性选择** | 推荐特性 + 理由（一句话） | `bd.abi` / 特性修正评估结论 | chip + 理由 | 点 chip → L1「作用详情」 | 理由用玩家话术，不写倍率式子 |
| ⑤ | **性格** | 推荐性格 | `bd.nat` | 徽章 | 点 → 性格含义反查 | — |
| ⑥ | **努力值分配** | 252 / 252 / 4 式配比（按流派模板） | **v4.11 新增输出**（见 §5.1，`[待拍板]`） | **横向条形图**（见 §4.5） | 点 → 模板说明一句话 | 本轮标注 `[待拍板]` |
| ⑦ | **道具** | 主推 + 备选（各 1–2） | `bd.it` / `info.item` | 徽章（主推高亮） | 点 → 道具反查（既有） | 主推 1 个 + 备选 ≥ 1 |
| ⑧ | **队友推荐** | **主推 2–3** + **备选 3–5**；每只配合理由 + 存档池「你拥有」标记 | 队友推荐 `recs` + 体系补盲队友（合并去重）+ 存档池投影 | 队友卡（图标 + 名 + 理由 + 标记） | 点队友 → 该宝可梦详情 / 适配说明 | 主推 2–3、备选 3–5；「你拥有」标记**仅在已导入存档时出现** |
| ⑨（可选） | **注意点** | 一句话风险 / 提醒 | 双刀补盲降级 + 天敌注意 + 15 轴弱点体系提炼 | 单行提示条 | 可折叠 | 至多 1 条；无则不显示 |

**字段间规则**

- ⑧ 的「备选」必须与「主推」在**视觉与文案上双重区分**，满足用户「肯定要有备选的」。
- ② 的溯源与 §1.3 的机制溯源**共用同一套数据**：L2 只展示结论，溯源按需展开，不与 L3 重复堆叠。
- 百分比 / 倍率式子**不得出现在 ①②④⑧**；确需数值时改写为「大幅 / 小幅 / 免疫」等玩家话术，精确数值放 L3。

### 1.3 L3 引擎细节层（默认折叠「引擎视角 ▸」）

**入口**：详情页底部（或 L2 卡尾）固定一条「引擎视角 ▸」折叠条——**默认收起**，点击**就地展开**，**不使用全屏弹窗**。

#### 1.3.1 L3 保留项（可展开，玩家可选读）

| 保留项 | 内容 | 依据 |
|---|---|---|
| **机制溯源** | 机制解读 / 可配合组合的 combo 来源 URL，可展开查证 | 既有裁定「combo 来源仍可查」 |
| **口径表** | 机制口径（`WCONF` 等）表格化，可展开 | v4.10 机制口径折叠块 |
| **结论式「为什么这样推荐」** | 一段短文字结论（**结论层，非推导层**） | 用户 P4 允许「隐藏」，但结论仍应有据可查 |

#### 1.3.2 L3 应隐藏 `[隐藏]` 的引擎内部逻辑（玩家无意义，不得出现在 L1 / L2）

> 本节即任务要求的「引擎内部逻辑应隐藏」清单。以下内容在 v4.10 多为可见或半可见，v4.11 一律**下沉至「引擎视角」折叠层内部、默认不可见**；标注**移除**者连 L3 也不保留。

1. `[隐藏]` **评分过程**（逐维度打分、权重、贪心覆盖过程、选招依据）。
2. `[隐藏]` **轴引擎推导**（侧判定、候选池构建、覆盖贪心、盲点 + 双刀补盲判定）。
3. `[隐藏]` **机制覆盖内部逻辑**（机制命中 / 前提改写 / 威力覆盖的中间量）。
4. `[隐藏]` **倍率构成式**（`pow × stab × hit × prio × cover × weather × func × abi`）。
5. `[隐藏]` `WCONF` **机制口径数值**（下沉「口径表」，默认折叠）。
6. `[隐藏]` **双刀补盲判定条件**（「本侧 ≤ 0.5x 且另一侧 ≥ 1x」）。
7. `[隐藏]` **15 轴协同的轴手判定 / 受益者判定内部标签**。
8. `[隐藏]` **需求驱动队友方案的方案级推导**（目标规模、补位、std / tight / full 多方案评分）。
9. `[隐藏]` **特性修正评估的聚合推导过程**（属性 × 天性 × 可选特性聚合）。
10. `[隐藏]` 结论式说明之外的一切**推导中间态**。
11. `[移除]` **耐久口径小字**（「物理耐久 = HP + 物攻 + 防御 … ≥ 300 判肉盾」）。
12. `[移除]` **RS 规则偏移校准行**（「强度校准（规则偏移层 · 确定性修正）」）。
13. `[移除]` **队友口径说明**（「正向体系构建…逐维度列分可解释」）。
14. `[隐藏 / 移除二选一]` **环境威胁榜**：默认折叠进 L3；仅将「天敌注意」一句话提炼进 L2 卡 ⑨ 注意点。

## 2. 冗余清单（逐项处置表）

> **处置口径**：**`保留溯源`** = 玩家可见且可展开查证；**`折叠 L3 [隐藏]`** = 引擎内部逻辑，下沉「引擎视角」默认不可见；**`改写`** = 换玩家话术后移入 L1 / L2；**`移除 [隐藏]`** = 彻底不输出。
> 「折叠」行与「移除」行**均属引擎内部逻辑应隐藏项**。

## 3. 交互规范

### 3.1 两段式：概览 → 详情

- **第一段（概览）**：列表 / 选择态，只给「选谁 / 选哪个流派」的最小决策信息。
- **第二段（详情）**：进入本页三层结构。
- 面包屑 / 返回随时一键回到概览，**不丢滚动位置**（会话记忆）。

### 3.2 内联展开，禁止全屏弹窗

- 所有展开均为**就地展开**（in-place）：展开区域推挤下方内容（accordion），**不覆盖、不遮挡**。
- **禁止全屏 modal / 抽屉遮挡主内容**；唯一例外：L1 词条解释的**轻量 modal**（小尺寸、可关闭、限定场景，见 §1.1）。

### 3.3 信息默认只显示一层

- 任何信息默认只呈现「一层」（结论层）；更深一层需**一次点击**。
- **禁止默认展开任何 L3 内容**；**禁止默认展开「溯源」**。
- 展开态是用户主动选择：切换 tab / 重新进入详情页，默认回到收起。

### 3.4 点击区 ≥ 44px

- 所有可点击元素（chip、tab、折叠加、队友卡、条形图维）**触控区最短边 ≥ 44px**（CSS px）。
- PC 鼠标态视觉可略小，但**热区仍保持 44px**（用 `padding` / `::before` 扩展热区）。

### 3.5 点击反馈

- 悬停：底色 / 边框微变（**禁止位移**，避免 44px 热区抖动）。
- 按下：0.08–0.12s 内高亮，或缩放 ≤ 0.98。
- 展开 / 收起：高度过渡 150–200ms；展开后**焦点移到新内容首元素**（键盘可达）。
- 状态可辨：展开态有明确箭头方向变化 + 视觉分组。

### 3.6 prefers-reduced-motion

- 侦测 `@media (prefers-reduced-motion: reduce)`：**关闭过渡与滚动动画**，展开即时呈现。
- 不依赖动画传递信息（动画仅作增强）。

### 3.7 无障碍与键盘

- 折叠控件用 `button` / `aria-expanded`；tab 用 `role=tablist` + 方向键切换。
- 徽章均配文字或形状，**不单靠颜色**区分。
- 正文对比度满足 WCAG AA（≥ 4.5:1）。

### 3.8 性能与懒渲染

- L3「引擎视角」内容**默认不渲染**（首次展开才渲染 / 计算），减轻长页负担。
- 队友卡图片懒加载（`loading="lazy"`）。

## 4. 移动端适配方案

### 4.1 断点与总体布局

| 断点 | L1 | L2 | L3 |
|---|---|---|---|
| PC 横版 ≥ 1024px | 左图右信息两栏 | tab 横排 | 底部折叠条 |
| 平板 768–1023px | 收紧为上下两层 | tab 可换行 | 底部折叠条 |
| 手机竖版 < 768px | **单列**，图居上 | **tab 横滑 + sticky** | 底部折叠条 |

**横向滚动仅用于**：流派 tab 条、队友卡横滑；其余一律纵向单列。

### 4.2 L1 卡布局（竖版）

- 顶部：大图居中 + 名字 + 全国编号 + 属性徽章（自动换行）。
- 中部：种族值六维**横向条形图**（标签左、条中、数值右对齐），**总值单独一行**。
- 底部：特性 / 天性 chip 组（自动换行）；属性克制网格（宽度自适应，超出时横滑兜底）。
- 点击展开的内容在**卡片内**向下展开，**不产生横向溢出**。

### 4.3 流派 tab 横滑 + sticky

- tab 条 `overflow-x: auto` + `scroll-snap`，激活项自动滚入视野。
- tab 条在滚动 L2 时 **sticky 吸顶**（含安全区），高度 ≤ 48px，**不遮内容**。
- 切换 tab 只换卡内容，**不重建页面**。

### 4.4 队友卡：横滑 / 网格

- **主推（2–3 张）**：横滑卡（每屏约 1.15 张露边，提示可滑）；或 ≥ 420px 宽时用 2 列网格。
- **备选（3–5 张）**：压缩为 **2 列网格**，或列表默认显示 3 张 + 「展开全部」。
- 每卡结构统一：图标 + 名 + 一句话理由 + 「你拥有」标记；卡高统一。

### 4.5 努力值分配条形图可视化

- 复用 L1 六维条形图，用**高亮叠加**表达 252 / 252 / 4：主投维饱和色、副投维次饱和色、余量 4 浅色。
- 或在条形图右端加「该维投入值」数字徽章（如 `252`）。
- 附一行模板名（如「速攻 · 252 速度 / 252 物攻 / 4 HP」）。

### 4.6 不遮挡原则（移动端）

- 所有展开层均在**文档流内**，不覆盖上方 L1 / L2 关键信息。
- 无固定浮层遮挡；如必须固定，**仅 sticky tab**（≤ 48px，半透明底 + 模糊）。

### 4.7 触控区与手势

- 所有热区 ≥ 44px（见 §3.4）；横滑区与纵向滚动不冲突（精确设置 `touch-action`）。
- 不禁用双击缩放（保持 `user-scalable` 可缩放），保证可读性。
