## 三、方案

### 3.1 P0 生成器脱钩（方案 A：承认产物为源）　**状态：✅ 已执行 2026-11-07（声明 + 文档对齐 + smoke 断言三层落地）**

**做法**：把 `build_tool_html.py` 从"生成器"降级为"校验器/归档脚本"，在文件头声明不再生成 v4.179；`index.html` 成为唯一真相源。

**理由**：反向移植 43 版增量需逐版 diff 产物与模板，工作量 2–3 人日且必然引入回归；而项目事实上已经用"直接改产物"的方式跑了 43 个版本，说明工作流可行。

**代价**：失去"一条命令重建全站"的能力。缓解：`tools/smoke.js` 承担"改完必过"的护栏，`tools/check_rebuild_faithful.py` 保留为数据层保真校验。

**回滚**：`git checkout v485 -- build_tool_html.py`。

### 3.2 P1 数据源合一（本轮执行）

**目标**：删掉 `data.js`，页面只认"CSV 源 + 三个分片"，兜底也走分片。

**步骤**：

1. **兜底块改分片**：`document.write` 依次拉 `data_lite_v498.js` → `data_species_v498.js` → `data_adv_v498.js`（顺序敏感：lite 先定义 `ERDATA`，另两个挂键）。
2. **本地 `data.js` 移入 `archive/`**（不删除，留作对照与本轮等价性证据的载体）。
3. **部署白名单** 6 项 → 5 项（去 `data.js`）。
4. **`smoke.js` 断言更新**：不再要求 `data.js` 存在；改为要求「兜底块含 3 个分片」+「`index.html` 不引用 `data.js`」。
5. **验证**：
   - 正常路径：`file://` 与 8901 下 9 Tab 全渲染、伤害值不变；
   - **兜底路径**：临时把 3 个分片改名制造同域 404 → 页面应转向 CDN 分片并成功就绪（这是本轮最关键的一条验证）。

**风险**：兜底块若写错，同域失败时页面会全空。缓解：先做 404 模拟验证，通过后才移 `data.js`；任一步失败立即回滚（备份 `index.html` + `archive/` 里的 `data.js` 可原路放回）。

**不做**：不动 `assets/showdown_sets_v496.json`（74 KB，是运行时按需 fetch 的功能数据，非死重）。

### 3.3 P2 文档拆分　**状态：✅ 已执行 2026-11-07**

- **原问题**：`AGENTS.md` 单文件 780,623 B / 3,272 行，**超过单次读取上限 256 KB** —— 号称"唯一入口"但实际一次读不完；体积集中在两段历史（§6 状态快照 232 KB 字符 + 版本块 190 KB 字符），合计约 70%。
- **做法**：`§9` 起版本记录下沉 `docs/changelog/VERSIONS.md`（319,245 B）；v4.55 / v4.82 状态快照下沉 `docs/changelog/STATE_snapshot_v4.55_v4.82.md`（414,969 B）；`AGENTS.md` 重写为 **208 行 / 28 KB**，保留 §1–§5、§7 准则（防卡死体系 / 测试方法论 / README 同步等硬准则一条不少）、§8 部署；§6 改为 v4.179 当前状态摘要，§9 改为索引。
- **验收**：`head + state + core + versions = 450,388 字符`，与原文长度**逐字符相等**，无内容丢失；拆后单次可读完。

### 3.4 P3 CSS 去重　**状态：✅ 已复核 2026-11-07，结论「不动」**

- **复核方法**：`analyze_css.js` 把 4 个 `<style>` 块（50,125 字符）按选择器拆开统计 → 106 个多次定义，其中**声明完全相同仅 3 个**，且这 3 个分别落在 `@media (max-width:640px)` 与 `@media (pointer:coarse)` 两个**不同媒体条件**下（条件不同即非冗余）。
- **103 个"有差异"的**是「一条基础规则 + 若干媒体查询覆盖」——响应式设计标准写法，合并等于拆掉响应式。
- **结论**：真冗余 **0 条**，**不改代码**。合并收益 <1 KB，风险是一次无法穷举的视觉回归，收益/风险倒挂。
- 内联 CSS 外置为 `.css` 能减体积、便于维护，但会破坏「`file://` 双击即可打开」这一前提，**同样不做**。
- **方法论教训**：`audit_quality.js` 的"重复选择器数"是启发式指标，任何这类指标下结论前必须先看上下文；照指标硬改会把一个本来正确的设计拆坏。

### 3.5 P4（不做）

- 模块化（193 处 inline onclick / 242 顶层 var）等于重写，在当前"产物即源"的形态下没有意义。
