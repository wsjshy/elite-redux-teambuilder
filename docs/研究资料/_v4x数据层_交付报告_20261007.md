## 1. D1 中文描述字典

### 1.1 覆盖池与结果

- 覆盖池（按任务口径）：`ABI_TAGS` 107 条特性 ∪ `MOVES_NOTES` 69 条招式 ∪ 战术模板（含新增 6 套）涉及招 ∪ `FUNC_MV` 43 条功能招 ∪ **威力≥100 攻击招 212 条** ∪ 全部天气/场地招 ∪ 对战常用功能招。
- **实测输出：moves 291 + abilities 118 = 409 条**（目标区间 300–500 ✓）。
- 特性侧 118 条 = `ABI_TAGS` 107 条 **+ 11 条补译**（`sysSet` 命中的设置手：`45/70/117/226/227/228/229/584/604/834/989`，即 SYS_SET 输出的每一个 id 都有自己的中文 desc，引擎层拿到 id 即可直接渲染）。
- 校验：`ABI_TAGS(107)` 与 `MOVES_NOTES(69)` **100% 落在 `mvDescZh`/`abiDescZh` 内**；全部 id 均存在于 gameData 与 ERDATA；无残留英文长词（允许 `HP`/`Mega`）；译文去重后 271 条（moves）/ 114 条（abilities），无占位重复。
- 生成期过滤器：`MV_DESC_ZH = {k:v for k,v in MV_DESC_ZH.items() if k in moves}`、`ABI_DESC_ZH = {…if k in _gd_abi_ids}` —— 双重保险，**未覆盖/无效条目不进 ERDATA**（引擎回退英文）。
- **实现形态**：`MV_DESC_ZH` / `ABI_DESC_ZH` 均为**手写字面字典**（逐条人工翻译，**无程序化机器翻译**），上表覆盖池是**人工选目依据**；程序只做「id 存在性」过滤，翻译内容不参与任何自动生成。锚点数值复核：`pwr >= 100` 的攻击招实为 **212 条**（gameData 字段名是 **`pwr`**，非 `power`）、`FUNC_MV` 去重后 **43 条**（`rec 8 / boost 11 / hazard 4 / removal 2 / speed 4 / protect 2 / pivot 2 / wear 2 / weather 8`，`boostPhys`、`boostSpec` 为 `boost` 子集）。

### 1.2 翻译口径

逐条基于 **gameData 英文 desc 原文**翻译；术语沿用官方汉化习惯：`recharge=僵直`、`recoil=反伤`、`Never misses=必中`、`frostbite=冻伤`、`STAB=本系加成`、`hazard=钉子`、`priority=先制`。
特性侧另有权威中文旁证可交叉核对：`ER2.65简汉化\特性文本.c`（官方汉化 `gAbilityDataTable[]`，含 `.name/.description/.fullDescription`），本轮译文与其语义一致（例：`91` 官方「1.5 倍→2.0 倍」↔ 本表「本系加成由×1.5提升至×2」）。

## 3. D3 FAMILY 形态家族表

- 构建：`gameData.species[].evolutions` 中 **`kd==1`（`EVO_MEGA_EVOLUTION` = Mega/Redux 道具进化）** 边 → `parent[target] = source` → 沿 parent 链上溯至链头（链头自身不是 kd==1 目标）＝ `rootId`。
- **字段语义勘误（实证）**：`evolutions[].in` 是 **species 数组下标**，不是物种 id —— `Venusaur {kd:1, rs:"ITEM_VENUSAURITE", in:1119}` → `GD['species'][1119] = 'Venusaur Mega Y'`(id 1501)。故构造用 `GD['species'][e['in']]['id']`。

## 10. MATCHUP_SP 预计算矩阵（v4.x 追加项｜克制页「点格看人」数据源）

### 10.1 语义（与引擎 `abiAdjOf` / `IMMUNE_RISK` 一致）

对**每只宝可梦**（1906 物种）× **21 攻击属性**，预计算「**实际承受倍率**」（天性档 `defCellTrio(s,at).inn`）：

```
基础 = ∏ 防守属性 × 攻击属性（ERDATA.matchup 21×21；码 0→0 / 3→0.5 / 1→1 / 2→2）
天性(inns) 修正（按 ABI_TAGS 语义）：
  im  → 该攻击属性伤害 = 命中短路为 **0**（优先级最高，不再乘算）
  hf  → 该攻击属性伤害 **×0.5**（乘法，非覆盖）
  add → 出场**附加防守属性**，并入防守属性列表后重查 21×21（可新增弱点/抵抗）
  phy / def / out / conv / nt → **不入矩阵**（物理侧减伤 / 全局减伤 / 转换，均与属性倍率无关）
```

**分层决策树**（与引擎 `IMMUNE_RISK` 同序）：① 属性免疫（基础表 0，如 地面 打 飞行）→ ② 天性 `im` → ③ `hf` 减半 → ④ `add` 属性并表重查。
**可选特性（`abis`）不入矩阵** —— 引擎 `openMxList` 注释即为「矩阵口径 = 天性档；若当前队伍已为这只勾选了可选特性，则按 tr 的差值叠加」，本矩阵严格只吃 `inns`。

### 10.2 存储与产出

- **字段**：`ERDATA.matchupSp` = `{攻属性名: {spId: 倍率}}`（**形状 A**，与引擎 `mxSpPre` 主路径一致；键为属性**中文名**，引擎用 `tk=[at,''+at,ti,'' + ti]` 兼容名/下标双键）
- **稀疏**：**只写入倍率 ≠ 1 的格**；未列出的格 = `1×`。**全 1 的攻击属性整列不入表**（`星晶 / 无 / 神秘` 三条全中性属性因此缺席）
- **产出**：并入 `配招工具_data.js`（`data['matchupSp']`，§6c 构建块 L280-370）；`build_tool_data.py` 构建期自检打印 + 档位断言
