## 四、构建输入保护（关键偏离与理由）

### 偏离：未执行「清工作区前移出保护项」
改为 **git worktree 隔离重建**：用 `git worktree add <wt> gh-pages` 建临时检出（`…\scratch\ghpages-wt`），在**该临时检出**中清内容、取部署集、提交；主工作区 `D:\game\elite-redux` **全程零清理、零删除**。产物树与 §8 流程完全等价（同分支、同部署集、同 blob）。

### 理由：清工作区会误删「保护清单之外」的不可再生文件
`git status --ignored` 实测，§8 的「清工作区」步骤会物理删除以下 ignored 项：

| `nn_models/`（66 文件，M5 模型产物） | ignored，不入库 | **否** |
| `_chk_script_1.js`（2.5 MB） | ignored（`/_*`） | **否** |
| `ER-source/`（16571 文件，含 `.git.bak` 上游克隆） | ignored | 是 |
| `nn_data/`（698 文件） | ignored | 是 |
| `ER2.65简汉化/` | ignored | 是（其中 2 文件） |
| `招式表_可学总表.csv` / `ER2.5正式版图鉴v0.5.xlsm` | ignored | 是 |

若按原流程仅移出清单内 5+2 项再清工作区，将**不可恢复地**删除 `assets/sprites/`（合图源）、`nn_models/`（M5 模型）与 `_chk_script_1.js`——重演 §12 事故。worktree 方案使该风险归零。
