## 第二层：卡级 `abiIds` 为空字符串

### 判定依据：不是判定输入

grep `abiIds` 共 22 处引用，**全部读物种级 `s.abiIds`**，没有一处读卡级：

```
L2325 / L4080 / L5587 / L14398 / L15214 / L15833 / L17679 / L17885 / L22026 / L22746 / L23763
```

其中 L15833 是关键：

```js
var id=(s.abiIds&&s.abiIds[ai]!=null&&s.abiIds[ai]!=='')?s.abiIds[ai]:abiIdByZhOrEn(n)
```

即使物种级 `abiIds` 缺失，也有 `abiIdByZhOrEn(名)` 兜底，所以**联动判定拿得到 id**。

### 数据真相

快照里卡的 `abiIds` **不是空字符串**，是逗号分隔 id 串：

```
#1[0] 妙蛙种子  abi="叶绿素|叶绿体|粉彩护幕"  abiIds="34,268,257"
```

全库 9842 张：`abiIds` 为空 675 张（6.9%）、含非数字 token 1626 张（16.5%）。这些都是**导出层字符串拼接的产物**（引擎内部 `b.abi` 是 `[{n,id,sc,why}]` 数组，快照用 `map` 压成了字符串）。

### 判定：不改

卡级 `abiIds` 只是快照/导出字段，引擎判定不读它。空值与非数字 token 不影响任何推荐结果。

> 附：AGENTS.md L2979 早已明确「`abis`/`inns` 是中文名数组，`abiIds`/`innIds` 是 id 字符串数组；写小写 `abids` 会得到 `undefined` → 空集」。台账里「所有卡 abiIds 为空字符串」这条描述与仓库文档矛盾，**以仓库文档为准**。

## 第三层：`core` 点名的招不在四招里（362 条）

### 语义先搞清楚

`core` 不是「必须带」的断言，是 `MECH_BUILD` 模板写死的**保护标记**——注释原文：

- L14425 `b.core=[144];b.choiceExempt=1;  /* v4.34：核心招落地校验 */`
- L14450 `b.core=[512];  /* v4.34 P0-1：核心招落地校验（净化/过滤不得清空杂技） */`
- L14695 `if(rec)b.core=[rec.id];  /* v4.34 P0-1：回复招为核心，净化不得清空 */`

即「这张卡的机制核心招，后续净化/过滤不得把它清空」。**它是防清空用的，不是承诺。**

### 284 条睡觉的根因：物种限制 + 睡觉门叠加（不是缺陷）

`_v395p1` 的功能槽循环里有这一行：

```js
if(_p===156&&!_v395SLP(_s))continue;
```

而 `_v395SLP`（L18443-18444）：

```js
var _v395SLP=function(_s){
  if(typeof isGlassCannon==='function'&&isGlassCannon(_s))return false;
  var _n=((_s.abis||[]).concat(_s.inns||[])).join('');
  return /梦话|自然回复|早起|不眠|活力/.test(_n);};
```

**只有带「梦话 / 自然回复 / 早起 / 不眠 / 活力」特性的卡才允许用睡觉**（否则睡眠两回合是纯亏）。而这个门槛恰恰是对的。

具体到个案：`#4 小火龙`（属性免疫联防位）四招是 **龙之波动 406 / 替身 164 / 过热 315 / 磷火 261** —— 零回复。小火龙能学的回复招只有睡觉，而它特性（猛火 / 太阳之力）不满足 `_v395SLP`，所以睡觉永远选不上。

**换句话说：这 284 张的推荐结果是对的（不该给脆皮配睡觉），错的是 `core=156` 这个标记本身** —— 模板把睡觉写进 core，规则却永远不允许它落地，于是 core 保护落空。

### 78 条攻击招缺失 = 模板写死、之后被选招顶替

例：

- `#67[1] 豪力`「全力攻击炮台」core=66 深渊翻滚，四招 蛮力276 / 地裂90 / 替身164 / 彗星拳309 —— 深渊翻滚被「蛮力」顶替（同为格斗物理 120，蛮力更优）。
- `#128[0] 肯泰罗`「胆量无盲流」core=416 终极冲击，四招 珍藏387 / 双刃头锤457 / 替身164 / 愤怒99。

### 判定：不改推荐，记为内部标记已知项

- **284 条睡觉**：推荐正确，core 过期。
- **78 条攻击招**：被更优招顶替，属正常选招结果，core 过期。
- 影响面：core 只被「净化/过滤不得清空」使用，且 v4.398 已删掉「core 点名日光招 → 豁免保留」这条依赖（删的理由正是「core 点名只表示机制思路与日光有关，不等于具备免蓄力条件」）。**当前没有活跃逻辑因 core 过期而给出错误推荐。**
- 若要彻底收口，应让 core 与实际 mv 同步（core 里不在 mv 的剔除或改写为实际落地的同类招）。但这是**内部标记维护**，玩家看不到，且涉及 284 张的标记改动，收益与风险不成比例 —— **登记，不动**。

## 这一轮学到的

1. **「零某物」类判据在动引擎之前，必须先查物种池**。第一层 11 张里 9 张是物种学不到，如果直接按「补一个消耗招」去改，会让引擎塞不能学的招 —— 这类假要求在 v4.401 的白名单设计里已经踩过一次（白名单含 270 帮助、203 挺住）。
2. **`core` 有两个语义要分清**：「机制核心招」用于防清空，「名实断言」才要求必须存在。混淆这两个语义，会把 362 条全部当成缺陷。
3. **台账本身会过期**。任务摘要里「所有卡 abiIds 为空字符串」「图图犬 `_di<0` 是漏洞」两条，实测都不成立；AGENTS.md 的原始记录反而是对的。**核实台账时以仓库文档与实测为准，不要以台账转述为准。**
4. **连续两版满足终止条件后，「找到缺陷」的冲动最危险**。本轮四层里没有一层能改善推荐 —— 承认这一点，比硬凑一个版本更有价值。
