# 配队联动口径（v4.346–v4.369 沉淀）

> 适用于 `index.html` 里所有「特性 × 招式 × 道具 × 流派」的联动判定。
> 这不是机制手册，是**判定纪律**：什么样的联动可以推、什么时候不能推。

## 一、总原则：代价 → 解法池 → 条件匹配

任何「有代价的强化/机制」都不能绑死一个解，按三段走：

1. **代价**：先说清这个机制让哪一项变差（破壳 -2 防 / -2 特防；杂技要求道具位已消耗；生命宝珠每回合自伤；讲究件锁招）。
2. **解法池**：把所有能抵消代价的手段列出来（道具 / 招式 / 特性 / 速度线 / 队伍轮转），至少 3 条。
3. **条件匹配**：只在这些条件成立时把某个解提首位；否则降为「备选」或干脆不提。

强绑定（`只要 X 就带 Y`）一律不允许。至少要多条件同时成立才绑，并且默认给次优解。

## 十五、队友副弹窗二级详情层（v4.404，不涉及判定）

- **问题定位**：`abiModal` / `mvModalById` / `itemModalZh` / `natModalZh` 四个详情函数都只做一件事 —— 拼好 body 后调 `l1Modal(title, html)`；而 `l1Modal` 是全局单容器（`#l1Modal`，`.lmod` z-index 300）。因此在队友窗内点四招，等于把队友窗内容原地换成招式内容，关掉后没有回程。
- **解法（守「同名口径必须同源」）**：不重写任何详情文案。新增 `#mqModal`（`.mqm`，z-index 400）作二级层；`mqOpen(label, fn)` 在**同步执行期间**把 `window.l1Modal` 临时替换成「渲染到 `#mqModalT` / `#mqModalB`」的包装，`try{fn()}finally{window.l1Modal = orig}` —— 四个既有函数照旧被调用、输出同源，只是落到了上层容器。
- **关闭语义**：一级（`l1Modal`）× / 灰底 / 按钮只关自己；二级（`mqModal`）× / 灰底 /「← 返回 队友·XX」只关二级，一级保持打开。两级互不联动。
- **为什么不改成弹层栈**：栈式改造要动 `closeL1Modal` 与 `.lmod` 结构，会影响全站所有详情弹窗（招式 / 道具 / 特性 / 性格 / EV 在主页面同样在用）。独立上层容器只影响队友窗这一条路径，爆炸半径最小。
- **判定零改动**：`mateAssemble` / `mateWhyNarr` / `findTeammates` 全部复用，只改渲染与点击去向。

## 十六、队友弹窗决策数字与属性对位表（v4.405，不涉及判定）

- **速度**：`speedStat((s.base||[])[5], ev[5], 31, spdNatCatOf(b.nat)==='加速')`。`speedStat` 本身不含 0.9 减速项，只吃 `natPos` 布尔 —— 照用引擎口径，禁止另写公式，否则与答案卡/详情页打架。`spdNatCatOf(性格)` 返回 `'加速'/'减速'/'中性'`（查 `NATURES[名]=[+项,-项]`）。
