# 仓库结构、分支与体量（内部口径）

> 面向维护者。回答三个反复被问到的问题：**为什么仓库首页显示旧提交**、**分支有没有冗余**、**仓库为什么这么大 / 哪些能删**。
> 对外文档（README / 使用手册）不涉及这些内容。

## 1. 部署链路：两个分支各自干什么

| 分支 | 作用 | 谁在读 |
|---|---|---|
| `master` | **源码主分支**，也是 GitHub 仓库的默认分支 | 人（看提交历史）、GitHub 首页 |
| `gh-pages` | **部署分支**，只放运行时需要的文件 | GitHub Pages 线上站点 |

**这是「线上页面正常、但仓库首页显示两天前」的全部原因**：线上站点由 `gh-pages` 生成，仓库首页显示的是默认分支 `master` 的最近提交。两者是两条独立的提交线，只要 `master` 没推，首页就一直停在上一次推送的时间点。

**正确顺序**（`tools/deploy_er.ps1` 只做前两步）：

```
1. 改 index.html
2. powershell -File tools/deploy_er.ps1      → 推 gh-pages（线上立刻生效）
3. git push github fix/<branch>:master       → 推源码（首页时间刷新）
4. git fetch github master:master            → 本地登记，不 checkout
```

**只做 2 不做 3** = 线上是新的、仓库看起来是旧的。v4.253 / v4.254 / v4.255 都已按上面四步走完。

## 2. 分支清单（2026-11-09 实测）

远端 `git ls-remote --heads github` → **只有 2 条**：

```
68d1ed3  refs/heads/gh-pages
604af7d  refs/heads/master
```

本地 `git branch` → **4 条**：

| 分支 | 状态 | 能否删 |
|---|---|---|
| `master` | = 远端 master | 不能 |
| `gh-pages` | = 远端 gh-pages | 不能（部署用） |
| `fix/abi-dedup-detail-20261108` | 当前开发分支，与 master 同点 | 不能（每次开发都从它出发） |
| `master-legacy-20261107` | **含 5 个未合并进 master 的提交** | **暂不能删**，见下 |

`master-legacy-20261107` 是 2026-11-07 那次大整理的备份，`git cherry master` 判定 **5 个补丁未进 master**：

```
c1746b6 清理 13 个 locked worktree + 抢救 43 版产物快照
8298e70 P3 复核：「40 个重复 CSS 选择器」是指标误读，结论不动代码
f915ebd P2 AGENTS 拆分：440 KB -> 28 KB，历史下沉 docs/changelog
a3ca89a P0 生成器正式退役：声明 + 文档对齐 + 冒烟断言
a324503 评估修复 + 工程护栏 + 数据源合一（v4.179）
```

其中 `tools/a11y-check.js`（295 行）**只存在于这条线**，当前分支没有。所以这条分支不是纯垃圾 —— 删了会丢 `a11y-check.js` 的引入历史和那批证据。

> 结论：**没有冗余分支**。GitHub 上若看到「17 个分支」，那是别的仓库或缓存的旧页面；本仓库远端一直是 2 个。

## 3. 两个 HTML 入口

| 文件 | 体量 | 是什么 |
|---|---|---|
| `index.html` | 1.65 MB | **唯一主程序**。9 个 Tab、全部计算逻辑都在这一个文件里 |
| `配招助手_ER.html` | 1.67 KB | **兼容跳转页**。`<meta refresh>` 到 `index.html`，防止老链接 404 |

`配招助手_ER.html` 不承载任何功能，只负责跳转，`<meta name="robots" content="noindex">` 让搜索引擎忽略它。

## 7. 版本号三处同步（v4.255 新增护栏）

| 位置 | 写法 | 例 |
|---|---|---|
| `index.html` | `var ER_ENGINE_VER='v4.255';`（**两段**） | 唯一真源 |
| `package.json` | `"version": "4.255.0"`（**三段**） | 对齐 `+ '.0'` |
| `AGENTS.md` | 版本表 `\| v4.255 \| 字节 \| SHA1 \| 状态 \|` | 文档登记 |

`tools/smoke.js` 第 33 项 `版本号三处同步` 会在任一处漂移时报警。

> 之前 `package.json` 停在 **4.179.0**，比实际版本落后 71 个号，正是因为三处各写各的没人对账。

**坑**：`ER_ENGINE_VER` 是**两段** `v4.255`，`package.json` 是**三段** `4.255.0`。写正则匹配三段会永远 null（本次踩过）。
