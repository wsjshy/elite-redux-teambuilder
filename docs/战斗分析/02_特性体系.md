## 一、机制说明（ER 实际规则）

### 1.1 四特性机制：可选池（abis）n 选 1 + 固定天性（inns）3 个

Elite Redux 最核心的战斗改动，是把"每只宝可梦 1 个特性"改成"每只宝可梦同时挂 4 项特性"。这套结构由本地权威数据 `ER-source\gameDataV2.65beta.json` 的 `species[].stats` 两个**定长数组**决定：

- `stats.abis` ——**可选特性池**（定长 3）：游戏内可从中 **n 选 1**；存档当前选中项实证 = `abis[0]`（土王 / 护城龙 2 样本吻合，AGENTS §3）。
- `stats.inns` ——**固定天性**（定长 3）：3 个**永远生效、不可更换**的特性（官方英文称 innate）。

于是"同时生效 4 项 = 1 项来自 abis 池 + 3 项 inns"。`配招工具_data.js` 的 `ERDATA.species` 把每只展开为中文名数组 `abis:[3]` / `inns:[3]`，与 `gameData` **同源、逐位一致**（出处：`_00_资料汇编.md` E.6）。

以游戏内真值样本土王 Mega（id 2232）为例，两表逐位对照：

| 字段 | gameData id | ERDATA 中文名 | 字段来源 |
|---|---|---|---|
| `stats.abis`（可选池，3 项） | 147 / 109 / 402 | 奇迹皮肤 / 纯朴 / 毒棘 | `gameData species[2232].stats.abis`、`ERDATA.species[2232].abis` |
| `stats.inns`（固定天性，3 项） | 834 / 11 / 840 | 毒沼制造者 / 储水 / 毒刺 | `gameData species[2232].stats.inns`、`ERDATA.species[2232].inns` |

网络侧有三方互证，唯措辞略有出入、落点一致：官方 Full Features 页写"**3 个可切换 + 至多 3 个固定（innate）**"；Smogon 的 ER 通关长帖写"every pokemon has four abilities active at once (three unchangable 'innates', and one variable ability thats chosen out of a pool of upto three, like regular games)"；产品整合页写"up to 3 switchable abilities along with up to 3 fixed ones (innates)"。三处说的都是"**1 项从至多 3 项池中选 + 3 项固定**"，与本项目"生效 4 项"的口径等价（`_01_ER资料检索.md` §1.1 已做此对照）。

对战场景下这套机制意味着三件事。**第一，特性必须分两类看待**：天性（inns）是**对手无法改变、我方无法回避的既定事实**，可写入联防基线；可选池（abis）是**战前可切换的选项**，是"潜力"与"对手变招空间"。二者混为一谈，防守剖面就会失真（详见 1.5）。**第二，同一只宝可梦因 abis 选择不同而扮演不同角色**：社区对 Dewgong 的解剖就是范本——它的天性固定为 Thick Fat / Water Veil / North Wind（北风自动铺 3 回合极光幕），而可选池 Fur Coat（物盾）/ Ice Scales（特盾）/ Arctic Fur（物特双减免 35%）决定它是哪一类盾。**第三，训练师全员满配**：ER 每个训练师队伍都被手工重做，带满道具、定制 EV 与 4 特性，因此"对手默认有 4 个特性 + 1 个道具"应当作基线假设，而不是例外（官方 FAQ / Full Features、RomProfessor）。

### 1.2 ABI_TAGS 标签体系：98 条 / 1034 特性

ER 共 **1034** 条特性，而 `build_tool_data.py` 的 `ABI_TAGS` 只把其中 **98 条**（约 **9.5%**）**标签化建模**。标签的语义（出处：`build_tool_data.py` 第 144–145 行注释 + 实读）与本次脚本对 `ERDATA.abiTags` 的复核计数如下：

| 标签 | 含义 | 作用面 | 顶层键出现次数 | 实读复核 |
|---|---|---|---|---|
| `im` | 完全免疫某属性 | 防守 | 25 | 覆盖 10 个攻击属性 |
| `hf` | 该属性伤害减半 | 防守 | 12 | 覆盖 9 个攻击属性 |
| `add` | 出场添加属性 | 攻防双向 | 4 | 龙 / 超能力 / 妖精 / 电 |
| `out` | 输出倍率（可带 `type`/`stat`/`cond`/`note`） | 进攻 | 43 | 见下举例 |
| `def` | 全局减伤系数（可带 `stat`/`cond`） | 防守 | 12 | 见下举例 |
| `phy` | 物理伤害系数 | 防守 | 2 | 毛皮大衣 / 毛茸茸 |
| `nt` | 人工备注（未量化的机制） | — | 11 | — |
| `cond` | 生效条件（晴 / 雨 / 沙 / 雪 / 异常 / <1/3 血…） | 修饰 | 13 | — |
| `stat` | 倍率作用于哪个能力项（atk/spa/def/spd/highest/both） | 修饰 | 4 | — |

对战含义可以概括成一句话：**`im`/`hf` 直接改写"这一只怕什么"，`add` 间接改写"这一只是什么属性"，`out` 决定"这一只打多疼"，`def`/`phy` 决定"这一只能挨多疼"**。前两类进防守剖面，第三类进进攻强度，第四类进耐久评级——这正是本项目引擎应当把特性接入的四个接口。同时必须清醒记住**覆盖度是硬边界**：98/1034 ≈ 9.5% 意味着**九成特性在引擎里等于不存在**（既不免疫也不减伤、也不增伤），因此任何"基于特性评分"的结论都必须显式声明这一前提，不能假装建模完整。

### 1.3 特性免疫 vs 属性免疫：两套免疫必须分开

承接 `01_属性克制体系.md` 1.4：ER 的"免疫"有两个独立来源。其一是**属性免疫**，即克制表内的 0 倍（电打地面、地面打飞行、钢免毒、妖精免龙……），它**永远生效、与特性无关、无法被任何特性手段取消**。其二是**特性免疫**，即 `ABI_TAGS.im` 描述的储水 / 引火 / 蓄电 / 飘浮 / 避雷针 / 干燥皮肤 / 引水 / 食草 / 正义之心 / 空气动力 / 蒸发 / 元素漩涡等，它**叠加在属性免疫之上**，且其中天性部分永久、可选部分可更换。

两者混算会掩盖关键信息：属性免疫是**结构性**的（这只宝可梦天生不吃这类招），特性免疫是**配置性**的（可以被"破格 / 兆级电压"这类穿透特性取消，也可以被对手的战前换特性规避）。因此在防守剖面里应当分列展示"属性免疫数 / 天性免疫数 / 可选池免疫数"三栏，而不是合成一个"免疫数"。

### 1.4 三口径评估（base / inn / opt）

引擎 `defCellTrio`（`build_tool_html.py` 第 690–729 行）对每一只、对 21 个攻击属性各算三个值，这是本项目对"特性如何影响防守"的核心抽象：

| 口径 | 计算定义（实读） | 生效范围 | 适用场景 |
|---|---|---|---|
| `base` 纯属性 | `defMult(基础属性, at)` | 不含任何特性 | 属性相性基准、跨版本可比 |
| `inn` 天性修正 | `defMult(base + 天性add, at)`，再 `天性im→0`、`天性hf→×0.5` | 只认 `s.inns` | **真实联防基线**（对手无法改变） |
| `opt` 天性 + 可选池最优 | 未勾选 = "池内最优"提示值；勾选后 = 勾选特性生效（覆盖池内其它） | `s.abis` + 用户勾选 | 潜力上限、点选模拟方案 |

以下是四个已实读的样本，展示 `base → inn` 的变化（数据出处：`_00_资料汇编.md` C.1、AGENTS §6）：

- **Storming**（水 + 飞行）被电打：`base` **4 倍** → `inn` **2 倍**——天性"闪电之躯"`add` 了电属性，电打电为 0.5×，把 4 倍弱点砍到 2 倍。
- **土王 Mega**：水 `base` 2 倍 → `inn` **免疫**——天性"储水"`im 水`。
- **雷电云**：电 `base` 1 倍 → `inn` **免疫**——天性"蓄电"`im 电`。
- **洛奇亚**：地面 `base` 1 倍 → `inn` **免疫**——天性"威严之翼"`im 地面`。

对战含义十分直接：**只有 `inn` 口径可以写进联防基线**，因为它是双方都无法在战斗中更改的事实。`opt` 是"如果我把可选特性换成某一项会怎样"的推演值——它既是对手可能做出的变招（对手也会换），也是本工具"点选模拟"的交互基础，但**默认不等于已生效**。

### 1.5 天性口径与可选口径：为什么必须分开统计

- **天性（inns）**：3 项永久生效。它是**对手视角的既定事实**，也是**我方组队时必须当成前提**的部分。队伍共同弱点、补位建议、核心弱点判断都应基于 `inn`。
- **可选（abis）**：3 项里选 1 项。未选中时引擎给出的是"池内最优"（`opt`），这是**潜力值而非事实**；用户点选某项后，该格才按"已选"重算。可选池的真正价值在于它给了同一只**一个免费的第二方案**——可以在战前按对手阵容切换，典型如 Dewgong 的 Fur Coat / Ice Scales / Arctic Fur 三选一。
- **分开统计的意义**：若把可选池免疫直接并入天性口径，会得到"人人全能"的虚假防守剖面（例如把某些队的"全队无弱点"算成常态），与真实对局不符；反之若完全忽略可选池，则会低估这只的上限，也会误判对手的变招空间。故引擎采取"**天性算基线 + 可选算潜力**"的双轨口径，这一取舍贯穿全文与后续所有规则。

## 三、对战决策影响

### 3.1 配招层面

**第一，选招要看对手的特性免疫，而不只是对手的属性。**这是 ER 配招与原版最大的操作差异。ER 里"水招撞储水 / 引水 / 干燥皮肤 / 蒸发 / 火焰形态"、"电招撞蓄电 / 避雷针 / 电气引擎"、"地面招撞 8 条 `im 地面` 特性"都是高频废招场景。因此一招的"期望价值"不能只看克制表倍率，还要乘上"该属性被对手可能持有的免疫特性挡掉"的概率——这也是 `IMMUNE_RISK` 应当从"文字提示"升级为"评分输入"的原因。

**第二，-ate 类特性会改写整只的招池价值。**一只带 Refrigerate / Pixilate / Aerilate / Galvanize / Hydrate / Normalize（id 174/182/184/206/315/96，本次实读 `gameData.abilities` 确认存在）的宝可梦，其普通系招会变成冰 / 妖精 / 飞行 / 电 / 水 / 一般属性，等于凭空获得一条打击面与（若给 STAB）一个第二本系。配招时应把它当"**隐性第二本系**"处理，而不是当"小增伤"忽略——当前 `ABI_TAGS` 对这 6 条**一条未收**，是明确的建模缺口。

**第三，免疫特性可以省掉一个补盲位。**若天性自带储水 / 飘浮 / 蓄电，四招里就不必为"挡水 / 挡地面 / 挡电"留功能位，可以把格子让给强化 / 回复 / 控速。反过来，若一只的防御命门（4 倍弱点）能被天性免疫覆盖，它的配招预算会宽裕得多。

### 3.2 组队层面

**联防评估用 `inn` 口径，`opt` 只作冗余保险。**队友推荐的"免疫你的弱点 +3 / 抵抗 +2"必须基于天性（对手无法改变）；可选池免疫记为"额外保险"，加分而不进基线。共同弱点统计同样按天性口径——若某属性的共同弱点 ≥2，补位建议应优先找"天性免疫该属性"的精灵，其次才是有可选池免疫的。

**可选特性决定同一只的多种定位，这是 ER 组队独有的弹性。**同一只 Dewgong，选 Fur Coat 是物盾、选 Ice Scales 是特盾、选 Arctic Fur 是双防盾；组队时可按"队里缺物盾还是特盾"临时切换，而不必再抓一只。引擎在渲染"流派卡"时应当把这层弹性显式呈现（当前 `pickAbiFor` 只按流派给前 2 名，未强调"可切换"这一点）。

**反特性手段要进队。**对手同样堆叠 4 特性，因此需要准备压制而非硬吃：破格 / 兆级电压类穿透（本项目尚未收录该族特性）、压制 STAB 的手段（GBACodes 提及 `Relic Stone`）、无视特性命中的克制招（GBACodes 提及 `Deadly Precision`）等。同时，由于对手"全员带道具"，拍落 / 戏法类削道具手段的期望收益也随之上升。

### 3.3 对战层面

**读对手的 4 特性面板，且优先读天性。**ER 战斗 UI 会直接显示 STAB 与包含特性修正的克制提示（官方 Full Features 明确说明），实战中最直接的判据来自游戏内提示，其次才是记忆。读的时候按"天性（永久）→ 可选（可能已换）"的顺序，天性才是可靠信息。

**换人优先级：属性免疫 > 天性免疫 > 可选池免疫 > 抵抗 > 中性（个人观点；排序依据：属性免疫不可被任何特性手段取消，天性免疫不因战前换特性而变，可选池免疫只在对手确实选了那一项时才成立）。**"特性免疫"在不被穿透时是硬免疫，价值等同属性免疫；而"可选池免疫"属于**概率性**判断，不能当作一定安全。

**警惕 `add` 属性的连锁。**天性"闪电之躯 / 飞龙 / 妖精飞行 / 意念悬浮"会在出场时改变属性，使原本的"安全换入"变成 2 倍弱点或反之。例：Storming 因天性 `add` 电，电招对它从 4 倍降到 2 倍（**反而变好**）；但若对手打出地面招，则要看该只当前是否已因其他特性不接地。任何"这只对某属性抗不抗"的判断，都必须走 `inn` 口径而非裸属性，这也是本文反复强调三口径的原因。

## 四、可执行规则建议

### 4.1 现状引擎评估

**已有实现**（对照 `_00_资料汇编.md` C 节，逐项实读）：

- `defCellTrio`（C.1）：三口径（`base`/`inn`/`opt`）评估 + `defProfiles` 队伍级聚合 + `abiBadges` / `rowAbiShort` 徽章 + `pickAbi` 可选特性点选（单选 / 取消 / 清除）。
- `pickAbiFor`（C.3）：流派内特性评分，`SYS_MAP` 体系 +3、`out` +3、`im` +2、`add` +2、`hf` +1、`phy`（仅肉盾 / 受队）+1、`nt` +1，取分前 2 展示。
- `IMMUNE_RISK`（C.7）：由 `ABI_TAGS.im` 反查 `ERDATA.abilities` 生成，用于队伍体检文字警示。
- 特性反查 Tab：名称 / 描述关键词搜索 + "天性 N / 可选 N" 统计 + 拥有者展开。
- `coreTags`（C.6）与 `coreIntensity`：以特性中文名正则识别"轮转肉盾 / 对攻吸血 / 站场强化"等细分定位，并以文字列出 `out`/`def` 强度。

**现状局限（本文档要解决的，逐条可复现）**：

1. **勾选可选特性会"顶掉"天性免疫（bug）**：`defCellTrio` 的 `pick` 分支（C.1 局限 2，`build_tool_html.py` 第 702–709 行）只把天性的 `add` 属性并入，**不再应用天性的 `im`/`hf`**。于是某只天性免疫某属性、用户又勾选了可选特性时，该格**反而会显示成未免疫甚至弱点**；该错误还会经 `defProfiles` 的 `v = row.pick ? c.opt : c.inn` **传播到队伍级共同弱点统计**，属于会改变结论的一级缺陷。
2. **`def` / `phy` 完全不进防守剖面**：12 条 `def`（多重鳞片 / 幻影防守 / 冰鳞粉 / 火鳞粉 / 太晶宝藏 / 合金外壳 / 脑容量 / 神奇鳞片 / 草之毛皮 / 花项链 / 可憎怪物 / 冰羽）+ 2 条 `phy`（毛皮大衣 / 毛茸茸）只在 `coreIntensity` 以**文字**列出（C.1 局限 1、C.6 局限 3），对生存力的贡献在格值里 = 0。
3. **`cond` 一律忽略**（C.1 局限 3）：`毅力（异常状态）`、`太阳之力（晴天）`、`茂盛（<1/3 血）`等按无条件理解，既可能高估（把满血减伤当常驻）也可能低估（把触发增伤当没有）。
4. **只覆盖 98 / 1034 条特性**（C.1 局限 4）：未收录 = 无建模；名称未命中（主名 + 别名都未收录）时 `abiTagOf` 返回 `null`，**静默跳过**，用户与引擎都不知道这里缺了东西。
5. **同属性多天性免疫只取首个**（C.1 局限 5）：`abiImHf` 里 `if(im[x]===undefined)` 的写法会丢掉"多条天性叠加"的信息。
6. **-ate 类属性转换特性完全未建模**：本次脚本实读确认 `gameData` 存在 6 条属性转换特性（Normalize 96 / Refrigerate 174 / Pixilate 182 / Aerilate 184 / Galvanize 206 / Hydrate 315），而 `ERDATA.abiTags` 98 条中**一条未收**（复核结果：这 6 个 id 均不在 `abiTags` 键内）。这既是覆盖率问题，更是**类别（tag 种类）缺失**问题。
7. **`pickAbiFor` 评分与防守口径脱节**：不区分天性 / 可选（天性 `im` 与可选 `im` 同权 +2）、不看该特性是否为体系核心（"雨盘"与"降雨"同 +2）、不含 `cond`、不看该只种族（C.3 局限 2、C.6 局限 2）。
8. **`IMMUNE_RISK` 只提示不影响选招**（C.4 局限 6）：`pickAttacks` 的评分完全不看对手特性免疫，导致"水招打一只天性储水的对手"照样被选进推荐。
9. **`coreTags` 依赖中文名正则**（C.6 局限 5）：译名 / 别名变动即静默失效。
10. **`opt` 未勾选时是"池内最优"**（C.1 局限 7）：跨文档、跨界面引用时极易被误读为"已生效"，需要在展示层强制区分。

**升级方向**：把特性从"文字/徽章"提升为**评分输入**——免疫与减半按"该属性在环境中的攻击权重"折算成防守分；`add` 并入属性计算；`out`/`def`/`phy` 合成等效攻防；`cond` 分级；勾选模拟修复天性丢失；未建模特性显式标注。
