**A.3 读取与自检**
- `ERDATA.types[9] = 地面`、`[2] = 火` → `matchup[9][2] = 1`（**火打地面 = 1 倍**；**原版标准表亦为 1 倍**——原版地面系弱点仅水/草/冰，火打地面 = 1x；此前「原版 2x」系标准表记忆错误，Bulbapedia / pikapedia / pokemons.io 三证，2026-10-06 修正）。
- `ERDATA.types[4] = 电`、`[12] = 水` → `matchup[4][12] = 1`（**水打电 = 1 倍**）。
- `matchup[4][9] = 2`（地面打电 = 2 倍）——同表内与常识一致，说明上两条并非"整表退化"。

**A.4 现状局限 / 风险**
1. ⚠ **末 3 行不是方阵**（星晶 19 格、无 20 格、神秘 21 格）——详见 D.9；当前因三属性全中性而结果正确，但属隐性 bug。
2. ⚠ **属性顺序与 S1 的 `typeT` 在 idx 18–20 不同**（S1：Mystery/None/Stellar；S2：星晶/无/神秘）——详见 D.8；**跨表按 index 直连会错位**，必须按名索引。
3. 表值来源为汉化图鉴 `ER2.65beta版图鉴v0.3.xlsm` Sheet1，`AGENTS.md` §6 记载其与官方 `battle_util.c sTypeEffectivenessTable`（2024-04 master，转置后）逐格零差异；§6 待办 0 仍把「火→地面 = 1」列为**待游戏内截图最终裁定**项。

### C.1 三口径评估（`defCellTrio`，第 690–729 行；配套 `effTypesOf` 658–665、`abiImHf` 675–688、`defMult` 666–671）

**三种防守口径的定义（实读）**

| 口径 | 计算 | 生效范围 |
|---|---|---|
| `base` 纯属性 | `defMult(t.base, at)`，`t.base` = 基础属性（t1 / t2，去重、去 `-`） | 不含任何特性 |
| `inn` 天性修正 | 先 `defMult(base + t.inn, at)`（`t.inn` = **天性** 特性里的 `add` 属性）；再 `if(ih.im[at]==='天性') inn=0`，`else if(ih.hf[at]==='天性') inn*=0.5` | **只认 `s.inns`（固定天性）**；可选池的 `add` 属性进 `t.ab`，**不入 inn** |
| `opt` 生效口径 | **已勾选**：`extra = t.inn + 勾选特性的 add`，`opt = defMult(base+extra, at)`，勾选特性 `im`→0、`hf`→×0.5；**未勾选**：`opt = defMult(base+t.inn+t.ab, at)`，`ih.im[at]!==undefined`→0，`ih.hf[at]!==undefined`→×0.5，再对 `s.abis` 单独扫 `onlyIm`（→0）/ `onlyHf`（→`min(opt, inn*0.5)`） | 未勾选时 = 「池内最优」**提示值**，不默认生效 |

**现状局限（逐条，均可从代码验证）**
1. **`def`（全局减伤）在防守剖面完全不生效**。`defMult` 只读 `matchup`；`多重鳞片(136)/影盾(231)/冰鳞(246)/铬镀层(539)` 等 12 条 `def` 标签只在 `coreIntensity`（1410）里以**文字**列出（`out.shield`），不改变任何防守格数值。`phy`（毛茸茸 0.5 / 毛皮大衣 0.5）同样不入格值。
2. **勾选可选特性会"顶掉"天性免疫**。`pick` 分支（702–709）只把 `t.inn` 的 **add 属性**并入，**不再应用天性的 `im`/`hf`**。即：某只天性免疫某属性、用户又勾选了可选池特性时，该格会显示成未免疫（可能反而显示为弱点）。此影响会经 `defProfiles` 的 `v=row.pick?c.opt:c.inn` **传播到队伍级共同弱点统计**。
3. **`cond` 条件一律忽略**：`毅力(异常时)`、`太阳之力(晴天)`、`茂盛(<1/3 血)` 等条件在防守剖面按无条件理解（对 `im/hf` 影响小，但因 `def`/`out` 不入剖面，实际只影响提示文字）。
4. **只覆盖 98/1034 条特性**；未收录特性 = 无建模（既不免疫也不减半）。名称未命中（主名+别名都未收录）时 `abiTagOf` 返回 null，静默跳过。
5. **同属性多天性免疫只取首个**（675–688 的 `if(im[x]===undefined)`），丢失"多个天性叠加"信息。
6. **未建模的防守相关因素**：天气/场地的防守增益（沙暴岩石特防 +50%、雪天冰系防御 +50% 等只存在于模板 `tips` 文本）、道具、等级/EV/能力值、异常状态、双打 spread 减伤。
7. **`opt` 未勾选时是"池内最优"**，容易被误读为"已生效"——UI 已用「可选」措辞与虚线徽章区分，但数值本身与 `inn` 并列展示，跨文档引用时须注明口径。

### C.4 打击面贪心配招（`atkCover` 1461–1470 / `coverHoles` 1675–1684 / `pickAttacks` 1471–1512）

**⚠ 首先纠正一处口径不符**：AGENTS.md §6 与任务描述给出的公式 `q × pow × stab × hitAdj × (novel?1:0.4) × prioAdj × (spread?0.9:1)`、函数名 `pickSet`、`strategy=cover` 在 **`build_tool_html.py`、`配招助手_ER.html` 中均不存在**（实读：`pickSet`/`novel`/`hitAdj`/`prioAdj` 出现次数 **0**；`nv*40`、`hole*25`、`function pickAttacks` 各 1 次）。以下为**代码实际逻辑**。

**① 候选池与初筛分（1472–1481）**
```
learn = lv ∪ tut 的招式 id 集合
过滤：非变化招（m[4] !== '变化'）；side !== '双刀' 时按 m[4] === (side==='物理'?'物理':'特殊') 过滤；pow < 55 丢弃
score = pow × (stab ? 1.6 : 1) × (prio > 0 ? 1.3 : 1) × (acc && acc < 85 ? 0.8 : 1)
        其中 stab = (m[3] === s.t1 || m[3] === s.t2)，prio = m[8]，acc = m[6]
```
（`hitAdj` 指的就是 `acc<85 ? 0.8 : 1` 这一项，但它乘在初筛分里，不是独立"加权系数"。）

**② 贪心逐槽（1485–1497）**，共 `n = 4` 槽：
```
nv   = 该招 atkCover 中「尚未被已选招覆盖」的属性个数
hole = 该招 atkCover 与 coverHoles(s)（本系最多 1× 的属性 = 盲点）的交集个数
v    = c.score + nv*40 + hole*25 + (slot===0 && c.stab ? 30 : 0)
每槽取 v 最大者；入槽后把其 atkCover 并入 covered，并 usedTy[属性] += 1
```
**③ 回填 1（1499–1504）**：按初筛分顺序补入**不同属性**高分招（`usedTy[ty] >= 2` 跳过）。
**④ 回填 2（1506–1510）**：仍不足 4 招则允许同属性补齐，取前 4。

**`atkCover(s,id)`**（1461–1470）：招式属性行 `matchup[tIdx(招属性)][*] >= 2` 的防守属性集合，**显式排除 星晶/无/神秘**。
**`coverHoles(s)`**（1675–1684）：`matchup[t1][t] × matchup[t2][t] < 2` 的属性（本系双属性相乘 < 2× 即视为盲点），同样排除 星晶/无/神秘。

**现状局限**
1. **两阶段两套打分**：初筛看 `pow×stab×prio×acc`，入槽看 `+nv*40 +hole*25 (+30)`；这两组权重的量级不可比（`score` 一般为两位数~三位数，`nv*40` 可达 400+），**实际是"覆盖优先、威力兜底"**，与"纯威力排序"或"纯覆盖"都不同口径。
2. **无 `novel` 系数**（"新属性降权 0.4"未实现），同属性两招在主槽阶段仍可能同时入选（只要覆盖属性不同）。
3. **无 `spread` 系数** → 双打 AOE 未降权；**无 `q` 参数**、无策略开关（只有单一贪心实现）。
4. **不看防守端倍率的期望值**：仅用 `coverHoles` 处引入盲点加成，不按"对手实际属性分布"加权；`pow` 用原始威力，未乘该招对目标属性的倍率。
5. **不考虑命中以外的副作用**：反弹（闪焰冲锋/勇鸟猛攻）、僵直（破坏光线/终极冲击）、能力下降（龙星群）、PP、`chance/eff` 均不参与。
6. **不考虑对手特性免疫**：`IMMUNE_RISK`（652–656 行由 `ABI_TAGS.im` 反查生成）只在队伍体检里做**文字警示**，不影响选招。
7. **`hole*25` 只对本系盲点加分**，非本系缺口（如"队伍整体覆盖缺口"）不参与个体配招。
