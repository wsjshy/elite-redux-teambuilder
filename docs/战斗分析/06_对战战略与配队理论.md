## 一、机制说明（ER 实际规则）

对战的胜负不取决于单只宝可梦的强弱，而取决于六个可控变量的组合：属性相性、生效特性、招式选择、能力分配、携带道具，以及前五者组合出来的**队伍结构**。ER 的特殊之处在于它同时放大了这六个变量的自由度——4 项特性同时生效、招式池被合并成单一可学池、物种数接近 1900、天气无限持续——于是「队伍结构」的差异被进一步拉开，而「单只强度」的解释力被进一步压缩。本节先把与组队直接相关的机制值落成可查证的数字。

### 1.1 队伍构成的六个机制变量

| 变量 | ER 数据源（字段） | ER 实读值 | 对战含义 |
|---|---|---|---|
| 属性相性 | `ERDATA.matchup`（21×21）、`types`（21） | 双属性相乘，最高 4x；`matchup[地面][火]=1`、`matchup[电][水]=1` | 决定「换人是否接近免费」，但只是最外层的一层过滤 |
| 生效特性 | `species.abis`（定长 3，n 选 1）+ `species.inns`（定长 3，固定） | 单只最多 4 项同时生效；`ABI_TAGS` 已建模 98/1034 条 | 免疫 / 减半 / 出场加属性 / 输出倍率，是「硬抵抗」的唯一来源 |
| 招式 | `moves`（1032）+ `species.lv` / `species.tut` | 可学池共 112,580 条（升级 40,299 + 教学 72,281） | 配招自由度 → 同一只可开出多套流派 |
| 能力 | `calcStat`（**公式无个体项**，等价 IV=0 口径） | 种族 + EV + 等级 + 天性修正 | 决定「能不能换进来吃下一击」——这是 Check / Counter 判定的前提 |
| 道具 | `items`（929 条，中文名 165 条、官方描述 701 条） | 剩饭 / 生命宝珠 / 气势披带 / 讲究三件套 / 凸凸头盔等常用件全覆盖 | 与特性一样直接改写角色分工（讲究系锁招、气腰保命、头盔反物攻） |
| 队伍结构 | 引擎聚合：`defProfiles` / `tplRecs` / `findTeammates` / 补位建议 | 12 套战术模板 + 三口径 + 补位 Top 4 | 把前五项组织成「一条能赢的路径」；这正是本文的主题 |

数据来源：`配招工具_data.js`（`ERDATA`）、`build_tool_data.py`、`build_tool_html.py`，逐项数值见 `_00_资料汇编.md` A/B/C/D 各节。

### 1.2 4 特性机制把联防从「属性游戏」变成「属性 × 特性游戏」

ER 单只同时生效 4 项特性（1 项从 `abis` 池 n 选 1 + 3 项固定天性 `inns`），官方 Full Features 页与 Smogon 的 ER 长帖对此表述一致（"three unchangable 'innates', and one variable ability thats chosen out of a pool of upto three"）。对本工具而言，可量化的是 **`ABI_TAGS` 98 条特性标签里，`im`（完全免疫属性）25 条、`hf`（伤害减半属性）12 条**，把它们按被免疫的属性归类，就能看出 ER 环境的免疫密度极不对称：

| 被免疫/减半的属性 | `im` 免疫特性条数 | `hf` 减半特性条数 | 特性举例（id） |
|---|---|---|---|
| 地面 | **8** | 1 | 飘浮 26、飞龙 312、隔空取物 511、高空杂技 606、巨翼 688、意念悬浮 715、终结烈日 746、妖精飞行 843；hf 坚实基础 904 |
| 水 | **7** | 1 | 储水 11、干燥皮肤 87、引水 114、蒸发 444、元素漩涡 665、终结烈日 746、火焰形态 871；hf 坚实基础 904 |
| 火 | 5 | **5** | im 引火 18、焦香之躯 446、元素漩涡 665、灼日 869、火焰形态 871；hf 厚脂肪 47、耐热 85、水泡 199、海草 342、深度冻结 764 |
| 电 | 3 | 0 | 蓄电 10、避雷针 31、电气引擎 78 |
| 恶 | 2 | 1 | im 正义之心 154、天才思想 422；hf 重金属 134 |
| 幽灵 | 1 | 2 | im 天才思想 422；hf 重金属 134、洁净之盐 547 |
| 虫 | 1 | 0 | 天才思想 422 |
| 草 | 1 | 1 | im 食草 157；hf 原木 337 |
| 飞行 | 1 | 0 | 空气动力 282 |
| 岩石 | 1 | 1 | im 登山 314；hf 化石化 303 |
| 毒 | 0 | 2 | 免疫 17、超净 855 |
| 冰 | 0 | 1 | 厚脂肪 47 |

三点直接的对战含义：

1. **地面与水是「免疫高发属性」**。地面有 8 条免疫特性、水有 7 条。这意味着「地震 → 岩崩 → 冰光」这类原版最稳的泛用物理打击链，在 ER 里被特性点掉的概率显著升高。Smogon 官方文章在论证特性价值时给的判据是「地震是全环境使用率最高的招式，因此免疫地面的飘浮是顶级特性」——ER 把这条逻辑推到了极致：免疫地面的特性不但多，而且分散在天性（固定生效）与可选池（可临时点选）两个来源上，**进攻方的预判难度因此上升**（个人观点）。
2. **毒与冰几乎没有免疫特性**（毒 0 条 `im`、冰 0 条 `im`）。这解释了为什么 ER 里「剧毒 + 钉子」的消耗路线比原版更可靠：它不容易被单一特性直接归零（毒只有 2 条减半，且都是「减半」不是「免疫」）。反过来说，冰系招式的价值提升主要来自**冻伤**（削特攻）而不是来自免疫压制。
3. **`im` 与 `hf` 的性质不同，不能同权**。`im` 让一招彻底失效（0 倍），`hf` 只把它压到 0.5 倍——前者逼迫进攻方换招/换人，后者只降低换人频率。这一点直接决定了本文第四节 R06-02/R06-03 的加权方式。

此外还有一层原版机制必须提醒：**飘浮（Levitate，id 26）不只是一条「免疫地面」标签**。按 Bulbapedia 对该机制的定义，飘浮会使宝可梦处于「不接地（ungrounded）」状态，因而同时免疫撒菱、毒菱、黏黏网以及场地效果。ER 的 8 条地面免疫特性里，只有 312（飞龙）、715（意念悬浮）、843（妖精飞行）在 `ABI_TAGS` 中标注了「出场添加属性」，**其余各条是否附带「不接地」属性，必须逐条回查 `gameData` 的特性描述**（本文不臆测，列为 R06-22 的落地前置）。

### 1.3 可学池合并决定了「多流派是常态，不是特例」

ER 官方 FAQ 明确写着「There are no TMs, HMs, or Move Tutors anymore, only these four categories.」——招式来源只剩 Level 与 Physical / special / stat 三类，本地数据完全吻合：全表 1907 条物种中 `eggMoves` 非空 **0** 条、`TMHMMoves` 非空 **0** 条，而 `levelUpMoves` 非空 1905 条、`tutor` 非空 1907 条（`_00` D.6 / E.4）。合并后的可学池共 **112,580** 条，摊到 1906 只上平均约 **59 条/只**。

对战含义有两层，且第二层才是关键：

- **对个体**：同一只宝可梦可以同时具备「特攻核心」「物攻核心」「肉盾消耗」「天气体系」「受队铺场」多套可行配置（引擎 `genBuilds` 已按种族 + 本系招 + 强化招 + 耐久 + 体系自动产出 2–5 套）。因此「这只强不强」不是正确的问题，「**这只在这支队里扮演什么角色**」才是。
- **对队伍**：招式来源丰富意味着配招的差异化空间变大，**全队覆盖的价值高于单只最优**。这正是用户对旧引擎「纯威力排序」批评的实质——按单只威力最大化去配，6 只会被配成同一种功能（都带最高威力本系 + 回复 + 强化），结果全队出现同一个天敌、同一条覆盖缺口，结构上失去冗余。修法不是「把威力权重调小」，而是让选招同时读取队伍级缺口与对手特性免疫（见 R06-19 / R06-04 / R03 系列）。

### 1.4 天气与场地在 ER 的定位是「节奏工具」

ER 把晴 / 雨增伤从 50% 削到 20%，同时保留了「天气特性 → 无限持续」，并新增了「冰系在冰雹中防御 +50%」（官方 Full Features）。本工具的体系常量给出的是可枚举的清单：`SYS_SET` **9** 条（真正的设置手）与 `SYS_MAP` **21** 条（体系归类，含 12 条受益特性）。

| 体系 | 设置手（`SYS_SET`） | 受益特性（`SYS_MAP` − `SYS_SET`） | ER 的关键调整 | 战略定位 |
|---|---|---|---|---|
| 雨 | 降雨 2、雨幕 | 悠游自如、雨盘、干燥皮肤 | 增伤 20%；打雷 / 暴风必中；无限持续 | 节奏工具：抢速度 + 必中压制 |
| 晴 | 日照 70 | 大叶子、叶绿素、太阳之力 | 增伤 20%；日光束免蓄力；太阳之力每回合掉血 | 节奏工具：日光束 + 提速 |
| 沙 | 扬沙 | 拨沙、沙之力、沙隐 | 岩石系特防 +50%；不因换宠结束 | 半受：持续削血 + 岩石特防 |
| 雪 | 降雪 | 拨雪、冰冻之躯 | 冰系防御 +50%；冻伤（1/16 掉血 + 特攻减半） | 半受：极光幕 + 削特攻 |
| 电场 | 电气制造者 | 发电机 | 电招 +30%（模板文本）；全队免疫睡眠 | 攻：电系提速压制 |
| 精神场地 | 精神制造者 | — | 超能招 +30%；防先制 | 攻：破先制 + 超能炮台 |
| 青草场地 | 青草制造者 | — | 草招 +30%；每回合回 1/16 | 受：续航 |
| 薄雾场地 | 薄雾制造者 | — | 龙伤减半；全队免疫异常 | 受：防消耗 |

数据来源：`build_tool_html.py` 的 `SYS_SET` / `SYS_MAP` / `WEATHER_MV`（8 条手动天气/场地招 id：240 求雨、241 大晴天、201 沙暴、258 冰雹、604 电气场地、641 精神场地、580 青草场地、581 薄雾场地），见 `_00` D.7；`tips` 逐条见 `_00` C.2。

**这意味着天气队的胜负手已经从「伤害」转移到「节奏」**：雨天真正的收益是「打雷 / 暴风必中」与「悠游自如速度翻倍」，而不是水炮那 20%；雪天的收益是「极光幕 + 冰系 +50% 防 + 冻伤削特攻」，即一套半受骨架。同时，场地体系在 ER 里确实**被收录**（四个场地招 id 与四个场地制造者特性均在本地数据中命中，且 12 模板的 keys 校验 0 未命中，见 `_00` F），但**场地倍率（模板文本写 +30%，原版为 ×1.5）与持续回合仍需游戏内实测**——这是 `_02` §4.5 标注的待验证项，本文只能确认「收录与否」，不能确认「数值多少」。

### 1.5 联盟与道馆是「主题队伍」，不是随机阵容

官方文档把「每一位训练师及其完整队伍」列入 NextDex（"all the available trainers in the game plus thier pokemon team's complete info"），因此 ER 的关卡是**可针对性备战的**：

| 关卡 | 训练师 | 主题 | 备战要点 |
|---|---|---|---|
| 四天王 1 | Sidney | 恶 | 恶系输出、先制、拍落消耗；备格斗 / 妖精答案 |
| 四天王 2 | Phoebe | 幽灵 | 幽灵输出、状态、先制；备恶 / 幽灵答案 |
| 四天王 3 | Glacia | 冰 | 冰系输出、天气或双墙压力；备火 / 格斗 / 岩石 / 钢 |
| 四天王 4 | Drake | 龙 | 龙系强化 + 强打击面；备妖精 / 冰 / 钢 |
| 冠军 | Wallace | 水 / 雨 | 厚实水系 + 雨天压制；备草 + 电双覆盖，并需要水抗中转 |

来源：RomProfessor 的联盟攻略（`_01` §3.1）与官方 documentation 页（`_01` §1.4）。三条推论：

1. **针对性备战可行**——官方 Level Caps 页直接建议「针对下一个挑战做配队」，本工具的 12 套模板正是「主题队骨架」的可复用版本。
2. **单主题队会在下一关失效**——攻略给的建议是「关键答案各备两份」（"Bring backup answers for every Elite Four member"），所以 6 个槽位必须容纳两套答案，这与 Smogon 组队框架里「角色定额」（HO 2–4 清场 + 1–3 破盾……）的思路一致：**槽位是按角色分的，不是按精灵分的**。
3. **BOSS 同样吃满 4 特性 + 道具**——攻略原文强调 "standard type-matchup thinking is not enough... may suddenly be much harder to break because of its innates"。这直接决定了第四节的「反特性手段检查」（R06-24）与「关键答案备两份」的量化（R06-06）。

## 二、与原版/常规差异（重要）

ER 的战略层差异不是零散的数值修补，而是**同时朝两个方向拉扯**：一方面把免疫密度和配招自由度推高（队伍更难被单招打穿，也更难靠单招打穿别人），另一方面把天气的爆发力削平（节奏工具化）。下表逐条给出差异、证据与对战含义。

| # | 差异 | ER 值 | 原版 / 常规值 | 证据（文件 / 字段） | 对战含义 |
|---|---|---|---|---|---|
| 1 | **4 特性机制** | 单只最多 4 项同时生效（1 项 `abis` 池 n 选 1 + 3 项固定 `inns`） | 1–2 特性 + 隐藏特性 | `species.abis` / `species.inns`；官方 Full Features；Smogon ER 长帖；`_01` §4 三源互证 | 联防从属性游戏变属性×特性游戏；免疫密度上升 → 进攻方需要「免疫穿透」或双打击面；防守方需要「反特性」 |
| 2 | **招式池合并（无蛋招 / TM / 教学界面）** | `lv` 40,299 + `tut` 72,281 = 112,580 条，约 59 条/只 | 升级 / TM / 蛋招 / 教学分层 | `gameData`：`eggMoves` 非空 0、`TMHMMoves` 非空 0（`_00` E.4）；官方 FAQ | 配招自由度大增 → 同只多流派成为常态；「这只需要遗传才有某招」的原版备战结论在 ER 无效 |
| 3 | **天气增伤** | **20%** | 50% | 官方 Full Features（"Damage bonus reduced to 20% for Sun/Rain"）；`ERDATA.templates[0].tips[0]` | 天气队从「核弹」降为「节奏工具」：收益转向上速度（悠游自如 / 叶绿素）与必中（打雷 / 暴风 / 暴风雪） |
| 4 | **天气持续** | 天气特性 → **无限持续** | 5 回合（靠道具延长） | 官方 Full Features；模板 tips「ER 无限天气」 | 不再需要反复开天气 → 设置手槽位可以更少；反制手段变成「用对手的天气特性抢归属」 |
| 5 | **冻伤替代冰冻** | 每回合 1/16 掉血 + **特攻减半**，冰雹中触发概率 ×3 | 冰冻（概率无法行动） | 官方 Full Features；`gameData` moves 描述写 frostbite（如冰冻拳 id 8）；`_00` E.3 | 冰系招附带价值上升；「削特攻」成为抗特攻手的新手段——但**对物攻手毫无压制力**，不能当控制用 |
| 6 | **冰系在冰雹中防御 +50%** | 有 | 无 | 官方 Full Features；模板 tips | 冰系肉盾在 ER 成立（原版不成立）→ 雪天半受骨架可用 |
| 7 | **个体值** | 默认满，但**不参与能力公式**（IV=0 口径） | IV 31 参与公式 | `calcStat` 公式无 IV 项；`_00` E.5 十二项真值全吻合 | 能力值可精确预测 → 「换入承伤阈值」可计算，Check / Counter 双档判定（`_02` §1.7）在 ER 才有落地可能 |
| 8 | **属性体系** | 21 属性（+星晶 / 无 / 神秘，全中性） | 18 属性 | `ERDATA.types` / `matchup`；`_00` A.1 / D.8 | 新增 3 属性不参与克制；跨表必须按属性名索引（gameData 与 ERDATA 在 idx 18–20 序不同） |
| 9 | **克制表特例：火 → 地面** | **1x** | 2x | `ERDATA.matchup[地面][火]=1`；用户游戏内实测 + 官方源码转置逐格比对三源一致（`_00` E.1） | 火系打击面缺口 +1 格；地面系精灵少一个 2x 弱点，防守价值上升 |
| 10 | **水 → 电** | 1x | **1x（与原版一致）** | `ERDATA.matchup[电][水]=1`；用户实测（`_00` A.3） | 无差异；此前记录误标「原版 2x」已更正，配队时不要按「水克电」或「电抗水」的错误记忆排布 |

## 三、对战决策影响

本节按「配招 / 组队 / 对战」三个决策场景，给出「决策场景 → 考量因素 → 推荐决策」的推导，而不是结论清单。三个场景共享一个前提：**ER 中任何单维判断都会失效**——只读属性会低估生存力（漏掉 4 特性），只读威力会做出纸面好看的核心（漏掉环境宽度与角色分工），只读种族会误判定位（漏掉特性带来的输出倍率与减伤）。

### 3.1 配招层面（选什么招、怎么选）

- **场景 1：攻手第 1 槽（本系主力）**
  考量因素：本系乘子 1.5（特性「适应力」提升到 2.0；ER 还有「神秘之力」id 287 让**全部招式**获得本系加成，`ABI_TAGS.out`）；以及该招式属性在 1.2 节表中的**免疫密度**。
  推荐决策：第 1 槽优先「高威力本系」这条通则不变，但**必须先查该属性的免疫风险等级**——火 / 水 / 地面 / 电是高风险（分别有 5 / 7 / 8 / 3 条免疫特性），毒 / 冰 / 龙是低风险。高风险属性的本系主招应配一条不同属性的第二输出，低风险属性可以放心堆威力。

- **场景 2：第 2 / 3 槽（打击面）**
  考量因素：`atkCover(s,id)` 给出的 2x 覆盖集合、`coverHoles(s)` 给出的本系盲点、以及**队伍级**覆盖缺口（`renderAnalyze` 的「覆盖缺口」列）。
  推荐决策：以「最小覆盖集」为目标——优先补 0.5x / 0x 的缺口属性，而不是在已被覆盖的属性上叠加更高威力的同类招。这与 Smogon 对理想攻手的定义一致（对全属性至少中性，使任何换入都要付出代价），也是 `_02` §2.2 建议的「把盲点检查升级为最小覆盖集搜索」的直接落地。

- **场景 3：第 4 槽（功能位）**
  考量因素：**队伍缺什么**，而不是这只擅长什么。ER 的功能招池是窄的：回复 8 招（`FUNC_MV.rec`）、钉子 3 招（`hazard`）、控速 4 招（`speed`）、强化 11 招（`boost`）、保命 2 招（`protect`）、轮转 2 招（`pivot`）、消耗 2 招（`wear`）。
  推荐决策：功能位由队伍缺口决定；因为可选面窄，**同队重复同一功能招的边际收益很低**（第二颗隐形岩不增加伤害），引擎应把「该功能是否已被队友提供」作为选招的减权项。

- **场景 4：要不要做双刀**
  考量因素：`_02` §2.4 给出的条件是「双侧攻击种族都够用（400+ 量级）且双侧招式池都够深」。
  推荐决策：在 ER 中**双刀门槛应当比原版更严而不是更松**（个人观点）——因为池子大，单侧也能凑出 4 招覆盖；只有当双刀能带来结构收益（打对方墙较软的那一侧、或换掉一条命中率差的不可靠本系招）时才值得牺牲一个槽位。这也正是现有 `genBuilds` 双刀分支 70/70 阈值偏松的地方（见 4.1）。

### 3.2 组队层面（选什么精灵、怎么配合）

- **场景 1：从一只核心起步**
  考量因素：`coreRole(s)` 的定位、天性口径弱点（`coreWeak`）、以及这只的**进度手段**（强化 / 破盾 / 破受 / 捕获，`_02` §5.4 的四种）。
  推荐决策：先回答「这只要怎么帮队伍赢」，再去找队友。若一只既不强化、也不破盾、也不破受、也不能捕获，它在本队里就只是在拖回合——引擎应对这类「空转位」给出显式标签（R06-11 / R06-12）。

- **场景 2：补位**
  考量因素：队伍共同弱点（`defProfiles` 的 `agg.w >= 2`）、完全无法命中的属性、以及对**具体某一只**的 Check / Counter 关系（`_02` §1.7：Counter 需通过「换入吃一击后仍高于 2HKO 线」的门槛）。
  推荐决策：优先选「能免疫 / 抵抗共同弱点、且不引入新的共同弱点」的候选；ER 中由于免疫来源多（属性免疫 + 特性免疫），**免疫权重要高于抵抗权重**——现有补位评分「免疫 +3 / 抵抗 +2」的方向是对的，但缺了「是否引入新共同弱点」的扣分项（R06-07）。

- **场景 3：面对 1906 只的选择面**
  考量因素：环境宽度使「逐只对比」不可行。
  推荐决策：**用角色筛，而不是用名单筛**：先用 12 套模板的 `match` 拿到候选池，再用补位规则收敛到 Top N，最后用「是否与现有成员功能重复」做去重。这也说明为什么模板的匹配权重（R06-04）比模板的数量更重要。

- **场景 4：非最终形态**
  考量因素：`nonFinal` 640 只（约 33.6%），默认被 `optFinalOnly` 过滤。
  推荐决策：推荐场景默认排除是合理的（推荐目的是「能长期用」）；但**手动查询必须保留全部**（现状已保留，正确）。需要补的是把「形态关系」显式化——同一物种的不同形态 id 不同，补位建议可能推荐一只与队伍成员功能完全重叠的形态（`_00` C.5 局限 7），应加去重。

### 3.3 对战层面（场上怎么用：换人 / 攻击 / 防守判断）

- **场景 1：首发**
  考量因素：是否有 Team Preview（待验证）；首发是否具备第 1 回合产出（钉子 / 双墙 / 顺风 / 威吓）。
  推荐决策：**走「最坏情况不崩」路线**——在 `base` 口径下对 21 属性的最坏防守倍率 ≤2（即不存在被任何属性 4 倍克制），且第 1 回合有确定的产出。这与 `_02` §1.6 对「无预览环境」的建议一致（自杀首发或对全属性都不过分脆的通用首发）。

- **场景 2：换人**
  考量因素：优先级是 **属性免疫(0) > 特性免疫(0) > 抵抗(0.5) > 中性(1)**；ER 还要额外读对方的 `abis` 池是否含对应免疫。
  推荐决策：换入信号按上述优先级取最高；同时**把「可选池免疫」当作概率事件而不是确定事件**——它未勾选时不生效（`opt` 口径只是提示值，`_00` C.1 局限 7），因此引擎的提示措辞必须写清口径，避免用户按「已免疫」去决策。

- **场景 3：攻击**
  考量因素：对方 4 特性中的 `im` 标签会让该招直接作废。
  推荐决策：选招前把「防守视角的免疫」翻转为「进攻视角的风险」——引擎已有的 `IMMUNE_RISK`（由 `ABI_TAGS.im` 反查生成）目前只在体检里做文字警示，应升级为**选招的减权项**（该属性招 ×0.5 并附警示），这正是 01 文档 R01-03 的落地位置。

- **场景 4：中转与清场节奏**
  考量因素：无损换人手段（急速折返 369 / 伏特替换 521，`FUNC_MV.pivot`）、回复型轮转特性（再生力类）、先制收割手段（神速 245、突袭 389、子弹拳 418、水流喷射 453、音速拳 183）。
  推荐决策：全队至少 1 个无损换人手段 + 1 个先制收割手段；两者都缺时，队伍会在「被读换人」和「残局收不掉」两个环节同时失分。Smogon 对平衡队的建议（「耐久型回复特性的怪是最好的防守轮转位，但双换往往比伏特替换更不被预判」）说明中转能力不等于轮转招式，**要分别评估**（R06-10）。

- **场景 5：对抗对手的特性**
  考量因素：ER 全员 4 特性，BOSS 亦然。
  推荐决策：队伍应备「无视或压制对手特性」的解（社区源列出破格类、`Relic Stone`、`Deadly Precision` 等，**待核对**）。这条在 ER 中被反复强调（RomProfessor 的「反特性手段」被列进配队十大维度之一），但本项目尚未在 `gameData` 中确认对应名称，故本文只列为低优先级检查项（R06-24）。

**现状局限（本文档要解决的）**

- **`match` 三维权重过于粗**：特性命中**不分天性 / 可选池**（`s.abis.indexOf(a)>-1 || s.inns.indexOf(a)>-1` 同权）、**不分设置手与受益者**（「降雨」与「雨盘」同 +2）、**无道具维度**、不考虑数值强度（`_00` C.2 局限 1）。
- **`tplRecs` 同分排序不确定**：`sort` 未定义稳定次序，Top 6 已是保守数量（局限 2）。
- **`tplAudit` 只判「名字是否出现」**：不校验数量、分工与重复（「3 只都带降雨」也算通过），且不与 `ABI_TAGS` / `IMMUNE_RISK` 交叉验证（局限 3、4）。
- **`renderAnalyze` 的进攻覆盖用「全可学池」而非当前 4 招**（`s.lv ∪ s.tut` 全量入表）→ 覆盖表**系统性偏乐观**，不代表真实打击面（C.5 局限 1）。
- **逐只体检只判「有 / 没有」**：带一个 40 威力本系招即算 ✓本系，不判数量、威力、命中、PP（局限 3）。
- **天气配套存在体系错配盲点**：`setter` 与 `booster` 分别判定、**不比对具体体系**（队里是降雨、受益者是叶绿素也输出「配套 ✓」），且 `booster` 硬编码 8 个名称（`['悠游自如','叶绿素','拨沙','拨雪','雨盘','太阳之力','沙之力','冰冻之躯']`，数组末位即第 8 个 = 冰冻之躯（雪）；`_00` C.5「局限 5」记作 7 个，属上游计数误差，此处以代码实读 8 个为准）、与 `SYS_MAP` 的 21 条（受益 12 条）不同步（局限 4、5）。
- **补位建议维度少**：仅「免疫 / 抵抗弱点 + 本系补缺口」，不含速度线、道具、天气招、`out` / `def` 强度；固定用 `inn` 口径，与防守剖面在勾选后走 `opt` 不一致（局限 6、7）。
- **`coreRole` 是顺序 if 链**：先命中先返回（「慢速炮台」先于「肉盾」、「炮台」先于「空间打手」），阈值 110 / 115 / 120 / 300 / 270 / 60 / 80 / 90 全部写死，无权重平滑（C.6 局限 1）。
- **强度「只列名不合成」**：`out` / `def` 只以文字列出特性名与倍数，不与种族 / 招式威力合成期望伤害；`def` 的条件（满血 / 异常 / 特殊招式）不参与数值（局限 2、3）。
- **队友推荐不区分天气角色**：`coreSys(t)` 同时含设置与受益特性，「同 X 体系 +3」可能把两个受益者互相推荐（局限 4）。
- **`coreTags` 依赖中文名正则**，译名变动即静默失效（局限 5）。
- **功能招分组不全**：`FUNC_MV.hazard` 只有 3 招（撒菱 / 毒菱 / 隐形岩），**缺 564 黏黏网**（该招在 `MOVES_NOTES` 中存在）；`FUNC_MV` **完全没有除钉分类**，而 229 高速旋转 / 432 清除浓雾 均存在（`_00` B.3、D.7）。
- **无速度线、无伤害计算、无实战模拟**；队友推荐对 1906 只逐只算三口径，是页面最重的同步开销（局限 7、8）。

**升级方向（结合 `_02` §9 的 P0–P3 清单）**：`_02` 给出的最高优先级是「建立 ER 机制白名单（P0）」与「特性评分接入环境招式使用率权重（P0）」。本文在此之上补两条：**(a) 先修数据层的分组缺口（黏黏网、除钉组），否则上层判定全部失真**；**(b) 把所有「推荐」的输出口径显式化（inn / opt、全池 / 当前 4 招、是否最终形态），因为口径混用比模型粗糙更容易造成误判**。

### 4.2 给引擎的组队方法论

#### 4.2.1 队伍类型判定（先定档，再切换评价权重）

| 档位 | 判定条件（字段级） | 后续权重切换 |
|---|---|---|
| HO（重攻） | 先制招成员数 + 强化招成员数 ≥ 3，且 `im + hf` 天性免疫总数 ≤ 3，且轮转招 ≤ 1 | **不评联防**，改评「清场路径是否通畅」：先制 / 强化 / 钉子数量与速度线 |
| BO（重攻平衡） | 轮转招成员数 ≥ 2，钉子 ≥ 1，免疫特性 ≤ 4 | 评「保持场上无钉」+ 破盾手换入路径 |
| Balance | 有回复招成员 ≥ 2，钉子 ≥ 1，且同时存在 ≥ 1 个 ≥120 威力本系招 | 评「防守骨架 + 破盾开路」双线 |
| Semi-stall | 回复招成员 ≥ 3，钉子 ≥ 1，强化招 ≤ 1，且存在耐久型强化手（速度 <80 且 `boost` 命中） | 评「唯一胜点是否成立」+ 被动消耗手段 |
| Stall（纯受） | 回复招成员 ≥ 3，钉子 ≥ 1，强化招 = 0，且 `im + hf` 天性免疫总数 ≥ 4 | 评「残余伤害」（钉 + 状态 + 削道具）+ 除钉是否具备 |

#### 4.2.2 核心构建流程（六步，全部字段化）

1. **选核心**：`coreRole + coreTags` 给出主定位与细分标签；`coreIntensity` 给出输出倍率与耐久评级。
2. **列弱点**：`coreWeak(s)`（`defCellTrio(s, w).inn > 1`），并按倍率加权（4x 权重 ×2）。
3. **列天敌**：对每个弱点属性，检索全图鉴中「对该属性有 ≥2x 攻击招（`matchup[弱点][招属性] >= 2`）」且速度/先制占优者 → 天敌集合（这是现有 `findTeammates` 缺失的一步）。
4. **补队友**：对天敌集合逐条求「能免疫 / 抵抗该属性」的候选，并叠加 `findTeammates` 现有 7 维（本系补盲点 / 同体系 / 开体系 / 回复 / 钉子 / 控速 / 威吓）与新增 3 维（移除天敌 / 铺场 / 补速度线）→ Top 6。
5. **定分工**：对选出的 6 只跑 4.2.1 的档位判定，与预期的队伍类型比对；不符则回到第 4 步换人（**换人优于改招**，因为改招会破坏单只的角色完整性）。
6. **查漏洞**：跑体检（防守剖面共同弱点 / 进攻覆盖缺口 / 进度标签 / 天气配套 / 除钉成对检查），逐条给出「补谁 / 补什么招」。

#### 4.2.3 补位决策树

```
共同弱点属性集合 W = { at | agg[at].w >= 2 } ，完全无法命中集合 M
│
├─ W 非空？
│   ├─ 是 → 在「未被选入队伍 且 非 nonFinal」中筛：对某个 w ∈ W，
│   │        defCellTrio(t,w) 的生效口径 == 0（免疫）→ +3
│   │        < 1（抵抗）→ +2
│   │        并检查「引入新共同弱点」（对 W 之外属性是否产生新的 >=2 弱点）→ 有则 −2
│   └─ 否 → 跳过，进入 M
│
├─ M 非空？（覆盖缺口）
│   └─ 是 → 候选 t 的 t1/t2 ∈ M → +2（本系补覆盖缺口）
│
├─ 功能维度（无论 W/M 是否为空）
│   ├─ 提供钉子（hazard ∪ {564}）或除钉（229/432）→ +1（成对缺失时优先除钉）
│   ├─ 提供回复（rec）→ +1
│   ├─ 补速度线（速度 >= 110 而队伍最高速度 < 80）→ +1
│   └─ 承伤能力（HP + 防 + 特防 >= 300）→ +1
│
├─ 去重
│   ├─ 与队内成员 t1/t2 完全相同的属性组合 → −2
│   └─ 与队内成员主定位相同（coreRole 主定位一致）→ −1
│
└─ 排序取 Top 6（排序键：总分 desc → 是否最终形态 desc → id asc），每行附「入队 / 详情」
```
