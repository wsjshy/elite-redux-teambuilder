## A. 数据层接口变更（build_tool_data.py）

### A1. matchup 方阵修复（P0-①）
现状：L85-89 在 `types` 动态增长中 `row.extend(...)` + `matchup.append(...)`，导致末 3 行长度 19/20/21 格（星晶/无/神秘），非 21×21 方阵（全中性故当前计算正确，但隐性 bug）。
修法：
1. 生成前定义权威 21 属性顺序常量（与 ERDATA.types 既定序一致：一般/格斗/火/冰/电/虫/飞行/钢/草/地面/毒/恶/水/超能力/岩石/龙/幽灵/妖精/星晶/无/神秘）。
2. 读取 xlsm 18 属性克制表后，**先定死 21 列序**再填格：对每行按 21 属性逐格取值（xlsm 缺的列填 1），新属性行（星晶/无/神秘）全 1。
3. 输出后自检断言：`len(matchup)==21` 且 `all(len(r)==21 for r in matchup)`；不过则报错退出。
4. `ERDATA.matchup` 保持"行=防守、列=攻击、0/1/2/3"编码不变。

### A2. lDesc 详细描述导出（P0-④数据侧）
现状：ERDATA.moves 只有简版 `desc`；gameData moves 有 `lDesc`（僵直"Needs recharging."、反伤"33% recoil damage."、天气必中、条件威力等）被整列漏掉 → 引擎对招式代价零认知。
修法：ERDATA.moves 每条新增 `lDesc` 字段 = gameData moves.lDesc（缺失时 ''）。保留原 desc 不变。输出后自检：moves 条数不变、lDesc 非空条数 >100 且含关键文本（recharge/recoil/Never misses）。

### A3. ABI_TAGS 新增 conv（属性转换）标签（P0-⑥数据侧）
现状：6 个 -ate 类特性（Normalize 96/Refrigerate 174/Pixilate 182/Aerilate 184/Galvanize 206/Hydrate 315）未建模；ER v2.65 将其改为**属性转换**（具体倍率以 `_机制默认口径表.md` ABI_ATE.multiplier 为准，默认标注待实测）。
修法：ABI_TAGS 每条追加 `conv: '属性名'`（96→'一般'、174→'冰'、182→'妖精'、184→'飞行'、206→'电'、315→'水'、**325 Intoxicate→'毒'**——口径表 ABI_ATE.types 共 7 条）。不影响既有 im/hf/add/out/def 键。另：MOVES_NOTES 中 '432'（清除浓雾）注释"清对方全场钉子+场地"与口径表"清双方"不一致，一并修正为"清双方钉子+降闪避1级（原版GenVI+口径，ER待实测）"。

### A4. 其他
- 若口径表发现需补的标签（如剧毒场地相关），按口径表补。
- 不改动：ABI_ALIAS、MOVES_NOTES、TEMPLATES、nonFinal 判定、species/moves/items/abilities 既有结构。

## B. 引擎层接口变更（build_tool_html.py 内嵌 JS）

### B1. defCellTrio 勾选丢天性免疫修复（P0-②）
现状：pick 分支（勾选可选特性）只并入天性 `add` 属性，丢天性 `im`/`hf` → 传播到队伍级统计（defProfiles）。
修法：**生效口径 = base + 天性全部修正（im/hf/add 均生效）+ 勾选特性修正（叠加）**；勾选只覆盖"同池其它可选特性"，不顶掉天性。未勾选时行为不变。

### B2. 耐久口径确认（P0-③，代码已正确）
实读：coreIntensity 用 `phys=b[1]+b[2]`（HP+攻+防）、阈值 300/230——**与 04 文档口径一致，无需改代码**。仅在 renderCore 文案处注明"耐久=HP+物攻+防御（阈值 300/230，2026-10-06 实读）"。

### B3. lDesc 消费（P0-④引擎侧）
在招式详情与配招评分中读 m.lDesc 生成代价标签（防御：lDesc 缺失/空时行为与现状一致）：
- `Needs recharging` → 僵直：评分 ×0.85；双属性AOE（暴风/水炮类）警告文案
- `recoil`（含 "33% recoil"）→ 反伤：评分 ×0.9；若精灵无回复手段（无 FUNC_MV.rec）再 ×0.9
- `Never misses` / `never misses` → 必中：评分 ×1.05
- 条件威力（含 "50%"/"boosted"/"weather" 关键词）→ 按天气/条件成立则按满威力，不成立 ×0.7
- 其他 lDesc 文本仅展示不评分。

### B4. 命中微调（P0-⑤，代码已正确 + 轻量补充）
实读：`(m[6]&&m[6]<85?0.8:1)` 已短路保护 acc=0 必中招——**保留**。补充：`m[6]>=85 && m[6]<90` → ×0.95（轻量微调，03 R03-03 建议）；`m[6]>=90` 不变。

### B5. -ate 消费（P0-⑥引擎侧）

### B9. pickAttacks 升级为多层决策引擎（核心，01~06 规则实现）
替换现有单式 `score` 为**分层管线**（保留 atkCover/coverHoles/usedTy 去重骨架）：

**分层1 侧判定（种族，04 文档）**：沿用 genBuilds 开流逻辑（sideOK：本系≥60 攻击招 + 种族≥90 或 ≥65+强化/威力≥100）。**双刀保留**：物/特攻双侧同时满足时，双侧各开独立流派（低侧标"备选"，不关闭）；种族双高（如凤王 130/110）强制双流派。

**分层2 候选池（技能，03 文档）**：按侧过滤攻击招 + 功能招（FUNC_MV：weather/boost/hazard/control/rec/protect/removal）+ lDesc 代价过滤（B3 标签）。

**分层3 多维打分**（替换 `score=pow×...` 单式，各维度相乘）：
```
score = pow
  × stabAdj   本系 1.6（含 conv 转换后本系）
  × hitAdj    acc==0 必中 1.05；acc<85 0.8；85~89 0.95；其余 1
  × prioAdj   先制 >0 ×1.3（-ate/暴风类等按实测）
  × coverAdj  该招对 21 属性 2x 覆盖数加权：1 + 0.05×覆盖属性数（上限 1.5）
  × weatherAdj 天气加成（**分源**）：手动天气（求雨/大晴天/沙暴/冰雹）→ 水/火招 ×(1+WCONF.boost=1.5)；特性天气（降雨/日照/扬沙/降雪）→ 水/火招 ×(1+WCONF.abilityBoost=1.2)；雨→打雷/暴风雨必中、雪→暴风雪必中（ER 官方）；场地加成按 WCONF.terrainBoost
  × funcAdj   功能招按定位权重表：天气设置手→weather 招 +40；站场强化→boost +30；铺场→hazard +25；控速→control +25；回复→rec +20；保命→protect +15；破受/拍落/挑衅类→+20；removal→按口径表
  × abiAdj    精灵自身 out 特性（大力士/适应力/天气加成等 ABI_TAGS.out）对应侧 ×1.2；对手可能免疫属性（IMMUNE_RISK + 目标物种 abis/inns im）→ 该属性招 ×0.5 并警示
```
**分层4 覆盖贪心（保留）**：atkCover 维护已选覆盖，后选招同覆盖降权（novel 语义 0.4）、usedTy≥2 去重、首槽本系 +30。

**分层5 盲点检查升级（03/06 文档）**：每流派 4 招对 21 属性 <1（抵抗/免疫）全列表；新增：①特性免疫警示（该属性招被对手常见免疫特性废掉）；②双刀补盲提示（物攻流盲点属性若特攻流可覆盖，提示"双刀补盲"）。

**输出**：流派卡新增"选招依据"摘要（每招权重构成，便于用户理解与后续调参）。
