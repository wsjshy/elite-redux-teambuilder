## §1 天气增伤倍率（考古 1）

### 考古结论
1. **旧版源码存在两档天气增伤，但分档依据不是「手动 vs 特性」，而是「战斗内设置 vs 地图固定天气」**：
   - `WEATHER_RAIN_PERMANENT` → 水 ×1.2（+20%）／火 ×0.5
   - `WEATHER_RAIN_TEMPORARY` → 水 ×1.5（+50%）／火 ×0.5
   - 日文照（SUN）对称：PERMANENT 火 ×1.2／水 ×0.5；TEMPORARY 火 ×1.5／水 ×0.5
2. **招式天气与特性天气在旧版源码中完全同档**：二者都只置 `TEMPORARY` 位，都是 +50%。
   `PERMANENT` 位在旧版源码中**只由地图/野外固定天气**（`ABILITYEFFECT_SWITCH_IN_WEATHER`）写入。
3. **口径表的「特性天气 +20% / 手动天气 +50%」在旧版源码中不成立**——旧版是「两者都 +50%」。
   → 分源（特性归 +20% 档）**属 v2.65 改动，或口径表对 ER 文档的归因有偏**（见下方「可检验假设」）。

### 证据

**E1-1 天气增伤主体** — `src\battle_util.c:14803-14831`（所在函数 `CalcFinalDmg`，定义于同文件 `14765` 行）：
```c
    // check sunny/rain weather
    if (IsBattlerWeatherAffected(battlerAtk, WEATHER_RAIN_PERMANENT))
    {
        if (moveType == TYPE_FIRE)
            dmg = ApplyModifier(UQ_4_12(0.5), dmg);
        else if (moveType == TYPE_WATER)
            dmg = ApplyModifier(UQ_4_12(1.2), dmg);
    }
    else if (IsBattlerWeatherAffected(battlerAtk, WEATHER_RAIN_TEMPORARY))
    {
        if (moveType == TYPE_FIRE)
            dmg = ApplyModifier(UQ_4_12(0.5), dmg);
        else if (moveType == TYPE_WATER)
            dmg = ApplyModifier(UQ_4_12(1.5), dmg);
    }
    else if (IsBattlerWeatherAffected(battlerAtk, WEATHER_SUN_PERMANENT))
    {
        if (moveType == TYPE_FIRE)
            dmg = ApplyModifier(UQ_4_12(1.2), dmg);
        else if (moveType == TYPE_WATER)
            dmg = ApplyModifier(UQ_4_12(0.5), dmg);
    }
    else if (IsBattlerWeatherAffected(battlerAtk, WEATHER_SUN_TEMPORARY))
    {
        if (moveType == TYPE_FIRE)
            dmg = ApplyModifier(UQ_4_12(1.5), dmg);
        else if (moveType == TYPE_WATER)
            dmg = ApplyModifier(UQ_4_12(0.5), dmg);
    }
```
（`UQ_4_12(1.2)` = 1.2 定点数，即 ×1.2；`UQ_4_12(1.5)` 即 ×1.5。注意 `PERMANENT` 判定排在 `TEMPORARY` **之前**，为 else-if 链——若两位同时置位，取 1.2 档。）

**E1-2 两个标志位是独立 bit** — `include\constants\battle.h:262-277`：
```c

#define WEATHER_RAIN_PERMANENT      (1 << 2)
#define WEATHER_RAIN_ANY            (WEATHER_RAIN_TEMPORARY | WEATHER_RAIN_DOWNPOUR | WEATHER_RAIN_PERMANENT | WEATHER_RAIN_PRIMAL)
#define WEATHER_SUN_TEMPORARY       (1 << 6)
#define WEATHER_SUN_PERMANENT       (1 << 7)
#define WEATHER_HAIL_TEMPORARY      (1 << 9)
```

（`include\constants\weather.h` **只有** 地图 coord-event 用的 `WEATHER_SUNNY/RAIN/SANDSTORM/...` 枚举，**不含** `B_WEATHER_*` / `*_TEMPORARY` / `*_PERMANENT`；本位定义在 `battle.h`。）

**E1-3 谁写入 PERMANENT** — `src\battle_util.c:4495-4525`（`case ABILITYEFFECT_SWITCH_IN_WEATHER`，即**进场时套用地图当前天气**）：
```c
                case WEATHER_RAIN:
                case WEATHER_RAIN_THUNDERSTORM:
                case WEATHER_DOWNPOUR:
                    if (!(gBattleWeather & WEATHER_RAIN_ANY))
                    {
                        gBattleWeather = (WEATHER_RAIN_TEMPORARY | WEATHER_RAIN_PERMANENT);
```
（雨 / 沙暴 / 晴天 三段同构，另两处为 `4513` 行 `WEATHER_SANDSTORM_PERMANENT | WEATHER_SANDSTORM_TEMPORARY`、`4521` 行 `WEATHER_SUN_PERMANENT | WEATHER_SUN_TEMPORARY`。
**取证说明**：全仓直接给 `gBattleWeather` 赋值 `*_PERMANENT` 的位置**仅此 3 处**（`grep 'gBattleWeather = .*_PERMANENT'` ⇒ 3 命中，均在 `ABILITYEFFECT_SWITCH_IN_WEATHER` 内）；另有 1 处经标志表**间接**写入（`:4166` 的 `sWeatherFlagsInfo[weatherEnumId][0] | sWeatherFlagsInfo[weatherEnumId][1]`，即 §1 所述本快照**不可达**的特性档分支）。故旧版源码中「可达的 PERMANENT」只来自地图天气。）

**E1-4 特性天气走哪一档** — `src\battle_util.c:4154-4181`（`TryChangeBattleWeather`，详见 §7 E7-1 全文）：
特性调用方传入 `viaAbility = TRUE`（`src\battle_util.c:5278` 求雨 / `:5315` 扬沙 / `:5352` 日照 / `:5389` 降雪，四者均传 `TRUE`），但该分支的生效条件是
`viaAbility && B_ABILITY_WEATHER <= GEN_5`，而 `battle_config.h:87` 为 `#define B_ABILITY_WEATHER GEN_8`
（GEN_8 = 5，`5 <= GEN_5(2)` 为假）→ **该分支永不生效**，特性天气落入下一个 `else if`，只置 `TEMPORARY`。

双证：4 条招式设天气指令全部传 `FALSE`（非特性），见 §7 E7-2。

### 与口径表的对照 → **冲突（重要）**
- 口径表 §1「天气伤害加成」：特性 +20% / 手动 +50%（待实测=**是**）。
- 旧版源码：特性 = 手动 = **+50%（TEMPORARY 档）**；+20% 专属「地图固定天气（PERMANENT）」。
- **可检验假设（属推断，标注为个人观点，不作证据）**：口径表引用的 Full Features「特性天气 `cause infinite weather again`」+「Damage bonus reduced to 20%」，与旧版源码 `B_ABILITY_WEATHER <= GEN_5` 分支的行为**恰好吻合**——该分支写入 `(TEMPORARY | PERMANENT)` 且**不设置** `weatherDuration`（=持续到战斗结束/被改），于是同时得到「长效天气」与「1.2 档（因 PERMANENT 判定在前）」。故 v2.65 可能把特性天气恢复为「永久档」。**建议实测量化点：特性降雨（Drizzle）下水招是否 ×1.2、求雨（Rain Dance）下水招是否 ×1.5。**
- 结论标注：**旧版源码口径 = 分档按 PERMANENT/TEMPORARY，特性与手动同档（+50%）；v2.65 是否沿用/是否改为「特性 +20%」见 changelog 与实测。**

## §2 场地增伤倍率（考古 2）

### 考古结论
**旧版源码场地增伤 = ×1.3（+30%），不是 ×1.5。**
倍率并非硬编码，而是由 `battle_config.h` 的世代宏 `B_TERRAIN_TYPE_BOOST` 决定；该快照中宏值 = `GEN_8` → 取 1.3 分支。
三个增伤型场地（草/电/精神）**均要求攻击方接地**（`IsBattlerGrounded`）。薄雾场地另有「龙伤 ×0.5」一行（旧版仍在，与 changelog v2.65.3b「已移除」冲突）。**源码中不存在「剧毒场地增伤」行**（与 §9 一致）。

### 证据
**E2-1 倍率实现** — `src\battle_util.c:13662-13669`（所在函数为招威力计算 `CalcMoveBasePowerAfterModifiers`，`return ApplyModifier(modifier, basePower);` 于 `13671`）：
```c

        MulModifier(&modifier, (B_TERRAIN_TYPE_BOOST >= GEN_8) ? UQ_4_12(1.3) : UQ_4_12(1.5));
    if (GetCurrentTerrain() == STATUS_FIELD_MISTY_TERRAIN && moveType == TYPE_DRAGON && IsBattlerGrounded(battlerDef) && !(gStatuses3[battlerDef] & STATUS3_SEMI_INVULNERABLE))
        MulModifier(&modifier, UQ_4_12(0.5));
    if (GetCurrentTerrain() == STATUS_FIELD_ELECTRIC_TERRAIN && moveType == TYPE_ELECTRIC && IsBattlerGrounded(battlerAtk) && !(gStatuses3[battlerAtk] & STATUS3_SEMI_INVULNERABLE))
        MulModifier(&modifier, (B_TERRAIN_TYPE_BOOST >= GEN_8) ? UQ_4_12(1.3) : UQ_4_12(1.5));
    if (GetCurrentTerrain() == STATUS_FIELD_PSYCHIC_TERRAIN && moveType == TYPE_PSYCHIC && IsBattlerGrounded(battlerAtk) && !(gStatuses3[battlerAtk] & STATUS3_SEMI_INVULNERABLE))
        MulModifier(&modifier, (B_TERRAIN_TYPE_BOOST >= GEN_8) ? UQ_4_12(1.3) : UQ_4_12(1.5));
```

**E2-2 宏值** — `include\constants\battle_config.h:134`：

### 与口径表的对照 → **冲突（关键项，反向）**
- 口径表 `WCONF.terrainBoost` 默认 **1.5**，标注「**是（关键）**」，理由栏自述「50% 为第八世代以前（含第 VI–VII 世代）口径；30% 系套用原版百科数值…**与用户假定的『原版 Gen6+ = 1.5×』并不完全一致**」。
- 旧版源码实测：**ER 内核宏把场地定在 GEN_8 → 1.3**。即 ER 自身配置**就是 30%**，而非 50%。
- 影响：口径表现有默认值 1.5 **很可能应改为 1.3**；引擎模板写死的「+30%」反而与 ER 内核一致。
- 结论标注：**1.3 为旧版源码口径；v2.65 changelog 未提及场地倍率改动 → 若未改宏则应沿用 1.3（需实测确认）**。建议把本项实测优先级**维持为最高**（它是当前默认值与源码唯一「方向相反」的项）。
- 附：薄雾场地「龙伤 ×0.5」在旧版源码**仍在**（E2-1 第 2 行），而口径表 §2 记录 changelog v2.65.3b 已移除 → **确认属 v2.65 改动**，口径表判定正确。
- 附（额外发现，非口径表条目）：旧版存在**地图永久场地**机制（`STATUS_FIELD_TERRAIN_PERMANENT`；`B_THUNDERSTORM_TERRAIN = TRUE` 使地图雷雨 = 永久电场地），该机制下 `terrainTimer` **不递减**，与 §13 记录的「场地基础 5 / 延展器 8」（`battle_util.c:4190-4193`，招式路径）**并存不冲突**。

## §3 -ate 类特性倍率与 STAB（考古 3）

### 考古结论
1. **转换后威力加成 = ×1.1（+10%）**，与 `UQ_4_12(1.1)` 逐条硬编码；共 **17 个**同类特性（远多于口径表列的 7 个）。**不是 1.2、不是 1.3。**
2. 加成**仅在「类型真的被转换」时生效**（受 `gBattleStruct->ateBoost[battlerAtk]` 门控，该标志在类型转换处置 1）。
3. **旧版源码中 -ate 不给通用 STAB**：STAB 判定仍是「攻击方属性 == 招式当前属性」的常规逻辑；仅 `ABILITY_SOLAR_FLARE`（火）与 `ABILITY_AURORA_BOREALIS`（冰）在 STAB 判定里被**单独特判**赋予 STAB，其余 -ate 家族没有。
   → 「Gain STAB conversion」在旧版源码中**未实现**，属 v2.65 新增。

## §9 剧毒场地 Toxic Terrain（考古 9）

### 考古结论
1. **旧版源码中完全不存在剧毒场地**（`TOXIC_TERRAIN` / `ToxicTerrain` / `toxicTerrain` 在 `src\` 与 `include\` 全仓 **0 命中**）。
2. 场地旗标亦只定义了 4 个（草/薄雾/电/精神），`STATUS_FIELD_TERRAIN_ANY` 亦只含这 4 个（`include\constants\battle.h:239-247`，见 §2 E2-3）。
3. 因此剧毒场地的**任何**参数（存在性、回合、毒招倍率、撒菱→毒菱转换、Toxic Seed）**均无法用旧版源码证实**。
4. **顺带核对结果（gameData）**：`gameDataV2.65beta.json` 的 `moves[1006]`（按 **id** 访问）确为 Toxic Terrain，其 `lDesc` **不含倍率数字**：
   - `desc` = `'Boosts Poison and damages mons for 8 turns.'`
   - `lDesc` = `'Boosts Poison-type moves for 8 turns and deals 1/16 HP damage.'`
   → 与口径表判定一致：**毒招增伤倍率仍只有 GBACodes 单一来源**。

> **ID 索引陷阱（复核时务必注意）**：`gameDataV2.65beta.json` 的 `moves` 是**数组**（`len = 1032`），且**数组下标 ≠ id 的条目恰好有 3 个**：
> `idx1006→id1007 Jetstream Burst`、`idx1007→id1008 Sky Quake`、`idx1008→**id1006 Toxic Terrain**`。
> 即 Toxic Terrain **位于数组下标 1008，但 id 是 1006**。口径表写的 `gameData.moves[1006]` 若要成立，必须**按 id 检索**（如 `moves.find(m => m.id === 1006)`）；若按 JS 数组下标 `moves[1006]` 读，会读到 `Jetstream Burst`（一个完全无关的招式）。**本项为对口径表公式化表述的风险提示，不代表口径表结论有误**（其引用的 desc/lDesc 文本与 id 1006 记录完全吻合）。
