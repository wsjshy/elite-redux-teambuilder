## 3. 缺陷与差异清单（含最小复现）

### D1 · 中 — 简评与流派标题的 HTML 未转义，字面 `<span>` 标签外露

- **现象**：`#coreOut` 的「强度…（简评）」段与每个「流派 N：…」标题行把类型 chip 的 HTML 当纯文本输出，用户直接看到 `<span class="t t-草">草</span>`。
- **实测文本**：
  - 妙蛙花：「强度：茂盛(<1/3血)×1.5 … 本系最高威力 130（`<span class="t t-草">草</span>`）。耐久 中物耐 / 中特耐。有回复。速度80 中速。怕 `<span class="t t-飞行">飞行</span>`/`<span class="t t-超能力">超能力</span>`」
  - 流派标题：「⭐ 推荐流派 1：特攻核心 （特殊向 · 特攻核心：本系最高 飞叶风暴(`<span class="t t-草">草</span>` 130)；自带强化轴；特攻输出向）」
  - 土王、凤王、大比鸟、雷电云同样复现（`literalSpanLeak=true`，同元素内另有 35~41 个正常渲染的 `span.t` chip）。
- **判定依据**：`innerText` 不会返回已解析元素的标签；出现字面标签说明该字符串是以文本节点注入的。截图附件可为视觉佐证。
- **复现**：核心配队 Tab → 搜索任意宝可梦 → 点卡片 → 观察「定位判断」块下第 4 段（强度/简评）与下方每个流派标题。
- **影响**：纯展示层，不影响配招/评估数值；但可读性明显受损。

### D2 · 低 — 存档导入不清空既有队伍，满 6 只后静默丢弃

- **现象**：若队伍已有 3 只（手工加入），再导入存档，导出的 6 只只会补进 3 只，**洛奇亚 / 鳃鱼龙被静默丢弃**，`#savParseOut` 仍提示「队伍 6 只已自动导入」。
- **复现**：核心配队依次把 土王/雷电云/Storming 入队 → 队伍构建上传 `.sav` → 读 `#tmSlots`（仅 6 槽，导入成员不完整）。
- **对照**：刷新页面（空队伍）后导入 → 6 只完全正确（见测试 7）。故属**边界行为**，非主流程缺陷；建议导入时先清空或给出截断提示。

### D3 · 低 — 雨天模板「待校准」徽标位置与口径表冲突

- **现象**：`tplBody0`「ER 调整说明」= 「特性天气 8 回合（带天气岩石 12 回合），增伤 +20%；手动天气招 5 回合、**+50%待游戏内截图校准**」。
- **冲突**：口径表引擎参数汇总表中 `WCONF.boost = 0.5` 的「是否待实测」= **否（用户已裁定）**；B8 要求只有标「待实测」的参数才加徽标。
- **复现**：战术模板 → 雨天速攻 → 展开 → 读 ER 调整说明。

### D4 · 信息 — 疯狂植物等「回合间隔型」僵直招未获僵直标签

- **现象**：`疯狂植物 #338` 详情无「代价标签：僵直」，而 `破坏光线 #63` 有。
- **原因推断**：`疯狂植物.lDesc = "The foe is hit with an enormous branch. Can only be used every-other turn."`，未含 B3 规定的关键词 `Needs recharging`。
- **判定**：属 B3 关键词口径的**已知限制**（非实现偏差），但会造成同类僵直招评分口径不一致，建议扩充关键词表。

### D5 · 信息 — 两处与规格 C3 文字的数量/条目差异

1. 规格 C3：「妙蛙花 **4** 流派」→ 实测 **5** 流派（多出「天气体系（晴）」）。
2. 规格 C3：「**雷电云天气体系**」→ 实测雷电云仅 3 流派（特攻核心/物攻核心/双刀输出），**无天气体系流派**；其定位判为「速攻手」、细分「站场强化」，天性为 兆级电压/天气掌控/蓄电，引擎未判为天气设置手或天气受益者。
- 判定：属规格文字与当前引擎行为的**描述性差异**；本项不作通过/失败裁决，提交实施方与规格作者确认应以哪一方为准。
