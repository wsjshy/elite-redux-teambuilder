### 0.3 ⚠️ 数据读取陷阱（本次实证纠正的重要事实）

`gameDataV2.65beta.json` 的 **`items` 数组不是按 id 排序的**：

- 前三个元素 id = `310 / 273 / 305`，末三个 = `705 / 706 / 707`；`all(id[i] <= id[i+1]) == False`。
- 因此 **`items[N]` ≠ 道具 id=N`**。实测：`items[308]` = `Aggronite`（id **751**）、`items[317]` = `Cameruptite`（id **760**）、`items[417]` = `Lucarionite Z`（id **860**）。
- 正确读法是按 `id` 字段检索（或按 `NAME` 字段）。本文件所有 items 结论均按 `id` 字段实读核对。
- `moves` 数组在 512/283 处下标与 id 恰好一致（`mv[512].id == 512`、`mv[283].id == 283`），但整体亦非严格有序；本文件按 `id` 字段检索。
- **item 对象只有 3 个键：`['NAME','id','name']`** —— gameData 中 items **没有** `flavor` / `effect` / `description` 字段。道具功能语义只能由 er-config 的 `items/*.textproto` 提供。
- move 对象键集合：`['NAME','acc','arg','chance','desc','eff','flags','id','lDesc','name','pp','prio','pwr','sName','split','target','types','usesHpType']`。

## C1 杂技 Acrobatics（MOVE_ACROBATICS，id 512，飞行系）

**定稿值：ER v2.65 基础威力 75；未持有道具时伤害 ×1.5 ⇒ 满倍 112.5。既非官方「55 基础 / ×2」，也非纯 desc 口径的孤证——倍率数值已从数据源码实读钉死。**

### 源码证据（A 级，Pin A）

1) 触发条件 — `src/script_conditions.cc:145-150`（Pin A 全量树）：

```cpp
template <>
int CustomMoveCondition<EFFECT_ACROBATICS>(CUSTOM_MOVE_CONDITION_PARAMS) {
    return gBattleMons[battlerAtk].item == ITEM_NONE
           // Edge case, because removal of items happens after damage calculation.
           || (gTurnStructs[battlerAtk].gemBoost && GetBattlerHoldEffect(battlerAtk, FALSE) == HOLD_EFFECT_GEMS);
}
```

> 条件 = 「攻击方未持有道具」；宝石（Gems）为「先消耗后结算」的边缘情形。**该函数只定义触发条件，不定义倍率。**

2) 倍率来源（数据源码，A' 级）— `proto/MoveBehaviorConfigList.textproto:1082-1093`（Pin A 数据提交 `6a30b667`）：

```
config {
  id: EFFECT_ACROBATICS
  attack {
    damage {
      condition {
        # Gems are weird
        custom: true
      }
      multiply: 1.5
    }
  }
}
```

3) 生成链（A 级）— `tools/codegen/src/er/move/MoveDamageGenerator.kt`：

- `:21` `for (behavior in MOVE_BEHAVIORS.filterValues { it.attack.hasDamage() })`
- `:37` `ConditionCase.CUSTOM -> "CustomMoveCondition<${behavior.key}>(CUSTOM_MOVE_CONDITION_CALL)"` （→ 落为 `REQUIRE(CustomMoveCondition<EFFECT_ACROBATICS>(...))`）
- `:49-50` `ModifierCase.MULTIPLY -> "baseDamage * ${damage.multiply}"` （→ 落为 `return baseDamage * 1.5;`）
- `:16` 函数签名 `u32 UpdateBaseDamage(u32 baseDamage, u8 battlerAtk, u8 battlerDef, MoveEnum move, MoveBehaviorEnum effect)`

> 结论：v2.65 的倍率由数据配置 `multiply: 1.5` 驱动，经 codegen 生成 `u32 UpdateBaseDamage()` 内的 `baseDamage * 1.5`。
> **推导（非实读，标注为整型语义推断）**：该函数返回类型为 `u32`，`75 * 1.5 = 112.5` 在 C++ 隐式转换为整型时截断为 **112**。引擎现值记 112.5 属「显示口径」，如需与 ROM 严格对齐可注为「口径 112.5 / 整型实值 112」。

4) 基础威力与描述（数据源码，A' 级）— `proto/MoveList.textproto:8524-8538`（Pin A）：


## C2 蛮干 Endeavor（MOVE_ENDEAVOR，id 283，一般系）

**定稿值：ER v2.65 实现 = 官方语义「把对方 HP 削至与自身相同」；gameData 的 desc「自身 HP 低于对方时增力」是**未更新的旧描述文本**（与 Bulbapedia 所载 Gen III RS/E 描述逐字相同），不是 ER 的行为。**

### 源码证据（A 级，Pin A）

1) 招式脚本 — `data/battle_scripts_1.s:6436-6448`（Pin A 全量树）：

```
	attackstring

	accuracycheck BattleScript_MoveMissedPause, ACC_CURR_MOVE

	jumpifmovehadnoeffect BattleScript_HitFromAtkAnimation
	bichalfword gMoveResultFlags, MOVE_RESULT_SUPER_EFFECTIVE | MOVE_RESULT_NOT_VERY_EFFECTIVE
```

2) 命令实现 — `src/battle_script_commands.c:11852-11859`（声明 `:337`、命令表 `:609` 记 `// 0xD8`）：

```c
static void Cmd_setdamagetohealthdifference(void) {
    if (gBattleMons[gBattlerTarget].hp <= gBattleMons[gBattlerAttacker].hp) {
        gBattlescriptCurrInstr = T1_READ_PTR(gBattlescriptCurrInstr + 1);
    } else {
        gBattleMoveDamage = gBattleMons[gBattlerTarget].hp - gBattleMons[gBattlerAttacker].hp;
        gBattlescriptCurrInstr += 5;
    }
}
```

⇒ 目标 HP ≤ 自身 HP → 跳失败分支；否则伤害 = **目标 HP − 自身 HP**，即**正好把对方削到与自身同血**。

3) 关键排他证据 — `src/battle_util.c` 全文（Pin A 全量树）对 `ENDEAVOR` 的检索结果：**0 命中**。
⇒ 蛮干**不存在任何 basePower 处理/成长分支**，也就不存在「低血线增力」的实现位置。

4) 数据配置（A' 级）— `proto/MoveBehaviorConfigList.textproto:901-904`（Pin A）：

⇒ 只有 `legacy_config`，**没有** `attack { damage { ... } }` 块，即**无倍率/无威力修饰**。与 C1 的 ACROBATICS（有 `multiply: 1.5`）形成直接对照，构成「蛮干不走威力成长」的机制级证据。

- **证据强度**：强（A+A'+A2/B2+B+C+D 全级）。
