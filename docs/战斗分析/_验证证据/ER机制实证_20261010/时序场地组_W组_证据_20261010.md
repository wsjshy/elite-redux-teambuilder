## W1 戏法空间回合数（5 还是 6）

**项**：TRICK_ROOM_DURATION=5（常量）但「施放当回合不递减」⇒ 实际覆盖几个回合时段？

### 源码证据（Pin A，实读）
1. 常量（Pin A `v265_include__battle_util.h`）：
   - `:56 #define TRICK_ROOM_DURATION 5`
   - `:57 #define TRICK_ROOM_DURATION_SHORT 3`
   - `:62 #define ROOM_DURATION_MAX 255`
2. 施放端（Pin A `v265_src__battle_script_commands.c`）：
   ```
   11861 static void HandleRoomMove(u32 statusFlag, u8* timer, u8 stringId, u8 duration) {
   11862     if (gFieldStatuses & statusFlag) {
   11863         gFieldStatuses &= ~(statusFlag);
   11864         *timer = 0;
   11865         SetActiveMultistringChooser(stringId + 1);
   11866     } else {
   11867         gFieldStatuses |= statusFlag;
   11868         *timer = duration;
   11869         SetActiveMultistringChooser(stringId);
   11870     }
   11871 }
   11873 static void Cmd_setroom(void) {
   11875     switch (gBattleMoves[gCurrentMove].effect) {
   11876         case EFFECT_TRICK_ROOM:
   11877             // Permanent
   11878             if ((gFieldStatuses & STATUS_FIELD_TRICK_ROOM) && gFieldTimers.trickRoomTimer > 10) {
   11879                 gBattlescriptCurrInstr = ptr;
   11880             } else {
   11881                 HandleRoomMove(STATUS_FIELD_TRICK_ROOM, &gFieldTimers.trickRoomTimer, B_MSG_TRICKROOMSTARTS, TRICK_ROOM_DURATION);
   11882                 gFieldTimers.started.trickRoom = TRUE;
   11883             }
   11884             break;
   ```
   ⇒ 施放时 `trickRoomTimer = 5`，并置 `started.trickRoom = TRUE`。
3. 递减端（Pin A `v265_src__battle_util.c`）：
   ```
   2024             case ENDTURN_TRICK_ROOM:
   2025                 if (gFieldStatuses & STATUS_FIELD_TRICK_ROOM && !gFieldTimers.started.trickRoom && --gFieldTimers.trickRoomTimer == 0) {
   2026                     gFieldStatuses &= ~(STATUS_FIELD_TRICK_ROOM);
   2027                     BattleScriptExecute(BattleScript_TrickRoomEnds);
   2028                     effect++;
   2029                 }
   ```
   ⇒ 回合末递减**要求 `!started.trickRoom`**。
4. `started` 到期清零（Pin A `v265_src__battle_main.c`）：
   ```
   4567 static void CheckFocusPunch_ClearVarsBeforeTurnStarts(void) {
   …
   4588     for (i = 0; i < gBattlersCount; i++) {
   4589         ZERO(gVolatileStructs[i].started)
   4590     }
   4591
   4592     ZERO(gSideTimers[0].started)
   4593     ZERO(gSideTimers[1].started)
   4594     ZERO(gFieldTimers.started)
   ```
   ⇒ 每回合开始 `ZERO(gFieldTimers.started)`，使上一回合的 `started` 失效。

### 机制判定（本项核心）
- 施放回合 N：`started.trickRoom=TRUE` ⇒ 回合末 ENDTURN_TRICK_ROOM **跳过递减**，timer 保持 5。
- 回合 N+1 起：`started` 被清零 ⇒ 回合末递减 5→4→3→2→1→0（第 N+5 回合末归零）。
- ⇒ 空间从施放后一直生效到 **第 N+5 回合结束**，覆盖时段 = {N, N+1, N+2, N+3, N+4, N+5} = **6 个回合时段**。
- 但由于 TR 先制 **−7**（见 gameData），施放当回合它最后出手，该回合的「序反转」几乎无实际收益 ⇒ 玩家实得 ≈ 5 个完整有效回合。

### 自洽性对比（顺风为何 3→4 自洽、空间 5→6 冲突）
- 顺风：常量 `TAILWIND_DURATION 3` + 同机制 ⇒ 3+1 = **4 回合**，与官方「Gen5+ 顺风 4 turns」**自洽**（见 W14）。
- 空间：官方 5 turns，按 ER 惯例常量应 = 4（4+1=5）；但 ER 写 `TRICK_ROOM_DURATION 5` ⇒ 5+1 = **6**，**比官方文案多 1**。属「常量未按 −1 惯例」或「desc 未同步」，二者无法从源码判定意图（无 changelog 佐证）。

**Pin B 对照**：`include__battle_util.h:56 TRICK_ROOM_DURATION 5`、`:57 TRICK_ROOM_DURATION_SHORT 3`（与 Pin A 逐字一致）；施放/递减/清零脚本代码结构一致（`src__battle_script_commands.c` Cmd_setroom 分支、`src__battle_util.c` ENDTURN_TRICK_ROOM、`src__battle_main.c` CheckFocusPunch_ClearVarsBeforeTurnStarts 同构）。
**旧版对照（2024-04 克隆）**：递减**无** `started` 判断（`D:\game\elite-redux\ER-source\src\battle_util.c:2203 if (--gSideTimers[side].reflectTimer == 0)`、`:2365 if (--gSideTimers[side].tailwindTimer == 0)` 均无 `started`）⇒ **v2.65 才新增「当回合不递减」机制**，这正是 3→4、5→6 的根因。

**gameData 原文**：`moves[433]`（id 433 Trick Room）`prio = -7`，desc「Slower Pokémon get to move first for 5 turns.」
**官方 URL**：
- `https://bulbapedia.bulbagarden.net/wiki/Trick_Room_(move)`：「This effect lasts for five turns, and **using Trick Room counts as the first turn**.」（Priority −7）
- `http://eksan-ltd.com/userfiles/file/96480395850.pdf`（general_search 命中）：「Trick Room lasts for 5 turns, but using the move counts as the first turn. In practice, Trick Room only lasts for 4 turns.」

### 结论
- **定稿值（以 ER 源码为准）= 6 个回合时段**（含施放回合：施放回合 + 之后 5 回合）；desc/Bulbapedia 文案为 5 turns。
- **冲突判定**：源码（双 pin、全链路实读）＞ desc ⇒ 实际生效 6 个回合时段；文案 5 属未同步/惯例缺失。
- **与引擎现值**：`build_tool_html.py:798 WCONF.trickroomTurns:5` 与源码机制**冲突** ⇒ **引擎应改为 6**（或保留 5 但显式标注「施放回合计入，实际覆盖 6 个回合时段」）。该值还用于配队描述 `:5090`「依赖空间窗口（5 回合）」。
- **状态**：可定稿（无需游戏内实测）。
- **证据强度**：强（源码 Pin A 全链路实读 + Pin B 逐字一致 + 旧版基线对照 + 官方文案冲突已注明）。

## W14 自动顺风回合（TAILWIND_DURATION_SHORT）

**项**：`TAILWIND_DURATION` / `TAILWIND_DURATION_SHORT` 实读；自动顺风实际回合；引擎 `autoTailwindTurns=4` 是否正确？

### 源码证据（Pin A，实读）
1. 常量（`v265_include__battle_util.h`）：
   - `:66 #define TAILWIND_DURATION 3`
   - `:67 #define TAILWIND_DURATION_SHORT 3`  ⇒ **SHORT 与 DURATION 同值（都 3）**
2. 手动端（`v265_src__battle_script_commands.c:10956-10964`）：
   ```
   10956 static void Cmd_settailwind(void) {
   10959     if (!(gSideStatuses[side] & SIDE_STATUS_TAILWIND)) {
   10960         gSideTimers[side].started.tailwind = TRUE;
   10961         gSideStatuses[side] |= SIDE_STATUS_TAILWIND;
   10962         gSideTimers[side].tailwindBattlerId = gBattlerAttacker;
   10963         gSideTimers[side].tailwindTimer = TAILWIND_DURATION;
   ```
3. 特性端（均用 SHORT）：
   - Air Blower（`v265_src__abilities.cc:1386-1393`）：`:1389 started.tailwind = TRUE;`、`:1392 tailwindTimer = TAILWIND_DURATION_SHORT;`
   - Harukaze（`v265_src__abilities.cc:10097-10112`，`onTerrain`，条件 `:10100 IsTerrainActive(STATUS_FIELD_GRASSY_TERRAIN)`）：`:10105 started.tailwind = TRUE;`、`:10108 tailwindTimer = TAILWIND_DURATION_SHORT;`
4. 递减端（`v265_src__battle_util.c:1897-1905`）：
   ```
   1897             case ENDTURN_TAILWIND:
   1901                     if (gSideStatuses[side] & SIDE_STATUS_TAILWIND) {
   1902                         if (!gSideTimers[side].started.tailwind && --gSideTimers[side].tailwindTimer == 0) {
   1903                             gSideStatuses[side] &= ~SIDE_STATUS_TAILWIND;
   1904                             BattleScriptExecute(BattleScript_TailwindEnds);
   ```
   ⇒ 同样要求 `!started.tailwind` ⇒ 施放当回合不递减。

### 机制判定
常量 3 + 当回合不递减 ⇒ **3+1 = 4 个回合时段**。手动与自动**同值、同时长**（SHORT = DURATION = 3）⇒ 自动顺风亦 4 个回合时段，与官方「Gen5+ 顺风 4 turns」**自洽**。

**Pin B 对照**：`include__battle_util.h:66/67`（DURATION/SHORT 均 3）；`src__abilities.cc:1363/1365/1367 Air Blower`、`:10096/10099/10101 Harukaze`（同用 SHORT）。
**旧版对照**：旧版**无** `TAILWIND_DURATION` 常量（`D:\game\elite-redux\ER-source\include` grep 0 命中），特性直写 `tailwindTimer = 3`（`src\battle_util.c:5203 / :6311`），且递减无 `started` 判断（`:2365`）⇒ 旧版自动顺风 = 3 回合；v2.65 因机制变更变为 4。
**gameData 原文**：`moves[366] Tailwind` lDesc「…ups the Speed stat of the party for **4 turns**.」；`abilities[320] Air Blower` desc「Casts a **3-turn** Tailwind on entry.」（desc 记 3 = 常量；实得 4 因当回合不递减）；`abilities[833] Harukaze`「Setting Grassy Terrain sets Tailwind and vice versa.」
**官方 URL**：`https://bulbapedia.bulbagarden.net/wiki/Tailwind_(move)`（Gen V「now lasts for **four turns**」；Champs「4 turns」）。
**旁证**：`v265_include__constants__battle_config.h:55 #define B_TAILWIND_TURNS GEN_7 // In Gen5+, Tailwind lasts 4 turns instead of 3.` —— 该配置在源码中**只有定义、无使用点**（全树 grep 仅命中定义行），故不参与时长计算。

### 结论
- **定稿值**：手动/自动顺风均 = **4 个回合时段**（常量 3 + 施放当回合不递减；SHORT = DURATION = 3）。
- **与引擎现值**：`build_tool_html.py:790 tailwindTurns:4`、`:792 autoTailwindTurns:4` ⇒ **一致**。
- **状态**：可定稿（无需游戏内实测）。
- **证据强度**：强（源码 Pin A/B 常量 + 手动/特性/递减三段实读 + gameData lDesc「4 turns」+ Bulbapedia 三方）。
