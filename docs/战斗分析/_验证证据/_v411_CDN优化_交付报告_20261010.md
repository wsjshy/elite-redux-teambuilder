## 4. 加载器设计（A：运行时择优加载）

### 4.1 块 1：主源加载器（`build_tool_html.py` L608–629，产物 L449–470）

```js
<script>/*__ER_LOADER__*/
(function(){
  var GC='__ER_CDN_PREFIX__';            // 构建期 → CDN_PREFIX
  var F=true;
  try{
    var L=window.location||{}, p=L.protocol||'';
    if(!p&&L.href)p=(String(L.href).indexOf('file:')===0)?'file:':'';   // 兼容仅有 href 的桩环境
    F=(p==='file:');
  }catch(e){F=true}
  window.__ER_FILE=F;
  window.__ER_ASSET_BASE=F?'':GC;        // 资产（sheets）主源前缀，消费点 sprOf()
  if(typeof ERDATA==='undefined'){
    document.write('<scr'+'ipt src="'+(F?'':GC)+'data.js"><\/scr'+'ipt>');
  }
})();
</script>
```

- **URL 形态**：`'https://gcore.jsdelivr.net/gh/wsjshy/elite-redux-teambuilder@gh-pages/' + 'data.js'`
  → `https://gcore.jsdelivr.net/gh/wsjshy/elite-redux-teambuilder@gh-pages/data.js`
- **同步性**：`document.write` 注入的是 parser-blocking 脚本，浏览器在同块结束后、进入下一块前完成下载与执行 → 应用代码块执行时 `ERDATA` 必定就绪（**无 DOMContentLoaded 包装，boot 调用位置零改动**）。
- **`file:` 分支**：直接写相对 `src="data.js"`，不触网。
- **`</script>` 转义**：JS 字符串中写作 `'<\/scr'+'ipt>'`，产物中 `</scr` 裸序列命中 **0** 处（否则 HTML 解析器会截断内嵌脚本）。

### 4.2 块 2：回退块（L630–637，产物 L471–478）

```js
<script>/*__ER_LOADER_FB__*/
if(typeof ERDATA==='undefined'&&!window.__ER_FILE){
  document.write('<scr'+'ipt src="data.js"><\/scr'+'ipt>');
}
</script>
```

- **回退判据 = `ERDATA` 是否仍 undefined**，因此对 **404 / DNS 失败 / TLS 失败 / 网络超时 / 返回内容不可用** 一律生效，不依赖 `onerror` 回调。
- **为什么必须独立成块**（本方案唯一的设计要点）：`document.write` 注入的脚本在「写入它的那个脚本块」**结束后**才被解析执行，故块 1 内 `typeof ERDATA` 必然还是 undefined，回退判定放在块 2 才可靠。已由离线夹具 A 例（主源 404 → 块 2 改写同域）实测确认。
- `!window.__ER_FILE` 门控：本地 `file://` 双击时不做二次写入（避免在白名单/本地场景重复下载）。

### 4.3 已定义跳过（VM/测试管线兼容）

块 1 的 `if(typeof ERDATA==='undefined')` 就是「预定义则跳过」的守卫：`_extract_script.js` 把 `data.js` 内容前置拼接进 `_chk_script_1.js`，Node VM 里 `ERDATA` 先于应用代码就绪 ⇒ 即使加载器块被保留也零写入。实测：**预定义 → writes=0**；**主源成功 → 回退块 writes=0**（不重复下载）。

## 11. jsdelivr 缓存 TTL 与 purge 方案

**实测 TTL（本次 HEAD/GET 实测，非文档推测）**：branch 引用（`@gh-pages`）的响应为
`Cache-Control: public, max-age=604800, s-maxage=43200`
- **边缘/CDN TTL = 12 小时**（`s-maxage=43200`）→ 更新 gh-pages 后最长 12h 才全网生效；
- **浏览器 TTL = 7 天**（`max-age=604800`）→ 老访客可能用本地缓存 7 天；
- 响应头带 `x-jsd-version: gh-pages` / `x-jsd-version-type: branch`（可据此判断 jsdelivr 解析到的引用）；`x-cache: HIT, MISS` + `cf-cache-status: HIT` 说明 jsdelivr 后面还有一层 Cloudflare。

**purge（强制刷新）方案**——本次改动只影响 `data.js` 与 8 张 webp（`index.html` 走 github.io，不经 jsdelivr，且 jsdelivr 对 `.html` 返回 `text/plain` 本就不能当入口）：
1. Web UI：`https://www.jsdelivr.com/tools/purge`（每次最多 10 条 URL）。官方提示：@latest/版本别名 URL 不清则会「wait up to 7 days」。
2. API：
   ```bash
   curl -L -X POST https://purge.jsdelivr.net \
     -H 'cache-control: no-cache' -H 'content-type: application/json' \
     -d '{"path":["/gh/wsjshy/elite-redux-teambuilder@gh-pages/data.js",
                  "/gh/wsjshy/elite-redux-teambuilder@gh-pages/assets/sheets/s0.webp",
                  "/gh/wsjshy/elite-redux-teambuilder@gh-pages/assets/sheets/s1.webp",
                  "/gh/wsjshy/elite-redux-teambuilder@gh-pages/assets/sheets/s2.webp",

                  "/gh/wsjshy/elite-redux-teambuilder@gh-pages/assets/sheets/s4.webp",
                  "/gh/wsjshy/elite-redux-teambuilder@gh-pages/assets/sheets/s5.webp",

                  "/gh/wsjshy/elite-redux-teambuilder@gh-pages/assets/sheets/s7.webp"]}'
   ```

   返回形如 `{"id":"CXWDAKcejkTaas0QS","status":"pending","timestamp":"2024-03-21T16:33:50.876Z"}`。
3. 单文件 GET 形式：`https://purge.jsdelivr.net/gh/wsjshy/elite-redux-teambuilder@gh-pages/data.js`。
