## 2. `buildTeam(s, side, roleTag)` 接口设计

### 2.1 签名与返回

```js
/* v4.2 正向体系构建：由核心 → 完整队伍方案（不淘汰个体，只排位） */
function buildTeam(s, side, roleTag)
// → {
//   core:{s, side, roleTag, arch, sys:[…], wx:[…], terrain:[…]},
//   overview:{arch, sysText, wxText, line},        // 体系总览行（一句话：这套队伍怎么赢）
//   slots:[ Slot, … ],                             // 槽位数组（顺序=建议出场/职能顺序）
//   notes:[ str, … ]                               // 全局提示（如「天气由队友提供」）
// }
// Slot = {
//   key:'wxsetter'|'ace'|'cover'|'defwall'|'hazard'|'pivot'|…,
//   label:'天气手', role:'开晴（出场日照）', need:'出场开晴 / 可学大晴天',
//   members:[ {// 该槽位 Top 1~3，按槽位分降序
//       s, score, why:[…], dims:[{dim,w,pts,txt}],
//       fill:{ mv:[{id,name,tag,why},…], abi:[{n,scope,why}], item:[[名,注]], nat:[[名,注]] },
//       links:[{to:'ace', kind:'受益'|'补盲'|'联防'|'接力'|'控速', text:'为 妙蛙花 提供晴（草/火受益）'}]
//   }, … ]
// }
```

### 2.2 生成流程（4 步）

1. **体系识别**：`coreSys(s)` / `spSys(s)` → `arch = archOfSp(s,side,roleTag)`；`wx = sys∩WX_SYS`、`terrain = sys∩场地`（`WEATHER_MV` / `SYS_MAP` / `SYS_SET` 复用既有判定）。
2. **骨架生成**：按 `arch` 取槽位骨架表 `SLOT_SKEL[arch]`（**权威来源 = 阶段 1 `07_组队方法论.md` 的 18 体系槽位骨架**；文档未落盘前用 §2.4 的兜底骨架，落盘后替换为其骨架并逐条对齐）。核心自身按 `arch`/`roleTag` 落位（妙蛙花[晴] → `ace`，同时标记 `members[0]=core`）。
3. **逐槽位正向评分**：`slotScore(cand, slot, ctx)` = Σ 维度分 × 权重，**无 drop、无硬否决**；候选池 = 全图鉴（`isFinalSp` + `isValidSp` 护栏后），排除：① 已被其它槽位占用的物种 ② 核心自身（其槽位除外）。取 `members = top3`。
4. **槽位内填装**：复用既有 `mkBuild(s,side,roleTag)`（内部 = `buildMoves` + `buildNature` + `buildItem` + `pickAbiFor`），对非核心成员以「该槽位职责的 roleTag」调用（如 `hazard` → `受队`、`pivot` → `双刀`、`ace` → `输出`），从而得到配招/特性/道具/性格 + why（**不新写一套配招逻辑**）。
5. **联动说明**：`links` 由三源合成 —— ① 体系受益：`spSys(member)∩sys≠∅` → 「为 X 提供 Y 体系受益」；② 补盲：`member` 本系命中 `coverHoles(core)` → 「补 X 盲点」；③ 联防：`defCellTrio(member, w).inn` 对核心弱点 ≤0.5 → 「免疫/抵抗你弱点的 X」；④ 功能接力：钉子/除钉/回复/折返/顺风/空间 → 「提供 Y，供 Z 换挡」。
