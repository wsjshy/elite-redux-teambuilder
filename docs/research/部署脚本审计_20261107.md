## 4. 【头条】增量模式为什么仍然是删库

### 4.1 推导链（每一步都有 git 实跑输出）

```
$ git rev-parse gh-pages
67b0dde3b0ed7227628edc1bfe5c1f64b2f77b8f

$ git rev-parse github/gh-pages
80e14f8ceb429f712cc342fe6cf5c13b1c5fd8ac

$ git rev-list --left-right --count gh-pages...github/gh-pages
0	118
# 左=本地领先 0；右=本地落后 118。本地 gh-pages 是远端的严格祖先。

$ (git ls-tree -r --name-only gh-pages).Count
19
$ (git ls-tree -r --name-only github/gh-pages).Count
139
```

### 4.2 脚本执行时实际发生的事

```
L135  Invoke-Git checkout gh-pages
      → 工作区切到 67b0dde3，树里 19 个文件
      → 这 19 个文件是 2026-10-19 的旧快照
      → 远端 80e14f8 上多出的 118 个提交、120 个文件，本地工作区根本没有

L155  Copy-Item "$Temp\*" "$Repo\." -Recurse -Force   （增量分支）
      → 只把 23 个暂存文件覆写到 19 文件的工作区
      → 工作区现在 = 19 ∪ 23 = 24 个文件

L160  git add --all
L161  git commit -m "$Message"
      → 新提交的父节点 = 67b0dde3（本地 gh-pages HEAD）
      → 新提交的树 = 24 文件
      → 这个提交在 git 历史上是 67b0dde3 的子节点，
        而 67b0dde3 是 80e14f8 的祖先

L162  git push github gh-pages --force
      → 远端 refs/heads/gh-pages 从 80e14f8 强制指向新提交
      → 80e14f8 这个提交（含 139 文件）从远端分支上被遗弃
      → 远端树从 139 文件变成 24 文件
      → 差集 116 个文件在远端消失
```

### 4.3 集合差验证（PowerShell 实跑）

```powershell
$online  = git ls-tree -r --name-only github/gh-pages   # 139
$localGH = git ls-tree -r --name-only gh-pages          # 19

$deleted = $online | Where-Object { $deployedAfter -notcontains $_ }
# $deleted.Count = 116

$added = $deployedAfter | Where-Object { $online -notcontains $_ }
# $added.Count = 1 → README.md

"data.js in deployed-after? True"   # 增量保住
"data.js in online? True"
```

### 4.4 为什么 `-Clean` 的删除计数提示是假的

```powershell
# L148 实际执行的命令：
$toDelete = (Get-ChildItem -Path $Repo -Exclude ".git" -Force | Measure-Object).Count
```

`Get-ChildItem` 不带 `-Recurse`，只数**根级条目**。`gh-pages` 工作区根级只有 6 项：

```
$ git ls-tree gh-pages
100644 blob e69de29b  .nojekyll
040000 tree 4161d9f  ER-source/
100644 blob 6d92c4c  README.md
040000 tree ededb6f  assets/
100644 blob a9910e6  data.js
100644 blob 190da68  index.html
# root entry count: 6
```

脚本会打印"将删除 gh-pages 根目录 **6** 个条目"，但 `Remove-Item -Recurse -Force` 实际递归删掉的是 **19 个文件**（assets/ 下 14 个、ER-source/ 下 3 个、根级 2 个 = 19），而 force-push 后远端消失的是 **117 个文件**。这条"安全提示"把删除规模低估了 19 倍（6 vs 117）。

### 4.5 修复路径（一条命令）

```powershell

git fetch github
git checkout -B gh-pages github/gh-pages
# 之后再跑 deploy_er.ps1，增量模式才是真零删除：
# 工作区 = 139 文件，增量覆写 23 个，push 后远端树 = 139 文件（仅 README.md/index.html/data_adv 内容变）
```

> 本审计严格只读，**未执行**上述快进命令。此修复路径由 `rev-list --left-right --count = 0 118` 推导（严格祖先 = 快进不会丢提交），但未实跑验证。

## 8. 白名单与护栏建议（按优先级）

> **核心问题再答：白名单路径需不需要补？不需要。** `$ExpectedFiles` 23 项已全覆盖。真正的问题是**本地 gh-pages 分支落后**与**护栏缺失**。
