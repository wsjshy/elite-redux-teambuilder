# ER 通用机制与招式/特性源码口径（2026-11-08）

> 本文回答一个问题：**玩家在 2.65 里实际感受到的规则，源码里到底是怎么写的**。
> 所有结论都标了源码位置，可以自己回查；查不到的就写「查不到」，不猜。

## 〇、先定口径：两个分支不是一回事

| 分支 | 用途 | 事实 |
|---|---|---|
| `master` | **2.65 发行版对应的代码** | `src/battle_util.c` 694,131 B；没有 `src/abilities.cc` |
| `upcoming` | C++ 重构的未来版 | `src/battle_util.c` 只剩 441,143 B；新增 `src/abilities.cc` 445,798 B |

**解释当前游玩体验必须用 master**。`upcoming` 只能用来判断「下一版会不会实装」。

实例：`ABILITY_TURBOBLAZE`（163 涡轮火焰）/ `ABILITY_TERAVOLT`（164 兆级电压）的「加属性」——
`AddBattlerType` 在 **master 全仓 0 命中**，在 **upcoming 的 `src/abilities.cc` 22 命中**。
所以 2.65 里这两条**没有加属性效果**，那是下一版的预留。

## 一、伤害是怎么算出来的

源码：`src/battle_util.c:15056` `DoMoveDamageCalcInternal`

```
① 相性为 0 → 直接 return -1（打不动，连伤害数字都不算）
② power = CalcMoveBasePowerAfterModifiers(...)     ← 特性/道具/天气改威力都在这一步
③ dmg  = ((攻击方等级 * 2) / 5) + 2
④ dmg *= power
⑤ dmg *= CalcAttackStat(...)
⑥ dmg /= CalcDefenseStat(...)
⑦ dmg  = (dmg / 50) + 2
⑧ dmg  = CalcFinalDmg(...)                          ← 相性倍率、会心、随机数、道具、特性
⑨ Monotype Champ 修正（见第五节）
```

这是标准的 Gen3 公式骨架，②⑥⑤⑧ 是 ER 塞特性的地方。**排查「为什么这一下伤害不对」时，按 ①→⑨ 顺序找断点，比凭描述猜快得多。**

## 二、属性相性：ER 把它当「可改写量」

源码：`src/battle_util.c:15186` `MulByTypeEffectiveness`

正统作品里相性是死表。ER 把它做成**可被特性拦截并重写**的量，这就是为什么很多"本该免疫"的组合在 ER 里打得动。

### 2.1 特性改写（源码里逐个 `else if` 分支）

| 特性 | id | 触发条件（源码原文） | 相性被改成 |

| 一般皮肤 Normalize | 96 | 一般属性招式且原相性 ≠ 0 | **1.0**（无视抗性，见数据层"无视抗性"） |

### 2.2 全局规则（不属于任何特性，人人都会遇到）

同一函数里，这几条**没有** `BATTLER_HAS_ABILITY` 前缀，属于通用修正：

| 条件 | 结果 | 源码 |
|---|---|---|
| `EFFECT_SLUDGE` 打水属性 | 2.0 | L15297 |
| `EFFECT_POISON_GAS` 打飞行属性 | 2.0 | L15299 |
| `MOVE_GIGATON_HAMMER` 打钢属性 | 2.0 | L15301 |

最后一条最隐蔽：**强风一开，飞行系的弱点全部消失**。这是天气机制，不是特性，配招时不会有人提醒你。

## 三、能力等级倍率：标准 Gen3，没有魔改

源码：`src/pokemon.c:3545` `gStatStageRatios[MAX_STAT_STAGE + 1][2]`

```
-6: 10/40   -5: 10/35   -4: 10/30   -3: 10/25   -2: 10/20   -1: 10/15
 0: 10/10
+1: 15/10   +2: 20/10   +3: 25/10   +4: 30/10   +5: 35/10   +6: 40/10
```

即 ±1 为 1.5 倍 / 0.67 倍，±2 为 2 倍 / 0.5 倍，±6 为 4 倍 / 0.25 倍，**与官方一致**。
所以"能力等级被我算错了"这类问题，基本可以排除——除非涉及特性对**倍率本身**的改写（那是另一套逻辑，不在这个表里）。

## 四、招式效果：993 个 `EFFECT_`，不靠名字猜

- 招式数据：`src/data/battle_moves.h`（366,858 B，993 处 `EFFECT_` 引用）
- 效果实现：`src/battle_script_commands.c` 里 `case EFFECT_XXX:` 分支 + `data/battle_scripts_1.s` 汇编脚本

**结论：招式行为由 `EFFECT_` 分派，名字和描述只是标签。**
同一个 `EFFECT_` 可以挂很多招式（例如各种「附加异常状态」的招式共用一套代码，只有概率字段不同）。
因此**不要用招式名去推效果**，要查它挂的是哪个 `EFFECT_`，再去看那个 `EFFECT_` 的 case。

## 六、天气：ER 取消了传统的水/火属性天气加成

**这是最容易被正统作品经验误导的一条。**

正统 Gen3 及之后：晴天火系招式 ×1.5，雨天水系招式 ×1.5。**ER 里这两条都不存在。**

**证据**：在 `src/battle_util.c`（694,131 B 全文）、`src/battle_script_commands.c`、`src/battle_main.c`
里同时搜 `WEATHER_SUN_ANY` / `WEATHER_RAIN` 与 `UQ_4_12(1.5)` 或 `1.5`，
**命中数 0**。基础威力函数 `CalcMoveBasePowerAfterModifiers`（`src/battle_util.c:12838`）
从头到尾没有针对 `moveType` 的天气倍率分支。

**ER 里的天气只剩这些作用**：

| 类型 | 位置 | 实际作用 |
|---|---|---|
| 冰雹 `WEATHER_HAIL_ANY` | `battle_util.c:13983` | 特性 Whiteout 冰系招式 ×1.5（**靠特性，不是天气本身**） |
| 冰雹 | `battle_util.c:13317` | 特性 Christmas Spirit 使受到的伤害 ×0.5 |
| 沙暴 `WEATHER_SANDSTORM_ANY` | `battle_util.c:13324` | 特性 Dune Terror 使受到的伤害 ×0.65 |
| 强风 `WEATHER_STRONG_WINDS` | `battle_util.c:15309` | 飞行系受到的 ≥2.0 相性强制压回 1.0（**弱点全消失**） |
| 任意天气 | `battle_util.c:12638` | 气象球改属性与威力 |
| — | `battle_util.c:14730~14757` | `EFFECT_WEATHER_BOOST` 类招式按天气改威力 |

**配招含义**：不要为了"雨天水系加成"去堆水招，也不要指望晴天火系增伤。天气在 ER 里的价值集中在
① 场地/天气特效本身（如沙暴每回合削血）② 触发特定特性 ③ 让气象球/天气球系招式变强。

## 五、Monotype Champ：ER 自己加的一套修正

源码：`DoMoveDamageCalcInternal` 末尾 `switch (getMonotypeChampType())`

这是 ER 独有的，正统作品没有对应机制：

| Champ 类型 | 修正 |
|---|---|
| 草 / 超 / 电 / 毒 / 钢 | 对手不是玩家方 → 伤害 **减半** |
| 地面 / 格斗 | 对手不是玩家方，且相性 ≥ 2.0 → **减半** |
| 格斗 | 玩家防守、对方用格斗招式打过来 → **×2** |
| 冰 | 玩家防守、对方攻击 → **×2** |

换句话说，这四类 Champ 是**针对玩家方的难度调节**：前几类让对面打你更轻，格斗/冰反而让对面打你更重。

## 六、全量特性普查结论（618 条）

方法：用 `include/constants/abilities.h` 的 `#define ABILITY_XXX <id>` 做 **id → 常量名**映射，再在 master 全仓 grep 每个常量。

> **为什么必须走 id**：数据层的英文名是压缩过的（`WandrngSprit`、`CuriusMedicn`、`Twist. Dimension`），由英文名推不出常量名。第一版按英文名推得 441 条「零命中」，全是假阴性。

### 6.1 覆盖率

| 项 | 数值 |
|---|---|
| 数据层特性条目（有 id） | 618 |
| 在源码中有引用 | **618 / 618** |
| 在「效果实现文件」中有引用 | **616** |
| 仅出现在 AI 判断 | **1**（#180 共生 Symbiosis） |
| 仅出现在声明与文本 | **1**（#600 龙族拳手 Brawling Wyvern） |

「效果实现文件」= `src/battle_util.c`、`src/battle_script_commands.c`、`data/battle_scripts_1.s`/`_2.s`、`src/battle_main.c`、`src/pokemon.c`。

### 6.2 复杂度分布

`src/battle_util.c` 内命中次数：min 0 / p25 1 / **p50 2** / p75 3 / max 17。

中位数只有 2，说明**绝大多数特性是「表驱动」或「单点判定」**，不是每条都有一段可叙述的复杂机制。
最多的几条：`#197 界限盾壳`、`#563 发号施令`（各 17），`#59 阴晴不定`（13），`#122 花之礼`（12），`#90 毒疗`（12）。

### 6.3 「读代码行自动生成效果摘要」这条路走不通

618 条里，只有 **34 条**的关键行带 `//` 注释（唯一可直接读出的语义来源），且集中在 `battle_ai_util.c`(273 行)、`battle_util.c`(203 行)。

反例：`#262 电晶体` 数据写「电属性招式威力提升至 1.5 倍」，但它在效果文件里只有 1 处引用、且那行不含任何数字——真正的倍率写在通用表里，单看常量的出现位置读不出效果。

**所以全量覆盖的正确形态是「覆盖率台账 + 少数高价值条目手工详解」，不是给 618 条各编一段散文。**

## 七、招式机制归类：950 招背后只有 402 个 `EFFECT_`

**招式行为不是由名字决定的，是由 `effect` 字段分派的。** 名字和描述只是标签。
所以判断一个新招"到底干什么"，第一步永远是看它的 `EFFECT_`。

- 950 个招式 → **402 个 distinct `EFFECT_`**
- 其中 **280 个 `EFFECT` 只挂 1 个招式**（专属实现，基本是作者为单个招写的脚本）
- 剩下 122 个 `EFFECT` 承担 670 个招式

**同一 `EFFECT_` 下的招式，附加机制完全一致，只是属性/威力/命中不同。** 这条对配招很有用：
想知道某招的附加效果，直接看它的同组兄弟就行。

### 7.3 一个必须知道的陷阱：`EFFECT_ARGUMENT_HIT`

有 13 个招式的 `EFFECT_` 是 `EFFECT_ARGUMENT_HIT`，这个名字本身说明不了任何事。
`data/battle_scripts_1.s:12061` 的脚本是：

```
BattleScript_EffectArgumentHit:
    argumenttomoveeffect
    goto BattleScript_EffectHit
```

而 `argumenttomoveeffect` 展开成 `various BS_ATTACKER, VARIOUS_ARGUMENT_TO_MOVE_EFFECT`，
对应 `src/battle_script_commands.c:10041`：

```c
case VARIOUS_ARGUMENT_TO_MOVE_EFFECT:
    gBattleScripting.moveEffect = gBattleMoves[gCurrentMove].argument;
```

**真实效果写在每个招式自己的 `.argument` 字段里**：

| 招式 | `.argument` | 实际效果 |
|---|---|---|
| Burning Jealousy 妒火 | `MOVE_EFFECT_BURN` | 100% 灼伤 |
| Alluring Voice 魅诱之声 | `MOVE_EFFECT_CONFUSION` | 100% 混乱 |
| Malignant Chain 邪毒锁链 | `MOVE_EFFECT_TOXIC` | 50% 剧毒 |
| Dire Claw 撕裂爪 | `MOVE_EFFECT_DIRE_CLAW` | 50% 特殊效果 |
| Spin Out 疾速转轮 | `MOVE_EFFECT_SPD_MINUS_2` | 自身速度 −2 |
| Make It Rain 淘金潮 | `MOVE_EFFECT_SP_ATK_MINUS_1` | 自身特攻 −1 |
| Water/Fire/Grass Pledge | 各自专属 | 合击效果 |

**只看 `EFFECT_ARGUMENT_HIT` 什么都推不出来，必须落到 `.argument`。**
