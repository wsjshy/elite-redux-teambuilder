# v4.423 测试报告：「加载更多」点击后滚到新增起点

- 版本：v4.423（2026-11-21）
- 起因：v4.422 给三处列表加了分批后，容器内滚动是独立的，追加发生在容器**底部**；用户停在容器顶部点按钮，只看到按钮文字变化、画面基本不动，主观上等同「点了没反应」。
- 产物：`index.html` 2,124,457 → **2,124,911 B**（净增 454）。

## 一、复现（改前基线）

招式「地震」（共 248 只可学）：

| 指标 | 点按钮前 | 点按钮后（v4.422） |
|---|---|---|
| 网格卡片数 | 60 | 120 |
| 网格 scrollTop | 0 | **0（没动）** |
| 网格 scrollHeight | 930 | 1848 |
| 可视高度 | 320 | 320 |

即新增的 60 张全落在 scrollTop 924 之后，用户视野仍在 0–320 的第一批卡片，感知不到任何变化。

## 二、改法（2 处）

1. `mvLookupRender` 的 foot 按钮：onclick 改为
   ```js
   var _h=grid.scrollHeight; fill(); grid.scrollTop=Math.max(0,_h-6);
   ```
2. `abiOwnerFill`：追加前（**必须早于 appendChild**）记 `var _h0=grid.scrollHeight`，追加后 `grid.scrollTop=Math.max(0,_h0-4)`。
   - 该函数同时被「列内滚动触底」自动调用；此时用户本就站在底部，滚动到新内容起点同样正确。
   - 两处都包 `try{}catch(e423a/e423b){e423a.name}`，不引入新的静默空 catch。
