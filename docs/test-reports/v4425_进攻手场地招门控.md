# v4.425 测试报告：进攻手手动场地招统一门控

- 版本：v4.425（2026-11-23）
- 性质：根因级判定修复，覆盖全部手动队伍级场地招，非个案补丁。
- 产物：`index.html` 2,125,289 → **2,126,977 B**（净增 1,688，分两个补丁：+1,504 / +184）。

## 一、立项与用户投诉

用户带截图指出：超级喷火龙X #1502 的推荐流派「顺风速攻强化清场」四招含手动「顺风」（366），物理输出手浪费一回合铺队伍级速度场地。用户判断「底层逻辑出问题」，要求覆盖全部手动场地招（天气/场地/顺风/空间/墙），而非只补 366。

## 二、根因链路（取证闭合）

1. `funcProfile` 因可学 366 置 `fn.tw=true`；`mechPrefix` 以「学得会」给流派冠「顺风」前缀，冠名依据是可学性而非实际携带。
2. `buildMoves` 的 funcOrder 含 control；既有语义门只过滤 weather，control 无门，`pickFuncs` 按评分把 366 推入槽位。
3. `finalizeBuildInPlace` 墙块在 autoW（北风/极北之风）命中时再插手动墙招；`mvKindOf` 不识别墙，墙 kind 落为 attack。
4. `fillMvSlots` 的 rest 池含 speed 类，366/433 可在补槽时回灌。
5. `selfSpeedSource` 把手动招算成自身速度来源（×2）——慢速物种靠「可学顺风」获得速度轴生成资格，属更深建模缺陷。
6. **v4.43 命名修复块（漏网路径）**：P0-B 控场候选池、P0-C 空间块、①-3 天气轴会在「名含场地词但未带招」时把场地招硬插回主槽，绕过 pickFuncs 门控。

历史门控（v4.379/380/395）按招类别和速度阈值分块，366 被归入 speed/control 而非 weather，从未进入清理清单；v4.381 顺风专项以「耐久≥270 保留」为错误口径（肉度≠职责）。根因：门控按类别分块，而非按统一的「进攻定位 × 手动队伍级场地招」语义建模。

## 五、补丁（10 处锚点）

补丁 A（单一真源 + 选招门控，7 处）：

- 新增 `FIELD_SETUP_MV`（weather/tailwind/space/wall 四类 id 表）、`FIELD_SETUP_OF` 反查表、`isFieldSetupId(id)`、`isOffRoleTag(r)`（增伤/输出/强化为 true）。
- `pickFuncs`：进攻角色遇场地招直接跳过（control 下保留电磁波 86/岩石封锁 317，只拦 366/433）。
- `fillMvSlots`：进攻角色 rest 池过滤场地招，防补位回灌。
- `finalizeBuildInPlace` 墙块：进攻角色不再因 autoW 插手动墙；自动极光幕仍由特性入场触发，防御效果不丢。
- `mechPrefix`：删除「可学即冠名」的顺风/空间分支，保留低速空间受益者口径。
- `selfSpeedSource`：删除「自开顺风 ×2」，手动招不再算自身速度来源。

补丁 B（命名修复块门控，3 处）：

- P0-B 控场候选池：进攻角色过滤场地招 id。
- P0-C 空间块：进攻角色不硬插 433，走改名兜底。
- ①-3 天气轴：进攻角色不硬插天气招，走去前缀兜底。
