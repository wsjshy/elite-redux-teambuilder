## 一、问题怎么发现的

承 v4.398 之后换了个判据方向：不再扫「单卡配置合不合理」（机械判据已证明边际收益耗尽），
改扫「**同一物种的多个流派之间是否真的构成不同玩法**」。

`probe_diversity.py` 在 1906 物种 / 5645 卡上算同物种流派两两的招组 Jaccard：

| 口径 | 六人队 | 空队 |
|---|---|---|
| 招组 Jaccard ≥ 0.75 | 149 对 | — |
| 　+ EV 与特性也相同 | 64 对 | — |
| 　+ side 与性格也相同 | 15 对 | — |

再按「四招集合是否完全相同」细分：

| 类 | 六人队 | 空队 |
|---|---|---|
| A 同名同招（名字+四招全同） | **10 对** | 0 对 |
| B 不同名同招+配置全同 | 1 对 | 1 对 |
| C 同招不同名但配置有差 | 138 对 | 13 对 |

## 二、根因：v4.371 的去重跑在链中间，被后面的改招块绕过

v4.371 的同玩法去重条件是：

```
同 side && 特性[0] 名相同 && 道具[0] 名相同 && EV 模板相同 && 招组 Jaccard ≥ 0.6
```

它在 `_deriveBuildsCore` 的**中段**执行，之后还有 `eX372`（命中诚实修正/换反伤招）、
`eV4386`（玻璃大炮睡觉替换）、`eV4393`（roleTag 重算）、`eV4396`（日光换槽）等块**会改招组**。
改完之后两张原本不同的卡可能变得四招完全相同，而**没有人再查一次**。

量化证据：用现口径在最终输出上重跑一次，会发现 **19 对（六人队）符合「同一玩法」**——
说明这 19 对是在去重门之后才「长出来」的。

## 三、为什么不能直接把 v4.371 的门重跑一遍

19 对里有 16 对是 Jaccard = 0.60（三招相同、第四招不同），差异是**真实的打法分裂**：

| 物种 | 卡 A | 卡 B | 差异 |
|---|---|---|---|
| 烈焰马 | [0] 强化清场（输出）闪焰冲锋/飞膝踢/剑舞/替身 | [2] 强化清场（强化）晨光/替身/剑舞/闪焰冲锋 | 飞膝踢（进攻覆盖）vs 晨光（回复续航） |
| 铁掌力士 | [1] 慢速重炮（输出）真气拳/铁头/腹鼓/替身 | [2] 强化清场（强化）吸取拳/替身/腹鼓/铁头 | 真气拳（高伤）vs 吸取拳（吸血续航） |
| 冻原熊 | [0] 慢速重炮（输出）雪崩/真气拳/剑舞/替身 | [1] 强化清场（强化）吸取拳/替身/剑舞/雪崩 | 同上 |

这 16 对**不该合并**——重跑 J≥0.6 会误伤。所以末尾复查必须用**更严的口径**。

## 四、定口径：末尾复查只抓「配置全同」

```
四招集合完全相同（Jaccard = 1.0，四张卡都必须是 4 招）
&& side 相同
&& 特性[0] 名相同
&& 道具[0] 名相同
&& EV 模板相同
（roleTag 与 name 不参与判定——名字不同但配置全同，对用户仍是同一张卡）
```

各口径的减卡规模（`probe_dedup_scale.py`）：

| 口径 | 六人队 | 空队 |
|---|---|---|
| ① 现口径 v4.371 重跑（J≥0.6 全条件） | 35 | 1 |
| ② 同 ① 去掉道具条件 | 199 | 9 |
| ③ 招组相同 + 特性 + EV模板 + side（J=1.0，不限道具） | 67 | 0 |
| ⑤ 仅招组相同（J=1.0） | 141 | 10 |
| **⑦ 招组相同 + 特性 + 道具 + EV模板 + side（J=1.0 全条件）** | **8** | **0** |

选 ⑦：只抓纯重复，零产品抉择。③ 的 59 张「只差生命宝珠/剩饭」属产品口径问题（见第七节）。
