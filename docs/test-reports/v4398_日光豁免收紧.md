# v4.398 日光招豁免收紧 + 强化招排除表修正

> 版本：v4.398　字节：2,078,394　SHA1：`EECAD3ED17BBAB6A1E646C33D4E41CD0CCBD9F76`
> 改动范围：`index.html` 两处（日光换槽豁免、`_v396SELF` 表）　行为变化：3 张卡（six/empty 各一份）

## 一、问题从哪来

v4.396 处理「带日光束 76 / 日光刃 632 却没有晴天源」的卡时，留了一个豁免：

```js
if(b.score===99){
  if(core 里点名了 _dv 这一招) { b._v396Keep="score99"; return; }   // 不换槽
}
```

它的依据是「core 点名 = 机制定义 = 合法保留」。但 **`core` 只表示这张卡的机制思路与日光有关，不代表它具备免蓄力条件**——日光招在无晴天时需要蓄力一回合（只有 chloroplast 类特性免蓄力）。

于是出现这种推荐：`森林蜥蜴[1] 轻装速攻流 / 输出` 四招 `日光刃(632) / 杂技(512) / 报恩(216) / 居合劈(15)`，特性「轻装」——一个速攻手每两回合才动一次。

## 二、量化（全库 9850 卡，六人队口径）

清单：`core` 点名 76/632 的卡，共 **6 张**（six 6 + empty 6 里的 3 对重复）。

第一版探针只查了天气特性（70/584/190/871）就报「无晴源」，**漏了 chloroplast**——补查 `268/366/374` 与物种池名字后才发现走路草/臭臭花本来就是合法的。这是本项目反复出现的同一类错误：判据比引擎严。

## 三、判据改成什么

保留条件只认两条，都在原函数上方已实现：

1. `_isChl` —— 物种特性池名字匹配 `/叶绿体|耀斑|巨大树叶|Mega Sol/`，或卡上特性 id ∈ `[268,366,374]`
2. `_sun` —— 卡上特性 id ∈ `[70,584,190,871]`，或四招里含大晴天 241

`score=99 + core 点名` 这一条删除。

## 五、同时修正 `_v396SELF`（零漂移）

v4.396 的「只强化自己」排除表写成：

```js
var _v396SELF=[14,74,96,157,13,105,264,515];
```

实际内容：

| id | 名字 | 类别 | 结论 |
|---|---|---|---|
| 14 | 剑舞 | 变化 | ✓ |
| 74 | 生长 | 变化 | ✓ |
| 96 | 瑜伽姿势 | 变化 | ✓（自我强化，但名字不匹配 BSTR） |
| 157 | **岩崩** | **物理 75** | ✗ 攻击招 |
| 13 | **旋风刀** | **特殊 70** | ✗ 攻击招 |
| 105 | **自我再生** | 变化 | ✗ 回复招，不是自我强化 |
| 264 | **真气拳** | **物理 150** | ✗ 攻击招 |
| 515 | **搏命** | **特殊 1** | ✗ 攻击招 |

改成真表（变化招且名字匹配强化词，共 15 项）：

```js
var _v396SELF=[14,74,96,174,187,322,334,339,347,349,417,468,483,504,526];
```

**注意这条修正零漂移**（9850 卡逐字段 0 差异）：因为该表的用途是判断「补槽候选 `_w` 是不是自我强化招」，而 `_w` 只从**变化招**里挑，157/13/264/515 这些攻击招永远进不了候选。表错了但没触发过——修它是消除隐患。

顺带纠正两条长期记错的 id：**冥想 = 347（不是 96）、铁壁 = 334（不是 157）**。
