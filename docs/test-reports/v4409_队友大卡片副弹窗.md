## 一、立项（用户已同意的遗留项 + 探针实证）

上一版收尾时登记的未决之一是「队友大卡片（`mateCard` → `openSpById` 资料页）是否也改副弹窗」。本版按此立项，并用探针确认问题真实存在。

**同一区块两种行为**：

| 入口 | 位置 | 行为 |
|---|---|---|
| 小词条 `span.ansp` | 答案卡「带这 5 只」行 | v4.403 起 → `mateQuickModal` 弹窗，不离开核心 |
| 大卡片 `div.mate` | 核心卡「推荐 6 人队」行 / 备选网格 | 仍 `openSpById` → **直接跳资料页** |

大卡片是更显眼的入口，行为反而更粗暴。

**探针实证（`mk_dbg4409card.py`）**：

```
A_before_click:mates=20 spPage=0 l1open=0 accbd=3
clicked .mate[0]
B_after_click:mates=20 spPage=1 l1open=0 accbd=3
```

点前 `spPage=0`（不在资料页），点后 `spPage=1`（跳到资料页）、`l1open=0`（没有任何弹窗）。判定口径：`#spMvAnchor` 是否存在 = 是否在资料页；`#l1Modal.className` 含 `open` = 弹窗是否打开。

## 二、改动

1. **`mateCard` 渲染时注册 `_MQ`**：`_qk='MC|'+s2.id+'|'+coreId`；`_MQ[_qk]={r, core:teamCtx.team[0], mates:teamCtx.team.slice(1).map(x=>({s:x})), k:null}`。取 core 的依据是 `teamCtx.team[0]` 就是当前核心（调用处 23088 / 23099 都是 `[s].concat(队友)`）。
2. **整卡 `onclick` 改为 `mateQuickModal(_qk)`**，title 改为「点开预览这只在本队的完整配置（弹窗，不离开当前核心）」；`_qk` 构造失败时回退 `openSpById`。
3. **副弹窗底部新增「📖 看完整资料页」按钮**（`mqFullSp`）——资料页入口不删，只是降级为二级动作。
4. **`mqFullSp` 关闭的是一级弹窗**：`closeL1Modal()`，不是 `mqClose()`。

## 三、踩坑（两处，都已修）

**① 关错容器**：首版 `mqFullSp` 里写 `mqClose()`（关 `#mqModal`），但 `mateQuickModal` 是通过 `l1Modal(label,body)` 开的，落在 `#l1Modal`。实测：

```
after_card:mates=20 spPage=0 l1open=1 l1btns=3
click fullsp 1
after_fullsp:mates=20 spPage=1 l1open=1 l1btns=3   ← 页面切了但弹窗还盖着
```

改 `closeL1Modal()` 后：`after_fullsp: l1open=0 spPage=1`。

**② 空 catch 顶破 smoke 阈值**：`try{openSpById(id)}catch(eF409){}` 是空体，被 smoke 的「静默 catch 数量」统计到 —— 该项基线 361、阈值 >390，而 **v4.408 时已是 390**，再加 1 就 FAIL（`33/34`）。改为 `catch(eF409){toast('打开资料页失败：'+eF409.name)}` 后回到 390、`34/34`。

**结论：静默 catch 已顶在阈值边缘，后续任何空 catch 都会直接 FAIL。**
