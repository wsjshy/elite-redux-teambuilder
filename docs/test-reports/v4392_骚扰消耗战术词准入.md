## 一、立项：判据原则的另一半，一直没查

v4.390 立下的原则是两句话：**属性词按底子绝对档准入，战术词按本卡配置口径准入**。

- v4.390 查了属性词「耐久」——349 张 bulk<270 的脆皮被冠「耐久」，撤档；
- v4.391 查了属性词「输出」——185 张 `max(攻,特攻)<95` 的卡叫「主力输出」，只去掉「主力」二字；
- **「战术词按本卡配置」这一半，从头到尾一次都没被检验过。**

名字里的战术词有四类：骚扰、轮转、强化、清场（还有补盲、辅助）。它们的共同点是：**它们不承诺这只宝可梦的身体条件，只承诺这一栏招式在干什么**。于是检验方式也相反——不看底子，看**本卡实配招组**。

本轮挑其中最典型的一个词：「骚扰消耗」。

## 二、事实错误锚点：这个名字是捡来的，不是算出来的

`_v383route()`（`index.html` 17834–17839）是 v4.383 减伤轴/轮转族降级用的选择器：

```js
if(_v383imm) return '属性免疫联防位';
if(_v383off) return _v383boost ? '强化清场' : '主力输出压制';
if(_v383piv) return '轮转补盲';
return '受队消耗';                       // ← 不看招组的硬兜底
```

最后一行是**不看招组的硬兜底**：只要卡既不属性免疫、又不满足 `_v383off`（`dmg>=2 且攻/特攻 EV>=120`）、也没有折返招 369/521，就一律叫「受队消耗」。v4.389 R1 再把未过耐久门的经 `_nm.replace('受队消耗','骚扰消耗')` 改名（18193 附近）。

于是「骚扰」这个战术词被发给了招组里**根本没有骚扰手段**的卡：它继承的是「没能归进任何一档」这个兜底身份，不是「卡里带着钉子或状态招」这个事实。**这是同一类结构病的第三处，也是第一处落在战术词上。**

## 四、规则（只用既有词，不新造词）

判据：**名含「骚扰消耗」而招组三族全无 → 名实不符，按本卡实配落既有词**。顺序判定（先命中先落）：

| 序 | 条件 | 落词 |
|---|---|---|
| ① | 带强化招 **且** 伤害招 ≥1 | `强化清场` |
| ② | 伤害招 ≥2 **且** `max(攻,特攻) >= NEED_CFG.POWER_OK(95)` | `主力输出压制` |
| ③ | 伤害招 ≥2 **且** 火力 <95 | `输出压制` |
| ④ | 伤害招 ≤1 **且** 带墙 `113/115/657` | `双墙辅助流` |
| ⑤ | 其余 | `稳健联防` |

- ① 的「且伤害招 ≥1」是本版口径决定：4 张 0 伤害的强化卡（#79 / #712 / #2596 / #2597）不叫「强化清场」，分流到 ④/⑤——**只带强化招、没有任何输出手段的卡不能叫「清场」**。
- ② 与 ③ 刻意对齐 v4.391 的打手门 `POWER_OK=95`：过门的叫「主力」，不过门的叫「输出压制」。这样 423 张落词后**不会与 v4.391 的三条反向断言冲突**（见第八节）。
- 强化招判据复用引擎既有正则（与 18253 同源）：`/剑舞|龙之舞|蝶舞|冥想|诡计|诅咒|健美|巨大化|破壳|腹鼓|磨爪|铁壁|集气|自我激励|生长|宇宙力量/`
- **不动**：EV / 招组 / 道具 / 特性 / `side` / `roleTag` / 排序 / 候选集合。本版只改 `b.name`。

## 十三、教训

1. **加门槛要 grep 该指标的全部出口**（v4.391 的教训在 v4.392 又验证一次）：本版 ②③ 直接复用 `NEED_CFG.POWER_OK(95)`，而不是另写一个 95，避免同一指标出现两处不同答案。
2. **适配脚本里手写的规则函数最容易出错**：本轮在 adapt 脚本里写 `if(_V392_BST.test(String(r[1]||''))bo=true;` **少一个右括号**，两支脚本 `SyntaxError: Unexpected identifier 'bo'`（node 报在第 23 行）。引擎补丁本身写的是 `)))`，无此问题——**补丁脚本与适配脚本要分别 `node --check`**。
3. **断言豁免要按「来源」判，不能按「旧名」判**：`verify_ev` 的 169 条 FAIL 全是「名字变了、豁免白名单还对不上」。用 `b._v392Rename` 标记（来源）比继续往白名单里加旧名更稳。
4. **空队 0 / 六人队 423 的反差不是 bug**：两口径 `immCount` 阈值不同，同一批卡在空队口径下不进兜底桶。写断言时两口径必须分开给期望值，不能共用。
