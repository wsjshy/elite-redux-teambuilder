## 一、立项

答案卡（「这只就这么配」）已经把特性 / 道具 / 性格 / 努力值 / 四招 / 带哪 5 只列齐，v4.405 起队友弹窗里也各有一只的速度 chip —— 但**核心自己的速度值在卡上任何位置都没有**，想看齐六只速度得点开 5 个弹窗、还拿不到核心的数字。

速度是配队里最需要横向比的一个数（谁先手、谁压得过谁），缺口成立。改动只在展示层，不碰推荐。

## 二、口径（同源，不新造第二份算法）

| 层 | 函数 | 说明 |
|---|---|---|
| 单只速度 | `speedStat(base5, ev5, 31, 加速?)` | `floor((2*base+31+ev/4+5)*(加速?1.1:1))`；实测 base 77 / 0EV / 中性 = 190，base 100 / 252EV = 299，与手算一致 |
| 性格档 | `spdNatCatOf(nat)` | 中性 / 加速 / 减速 |
| 档位 | `mqSpdRank` → `spdRankOfVal` + `spdTierOf` | v4.407 定的 90/75/50 超速/高速/中速/慢速 |

新增 `spdStatOf(s, ev5, natName)` 把前两层包成一个入口：**核心与队友都走它**，区别只在参数从哪取（核心取 `bd.ev.alloc[5]` + `bd.nat[0][0]`，队友取 `mateAssemble(r,…)` 出来的 `asm.ev.alloc[5]` + `asm.nat`）。队友弹窗原有的速度 chip 同步改写为调用 `spdStatOf`，`index.html` 里不存在第二份速度公式。

## 三、改法

1. **答案卡**：`cardInner()` 里「努力值」行后追加「速度值 `<数字>` [性格加速/减速] [档位]`」，点击 → `teamSpdLine(key)`。
2. **数据登记**：`window._SL[SID|k] = {core, bd, mates, team, sys}`（与既有 `window._MQ` 同一处登记，`k` 跟随「换玩法」）。
3. **弹窗**：`teamSpdLine` 逐只算速度、按速度降序、核心标 ⭐，末尾一句快慢归属。走 `l1Modal`（与队友弹窗同层，点空白/× 关闭，不跳页）。
4. **两处文案修正**（本版自己引入又自己发现）：
   - 快慢计数原本在单趟 `forEach` 里边走边判，而核心在排序后位于中间位置，赋到 `c` 之前先把「比它快的」全漏掉了 → 1503 明明被波荡水 317 压过却输出「它是本队最快」。改为**排序后先定核心、二次循环统计**，并把快者名单带上。
   - 慢核心（穿山鼠 116 速、沙暴手）原本写「要压过这 5 只，靠先制招…」—— 对一只定位就是慢的怪没意义。改为「它是本队垫底的一档——先手权不归它，靠先制招、戏法空间或轮转」。

## 六、踩坑

1. **单趟循环不能边算边用未定的基准**：排序后「谁是核心」在中间才出现，一趟循环里用 `c` 做比较必然把前半段漏掉。凡「以某一只为基准统计其余」的展示，一律**两趟**（先定基准、再统计）。
2. **文案要按角色分层写**：慢核心不是「要压过别人」，而是「先手权不归它」。v4.411 的教训（同一段里主语反了）在这里是同一类问题 —— 数值对了，结论句仍可能在胡说。
3. **同一 Dialog 层要一致**：新弹窗最初借用 `mq`（二级层 `mqPaint`），但队友弹窗走的是 `l1Modal`；从答案卡点开的一级入口统一用 `l1Modal`，避免出现「有的弹窗有返回条、有的没有」。
4. **标签别贴着同义数字**：`252速` 后面紧接 `速度 299` 读成「252速 速度」，改标签为「速度值」。
5. **headless `--dump-dom` 重定向**：`cmd /c "... > file 2> $null"` 会报「命令语法不正确」且写出 0 字节；`2> 具体文件` 才稳定（本段复现两次）。

## 七、结论

- 缺口（核心速度无处可看、六只无法横向比）已闭合，入口只多一个 chip，不加区块、不增滚动。
- 口径单源：核心 / 队友一个函数、一个档位表；两处数字逐只核对一致。
- 文案自相矛盾两处已在本版内修掉并有实测样本。
- 待线上核验后回填 AGENTS 版本表与 VERSIONS 发布行。
