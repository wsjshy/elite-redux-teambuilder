# v4.430 测试报告：收尾兜底场地招同源门控 + v4.393 改名链双轨取证

- 日期：2026-11-25
- 触发：用户长期授权「继续推进，举一反三」
- 版本：index.html `v4.430`（2,147,429 B，SHA1 `739EE8F75FD4A7DA3253FAC79A1C9C6CDE7D9BF1`）／package `4.430.0`
- 性质：**零卡面漂移的防御性补漏 + 常驻门禁 + 历史问题取证**。当前线上推荐结果不因本版改变。

## 1. 选题过程：三个候选被数据证伪

沿用 v4.428/v4.429「卡内实际事实 vs 能学潜力」的方法，先审计输出/增伤手的变化招，避免为改而改。

### 1.1 异常状态招（86 电磁波 / 92 剧毒 / 261 鬼火）

按速度 × 耐久 × 攻击数分层，并核查恶作剧之心、耐久、强化、守住、卡名、攻击贫乏等资格：

- 剧毒 80 张中 78 张有依据（毒疗站场、诡计强化、守住+剧毒 DoT、急速折返游击等）。
- 鬼火 29 张全部有依据。
- 电磁波 163 张中 127 张有依据；其余 36 张细看均为电系高速特攻手的经典模板（本系电招 + 补盲 + 伏特替换 521/急速折返 369 + 电磁波；伏特替换本身是攻击招，多为三攻 + 控速）。

**结论**：主动干扰/控速有独立战术价值，不能当被动保命招一刀切，放弃删除式收口。

### 1.2 即时回复招（105/234/235/236/303/355/156）

输出/增伤卡 265 张，其中 260 张有依据（耐久、慢速、强化窗口、回复特性、剩饭、攻击贫乏）。5 张疑似逐个核对均合理：

| 物种 | 配置要点 |
| --- | --- |
| #6 喷火龙 | 弱点保险 + 三攻 + 羽栖 |
| #430 乌鸦头头 | 生命宝珠 + 羽栖续航 |
| #478/#1890 雪妖女(+Y) | 双倍奉还反伤 + 自我再生 |
| #615 几何雪花 | 弱点保险 + 三攻 + 回复 |

**结论**：证伪，不收口。

### 1.3 FUNC_FILL 的守住/同命

`FUNC_FILL_ZH` 在 v4.428 删除过「替身」但保留「守住」。其唯一消费方 `finalizeBuildInPlace` 只在攻击招补不满 4 槽时才走该池，是无攻击招/极低攻物种的有意兜底。实测全库仅产出 4 槽：

- 守住 182 ×2：#789 科斯莫古、#2262 弱丁虫-虫群（攻击池仅 3 招、无替代，与 v4.429「无 pick 不替换」一致）。
- 同命 194 ×2：#202 果然翁、#360 小果然（肉盾辅助经典）。

守住没有替身的 1/4 HP 代价，**不是替身式漏网**，不应同源删除。

### 1.4 v4.429 补位质量顺带复核

334 个替换槽中 333 个补攻击、1 个补功能（105 自我再生）；无低命中（<70）、无真低威力（双倍奉还 68/金属爆炸 368/陀螺球等机制威力字段为 0/1 属误报）、无实质侧别错误（#721 波尔凯尼恩的扑击按防御算伤）。11 张蓄力/僵直招均出现在攻击池贫乏、铁拳特性、拳系主题或反伤+羽栖协同的物种，且来自核心 `pickAttacks` 同源评分。

攻击补位对象的 `tag` 被末尾块写成「功能」，但该字段仅在 why 为空时作兜底文案，而收口必写 why；全库 tag 风格本就不统一，不可见、无逻辑消费，故不改。

## 2. 真缺口：队伍级设置招的两条收尾旁路

v4.425 确立的进攻手门控：

- `isOffRoleTag(role)`：增伤/输出/强化；
- `isFieldSetupId(id)`：天气（240/241/201/258/580/581/604/641）、366 顺风、433 戏法空间、113 光墙、115 反射壁、657 极光幕。

此前只接入三处：`pickFuncs`（约 L12075）、功能列表（约 L14173）、`fillMvSlots`（约 L15206）。审计发现两条收尾路径未接：

1. `finalizeBuildInPlace` 的 `FUNC_FILL` 循环（中文名兜底池含「顺风」「戏法空间」）。
2. `_deriveBuildsCore` 末尾替身收口（约 L19296）与守住收口（约 L19318）的攻击耗尽功能池：
   `[92,86,317,366,105,202,234,235,236,303,355,409,73,369,521]`，其中 **366 是唯一 field id**（无天气/墙/空间）。

### 补丁（同源判据，最小字节）

- FUNC_FILL 的跳过条件追加：
  `||(isOffRoleTag(role)&&isFieldSetupId(_idc))`（`role` 为该函数内已定义局部）。
- 两处功能池定义后链式过滤：
  `.filter(function(id){return !(isOffRoleTag(b.roleTag)&&isFieldSetupId(id))})`。
- `tools/headless/make_harness.py` 导出 `isOffRoleTag,isFieldSetupId` 并重建 harness。

## 4. INV17 与 v4.393 改名链历史双轨

### 4.1 INV17 精确口径

`verify_invariants.js` 新增 INV17，只检查最终 `b.mv.main` 四槽（不把 `mv.func` 候选池算作已带）：

执行段新增 `[LEGACY]` 动态计数（不硬编码基线）：

```
[LEGACY] v4.392/v4.393 改名链历史双轨：71 张（six 71/empty 0），INV17 不计 FAIL
```

### 4.2 71 张的构成

全部带 `_v393RoleAlign=1`：

- 队友口径：six 71 / empty 0；
- 外层 role：输出 25、强化 46；
- 招式分布（按招计 72，一卡可多招）：戏法空间 433×34、光墙 113×27、顺风 366×9、反射壁 115×1、冰雹 258×1；
- 来源：主选权重 42、墙体系注入 28、「名含空间→补入」2。

典型：#12 巴大蝶[0]（终极吸取 202/顺风 366）、#440 小福蛋[1]（替身/冥想 347/光墙 113）、#954 虫甲圣[1]（戏法空间 433/光墙 113）。

### 4.3 根因链（不是 v4.425 门控回灌）

1. v4.392（约 L18790）把没有骚扰手段的「骚扰消耗」卡中，`_d>=2`（至少 2 个伤害招）者按火力改名为「主力输出压制/输出压制/强化清场/双墙/联防」，**只改名字**。
2. v4.393（约 L18822）为消除「攻击向名字 + 肉盾 roleTag/EV」的表面矛盾，把 `roleTag/EV/性格` 对齐成名字暗示的进攻 role；注释明确「招组/道具/特性/side 不动（沿用 v4.385 只动 EV/nat 纪律）」。
3. 这些弱攻击/功能种族在 mkBuild 阶段按肉盾职责选出的顺风/墙/回复被保留；后续「名含空间→补 433」「墙/屏障体系入槽」等名字驱动注入又补入对应招。

最终形成「外层进攻流派名 + 进攻 EV，内层辅助实招」的分裂。直接删除顺风/墙/空间只会让巴大蝶、小福蛋这类攻击贫乏物种剩下更弱的攻击招，实战更差。

### 4.4 处置：立 v4.431，不在本版硬改

正确修法是让名字、roleTag、EV 与实际配招重新同源，方向二选一或组合：

- 收紧 v4.392 改名准入：火力不足、攻击招质量差或功能招占主导时不攻击化，落到辅助/联防命名；
- v4.393 对齐时若配招仍为功能主导则不攻击化，或改名时同步重算 `buildMoves`、道具与特性。

该改动牵动命名、EV/性格、道具、队友匹配与答案卡上层换人逻辑，且真实用户队伍（非固定测试 TEAM）的暴露面尚未量化，因此单独立为 **v4.431 名实同源专项**。本版仅锁定：新生成路径进攻手场地招零回灌；历史 71 张由 `[LEGACY]` 行与 gates 台账跟踪，不允许数量异常增长。

复跑探针（workspace `v4393/`，require 仓库 harness）：

- `classify_inv17.js`：按 six/empty、role、招 id、来源、`_v393` 分类计数；
- `dump_one4430.js <id...>`：打印单卡 name/roleTag/每招 why；
- `diff_six4430.js`：双 harness six 全量对比。
