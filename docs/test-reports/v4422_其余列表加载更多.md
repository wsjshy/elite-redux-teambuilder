## 二、改法（三处）

1. **招式「谁能学」**：模块级 `_mvLkStep=60`，`box.innerHTML=''` 后建 `grid`(.mxgrid, max-height:320; overflow:auto) + `foot`；内部 `fill()` 用 `list.slice(shown,shown+step)` 逐张建卡（`.mxc lkcard`、`data-sid`、`el.title` 属性赋值、`onclick` 关闭 drawer 跳详情）；`grid.onscroll` 距底 32px 自动 `fill()`；`foot` 显示「加载更多（还有 N 只）」，无剩余时「共 N 只 · 已全部显示」。
2. **特性持有者两列**：抽出 `abiOwnerCards(arr)` 纯字符串构造器；`abiOwnerCol(title,list,abid,kind)` 外层 `<div class="abicolw" data-abid data-kind data-shown>`，`list.length>60` 时输出 `.ownmore` 内联 `onclick="abiOwnerFill(this)"` 按钮；`abiOwnerFill(btn)` 从 `btn.parentNode.parentNode` 取 wrapper → 读 `data-abid/kind` 重算 `lkFilter(...)` → `slice(shown,shown+60)` → 追加 → 更新 `data-shown` 与按钮文案。
3. **特性结果卡**：改两趟——先 `matched.push(a)` 收全部命中并统一 `_hidN` 统计，原循环体抽成 `_abiCardOf(a)`（内部重声明 `zh/en/desc`，去 `_hidN+=`，末尾 `return card`，并绑定持有者列 `onscroll` 触底 → 点 `.ownmore button`）；尾部 `foot` + `_abiFill(60)` 分批 `appendChild`，按钮「加载更多（还有 N 个）」，`if(foot.parentNode===box)box.appendChild(foot)` 保证按钮永远在最后；`_st` 统计改用 `matched.length`。

## 四、踩坑（真 bug，值得记一笔）

- `abiOwnerFill` 初版写成 `Array.prototype.forEach.call(tmp.children, x=>grid.appendChild(x))`：`children` 是 **live HTMLCollection**，边 append 边迭代会跳过一半节点，实测「还有 13 只」只进了 7 只（60→67）。改 `Array.prototype.slice.call(tmp.children)` 先快照后，60→73 一次到位。
- 诊断误判：先按 `querySelector('#abiResult .abicolw[data-abid]')`（取第一个匹配列）+ `querySelector('#abiResult .ownmore button')`（取第一个按钮）判定，两处命中的是**不同卡片**，于是看到「列 21 只却报还有 13 只、点击不追加」。改为按 `data-abid="22"` 精确取卡后才定位到真因。**验证脚本也必须按唯一键取元素，否则自造伪缺陷。**
