## 一、立项（v4.409 截图里发现的真实问题）

v4.409 的截图里，队友弹窗第一段是这样两句：

> 你开晴，席多蓝恩的本系直接吃晴增伤——同一张牌两个人吃。队友 席多蓝恩（干旱）替你 把晴铺开，你的晴受益特性才有用（窗口 8 回合）

第一眼像「物种名重复」，细看是**主语相反**：一句说「你开晴、队友吃」，另一句说「队友开晴、你吃」。读者无法判断到底谁开。

**根因**（`index.html` `MATE_NARR`）：

| 规则 | 条件 | 文案主语 |
|---|---|---|
| `N-03`（corePri 1） | 核心是某系统 setter，队友受益该系统 | 「**你**开 X，队友吃」 |
| `N-04`（corePri 1） | 队友是某天气 setter，核心受益该天气 | 「**队友**开 X，你吃」 |

当双方**都是同一天气的手、又都受益**时，两条同时成立，`mateWhyNarr` 按 `corePri` 排序依次取，前两位正好是这两条，于是两句并排、主语互斥。

## 二、量化（不是个例）

在真实页面枚举「双方都是同一天气 setter、且彼此都受益该系统」的组合（`mk_dbg4410why.py`）：

```
setters_wx_with_self_benefit=175
both_direction_pairs=2969
```

**2,969 对**。沙 / 晴 / 雨 / 雪 各系统都有，例如：

- `27|穿山鼠 + 28|穿山王 | 沙` → 「你开沙，穿山王的本系直接吃沙增伤」+「队友 穿山王（扬沙）替你把沙铺开」
- `1503|超级喷火龙Y + 485|席多蓝恩 | 晴` → 同上（晴）

对照组（只有 1 句提到该系统）如「走路草 + 谢米 | 青草场地」——因为 `N-04` 只接受 `isWxSys`（天气），场地不参与，所以不会矛盾。**这解释了为什么矛盾只出现在天气系统上。**

## 三、改法（同源、不新增第二份判定）

1. `N-03` 的 `f` 增加第 5 个可选参数 `ctx`，命中时 `ctx.st=sy`；`N-04` 同样 `ctx.st=st`。返回值一字未改，其他调用点不受影响。
2. `mateWhyNarr` 循环里给每条规则一个独立 `ctx`，并记录 `meta={id, st}`。
3. 命中 `N-04` 且 `ctx.st` 与已入列的 `N-03` 项 `st` 相同时：**把那一句就地替换成合并句**，不再 push 第二句。

合并句：

```
你和{队友}都能开{系统}、也都能吃{系统}增伤——谁先上场谁铺，窗口 {abilityDurTurns} 回合
```

**关键设计**：判「是不是同一个系统」用的是 N-03 / N-04 自己算出来的 `ctx.st`，**不是另写一份 `isSetterAny`/`spSys` 判断** —— 符合「同名口径必须同源」铁律。

**副作用（有意保留）**：合并后空出一个位置，循环会继续尝试补一条其他维度的句子。实测出现「合并句 + 队友铺钉子压血线」，读起来是天气 + 钉伤两个维度，不矛盾且信息更丰富。
