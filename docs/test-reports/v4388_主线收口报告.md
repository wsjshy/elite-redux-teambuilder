## 六、终止条件与维护模式

**五条同时满足才算收口**

1. 五轴断言全 0 且可复跑（每版发布前跑全部 verify_*）
2. 名实一致无残留：nameMismatch / v13Demoted / v383Demoted 里「名字仍与 (side, role, 实际招组, EV, 性格, 道具) 冲突」= 0
3. 默认唯一最优解成立：进攻身份物种默认 [0] 违规 = 0，13 只白名单例外逐条写明理由
4. 数据层事实错误 = 0
5. 零漂移纪律：每版用改前快照证明未命中判据的卡差异 0

**终止开关**：连续两个版本同时满足 gate Δ=0、全部 verify_* = 0、且无新发现的事实性错误（只剩主观偏好/阈值微调/结构性不可修）→ 宣布主线收口、转维护模式。v4.387 与 v4.388 正好构成这两个版本。

**维护模式定义**：只处理用户报告的个案，不再主动开「再收口一轮」「再对齐一层」的版本。发现新事实错误才破例。

**明确不做**：墙类单墙保命；玻璃大炮披带不默认替换生命宝珠；存档不作数据参考；近配置联防匹配；速度/披带分档带（<270 / 270–299 / ≥300）不再调整。
