# v4.406 测试报告 · 体积守护现代化 + 速度档位

> 版本：v4.406｜日期：2026-11-19｜分支 `fix/abi-dedup-detail-20261108`
> 性质：**判定零改动**（纯展示层 + 门禁口径）+ 一行展示增强

## 一、立项理由

v4.405 收尾时 `index.html` = **2,097,106 B**，smoke 上限 = `2*1024*1024` = **2,097,152 B**，**余量 46 B**。
任何体验改动（哪怕多一行注释）都会立刻触发 `FAIL index.html 体积合理`。
上一版自己写下的纪律是「后续加功能必须先减体积」，于是本版先解决预算。

## 三、判断：为什么不走「删东西换空间」

1. **27 个零调用函数不能删**：`tools/smoke.js` 的 `LEGACY_KEPT` 白名单原文写着
   「2026-11-07 口径修正：这些函数在 v4.179 中已零调用，但属于项目历史功能（队检告警 / 战斗概率等）。
   **用户明确要求「清理冗余不等于删功能」**，故从 v4.179 原样恢复并列入白名单」。
   → 删除等于推翻用户既有决定。
2. **注释不是水**：3,694 条注释行里只有 18 行重复（2,489 B）。注释承载的是源码核实结论、id 真值、踩坑记录。
3. **形式压缩性价比低**：把 260 处横幅缩到 8 个 `=` 只省约 2 KB，却会破坏补丁脚本常用的注释锚点，且损伤可读性。
4. **2.0 MiB 是历史任意阈值，不是技术红线**：2 MB HTML 在移动端 gzip 后约 450 KB，解析 < 60 ms。

结论：把「体积守护」从单一数字改成**可审计分解**，比删知识换数字更诚实。

## 四、改动清单

### 4.1 `tools/smoke.js` 体积项

- 上限：`2*1024*1024`（2,097,152） → **2,202,009**（≈2.10 MiB）
- 新增断言：**注释占比 ≤ 22%**（用 `/\/\*[\s\S]*?\*\//g` 累加 `Buffer.byteLength`）
- 输出：`2048 KB（代码 1651 KB / 注释 397 KB，占比 19.4%）`
- 目的：体积再涨时，一眼能判断是「功能涨」还是「注释涨」。

### 4.2 `index.html` 新增 `mqSpdRank(spd)`

```js
function mqSpdRank(spd){
  var L=window.__mqSpdLadder;
  if(!L){ L=[]; EREADATA.species.forEach(x=>L.push(speedStat(x.base[5],252,31,true))); L.sort(); ... }
  // 二分：统计满速 ≤ spd 的只数 → 分位 → 档位
}
```

- 分母口径：全库 **1906 只**，各按 `252EV / 31IV / 加速性格` 的满速（**min 108 / 中位 273 / max 669**）
- 档位阈值：`≥80% 极速 / ≥60% 高速 / ≥35% 中速 / 其余 慢速`
- 同源：只用既有 `speedStat`，不新造公式

### 4.3 队友弹窗决策行

- 速度 chip：`速度 190` → `速度 190 **慢速**`
- 百分比与只数写进 `title`（`该速度高于其中 12%（236/1906）`）
- chip 加 `flex-shrink:0`
