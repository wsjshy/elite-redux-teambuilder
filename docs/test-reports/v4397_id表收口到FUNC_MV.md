## 三、根因：真源从未缺失，只是持续被绕过

`index.html` **L11624** 早就有单一真源（顶层 `var`，段 #5 内，11 个键）：

```js
var FUNC_MV={
  rec:[105,202,234,235,236,303,355,409],
  boost:[14,187,334,339,347,349,417,468,483,504,526],
  boostPhys:[14,187,334,339,349,468,504,526],
  boostSpec:[347,417,483],
  hazard:[191,390,446,564],
  removal:[229,432],
  speed:[86,317,366,433],
  protect:[164,182],
  pivot:[369,521],
  wear:[73,92],
  weather:[201,240,241,258,580,581,604,641]

```

**但后来的补丁块绕过了它，各自硬编码同一张表** —— 墙表被抄 6 次、折返招 9 次、钉子 4 次。补丁越多，绕过的地方越多，「真源」名存实亡。

这才是用户直觉「整体性降低」的准确落点：**不是表太多，是同一张表在多个地方各写一遍，改规则时容易改一处漏一处**。

## 四、方案：只做等价替换

原则：**只替换纯字面量副本，不碰任何带运算的表达式**。

- `FUNC_MV.boost.concat([504,526])`（L16064 / L17819 / L17877）—— `boost` 已含该两元素，简化会改变数组长度语义，**保留原样**。
- `(FUNC_MV&&FUNC_MV.speed)||[86,317,366,433]`（L23889，段 #6）—— 跨 script 段拿不到段 #5 的顶层 `var`，兜底必须留，**保留原样**。
- `WX_NEVERMISS={'雨':[87,542],…}`（L1508）—— 本身就是真源，**保留并作为 rainPerfect 的取值依据**。
