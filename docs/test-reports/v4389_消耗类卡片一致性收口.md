## 一、立项：用户两问引爆的系统性事实错误

用户提问两句：

1. 「超级耿鬼适合受队消耗的流派吗，评判一下」；
2. 「这个流派你没带任何攻击技能，怎么选择内敛性格呢」。

只读探针核到的实况（v4.388，六人队 #1509 超级耿鬼Y）：

```
[1] 受队消耗 | 内敛 | [252HP / 4特防 / 252特防] | 剧毒/电磁波/替身/守住 | 剩饭
```

- **物种不适合**：超级耿鬼Y 的 bulk 远低于受队消耗所需的耐久门槛，四招全为变化招、零输出；
- **性格自相矛盾**：`内敛` 是 **+特攻 −攻击**，而这张卡 **0 个伤害招、特攻 EV=0**，性格正项完全空转。

结论不是个案：`_v383route()` 兜底垃圾桶（`index.html` 17834–17839，最后 `return '受队消耗';`）把**所有未能归类的卡**都倒进「受队消耗」，于是「受队消耗」这个名字承担了两种物种完全不同的战术：真耐久消耗位，和脆皮骚扰位。这不是命名瑕疵，是**名实不符的系统性事实错误**。

附带承认一处**早前判定的口径过粗**：v4.388 收口时把「⑤ 防守卡首项性格偏进攻」整体裁定为「不修（属优化空间）」。其中「**零伤害招**」那一档不是浪费，是**配置内部自相矛盾**，必须修；「有伤害招但进攻项 EV≤4」那一档维持不修。

## 四、三条规则（定死，写进引擎收尾块）

- **R1 名称分流**：名含「受队消耗」→ 只保留 `bulk≥BULK_HIGH(300)` 或 `bulk≥BULK_MID(270) 且有真回复`（回血招 / 回复特性；**剩饭、黑色污泥不算**）；不够格按**实配伤害招条数**分流：`≤1` → **骚扰消耗**，`≥2` → **耐久压制**。保留原前缀（「顺风受队消耗」→「顺风骚扰消耗」），**roleTag / side 一律不动**（改 roleTag 会连带队友挑选 `ftC()` 与 EV 模板，且会击穿 gate 的 offHist 基线）。
- **R2 快卡加满速度**：名含「骚扰消耗」且基础速度≥`SPEED_HIGH(100)` 而速度 EV=0 → EV 改 `[252,0,0,0,4,252]` + summary `252HP / 4特防 / 252速`，性格取加速项（特攻侧 → `胆小`，物攻侧 → `爽朗`）。
- **R3 零伤害防守卡换性格**：防守身份卡（role∈{肉盾,受队,联防,辅助} 或 名匹配 DEF_NAME）且**实配零伤害招** → `nat[0]` 改为实际投资项：特防 EV>防御 → `沉着`/`慎重`，防御 EV>特防 → `大胆`/`淘气`；**只改 nat，EV 不动**；R2 命中者跳过。
  **减项必须落在低投入的一侧**：若「攻」EV 高于「特攻」EV（或相等而基础物攻更高），改用 `淘气/慎重`（−特攻）而不是 `大胆/沉着`（−攻击）——否则会出现「减攻但攻 EV 满投 252」的新矛盾（本轮首版即踩：4 张 #151/#213/#235/#1526 被 verify_ev ③ 抓出）。

引擎内真回复集 `_v389REC_MV` = {105,202,234,235,236,303,355,409,156,456,532,631,72,71,837,73,135,208,275,392,622,744,915}；回复特性 `_v389REC_ABI` = {144 再生力, 90?} 按引擎既有口径。
