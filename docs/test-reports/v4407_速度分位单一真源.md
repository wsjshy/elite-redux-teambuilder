# v4.407 测试报告 · 速度分位收敛到单一真源

> 版本：v4.407｜日期：2026-11-19｜分支 `fix/abi-dedup-detail-20261108`
> 性质：**纯展示层口径统一 + 代码减负**（推荐结果零漂移）

## 一、立项理由（怎么发现的）

v4.406 给队友弹窗新加了一套速度档位（`mqSpdRank`，阈值 80/60/35）。做 v4.407 勘察时发现页面里**本来就有一套**：核心卡努力值行的 `_spdBadge`（阈值 90/75/50，词为「超速 / 清场 / 中速 / 慢速」）。同一页面里同一个速度，两处可能给出相反结论 —— 这违反「同名口径必须同源」。于是本版主题定为**收敛**，而不是继续加功能。

## 二、探针（一次性查清全部分位实现）

`mk_dbg4407.py` 把页面加载后的计算结果写进 `document.title`，用 `--dump-dom` 抓取。改前结果：

```
arrLen=1906
v190  mq={"pct":12,"tag":"慢速"}  rk=12   A=慢速  B=慢速
v253  mq={"pct":40,"tag":"中速"}  rk=40   A=中速  B=慢速
v438  mq={"pct":99,"tag":"极速"}  rk=98   A=极速  B=极速      ← 分位差 1
pct={"n":1906,"P50":273,"P75":331,"P90":372,"P95":394,"P99":441}
pctVal=273/331/372/394/441        pctMismatch=（空）
badge190=P12慢速  badge253=P40慢速  badge438=P98超速
```

（A = v4.406 弹窗阈值 80/60/35；B = `_spdBadge` 阈值 90/75/50；rk = `spdRankOfVal`）

**四处实现、两套阈值、两套词**：

| # | 实现 | 用途 | 问题 |
|---|---|---|---|
| 1 | `speedPctiles()` | P50–P99 百分位表 | 自己重建一遍 1906 只排序 |
| 2 | `speedPctileRankOf(s)` | 物种 → 分位 | **每次调用都重排 1906 只，不 memo** |
| 3 | `spdPctileArr()` + `spdRankOfVal(v)` | 速度值 → 分位 | memo 版本（正确的那个） |
| 4 | `mqSpdRank(spd)`（v4.406） | 队友弹窗档位 | 又自建一套数组 + 二分，且用 `<=` |

`spdRankOfVal` 用 `arr[mid] < v`，`mqSpdRank` 用 `L[mid] <= spd` —— 这就是 438 速度 P98 / P99 的根因。

## 三、定规则

1. **阈值取既有那套（90/75/50）**，不自造。理由：`_spdBadge` 自 v4.72 起就在核心卡展示，玩家已熟悉；v4.406 的 80/60/35 只活了一天且未经反馈。
2. **词取「超速 / 高速 / 中速 / 慢速」**：「清场」是打法词不是速度词，改「高速」；不用「极速」是因为页面早已用「极速档」指代**满速计算口径（252+性格）**，同一个词两个含义会再造混淆。
3. **分位只留 `spdRankOfVal` 一份**（memo 数组），其余三处全部改调它。
4. **展示层默认口径**：`P{分位}{档位}`（如 `P12慢速`），弹窗 chip 用同一函数取词。

## 四、改动清单（`patch_v4407.py`，五处锚点全部 `count==1`）

| 位置 | 改动 |
|---|---|
| `speedPctiles()` | 改为读 `spdPctileArr()`，删掉自建数组 |
| `speedPctileRankOf(s)` | 一行：`return spdRankOfVal(spdMaxOf(s))`（顺带去掉每次重排的性能浪费） |
| `_spdBadge(p)` | 新增全局 `spdTierOf(p)`，徽标改用它出词；「清场」→「高速」 |
| `mqSpdRank(spd)` | 由 14 行缩到 2 行：分位走 `spdRankOfVal`、档位走 `spdTierOf` |
| 弹窗 chip title | 「高于其中 12%（236/1906）」→「P12（全库 1906 只）」 |

新增单一真源：

```js
function spdTierOf(p){p=Math.max(0,Math.min(99,+p||0));return p>=90?'超速':(p>=75?'高速':(p>=50?'中速':'慢速'))}
```

## 八、教训（写进 gates.md）

- **加新展示口径前，先 grep 同一概念的既有实现**：`_spdBadge` / `speedPctileRankOf` / `spdRankOfVal` 三个函数名都能 grep 到，v4.406 立项时漏了这一步，结果一天内就要返工。
- **「同源」不能只写在注释里**：`spdPctileArr` 的注释早写着「自洽：v=spdMaxOf(s) 时 ≡ speedPctileRankOf(s)」，但两份代码分别二分、比较符还不一致 —— 注释声称的同源必须用探针逐值验。
