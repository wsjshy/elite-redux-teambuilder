# v4.401 补槽不得落「纯降对手能力」的招

> 版本 v4.401 ｜ 日期 2026-11-17 ｜ 基线 v4.400（gh-pages `e5b27da`）

## 一、问题从哪来

上一版 v4.400 修的是**卡名承诺的机制在不在四招里**（机制前缀名实）。这一版继续往卡内走一层：**四招里的每一格，是不是真有用**。

探头从「属性免疫联防位」这类辅助/联防卡扫起，看到一批卡的第 4 格塞着这几招：

- **43 瞪眼**：一般 / 变化 / 威力 0 / 命中 100 / PP 20 —— 降对手防御 1 级
- **39 摇尾巴**：一般 / 变化 / 威力 0 / 命中 100 / PP 20 —— 降对手防御 1 级
- **108 烟幕**：变化 / 威力 0 —— 降对手命中
- **204 撒娇 / 213 迷人**：变化 / 威力 0

共同点：**威力 0、只降对手一项数值、不产生任何持续状态**。而它们所在物种的招式池里，明明有更好的选择。

### 探针第一版翻车（记下来）

第一版探针把「嫌疑人」定义成一张 70 项的宽表（热风257 / 铁尾231 / 月光236 / 磷火261 / 挑衅269 …），命中六人队 1022 张、空队 855 张 —— **全是误判**。把恢复招、天气招、正常输出招都算成坏招了。

第二、三版才收敛：

1. `MV[id]` 的结构是 `[id, 中文名, 英文名, 属性, 类别, 威力, 命中, PP, ...]` —— 判变化招必须用 **index 4（类别）**，用 index 3（属性位）会得到「变化招=0」的假结果。
2. **`45 叫声` 在 ER 里不是纯减益** —— 它是`一般 / 特殊 / 威力 60 / 命中 100 / PP 15`的**攻击招**。#831 毛辫羊带「叫声」是有效输出，必须从嫌疑名单剔除。

精确命中：六人队 **8 张** / 空队 **7 张**（含被剔除前的 #831）。

## 三、定规则

### 三条约束（都是被实测推翻后才定下来的）

**约束一：只改「兜底结果是纯减益招」这一种情形。**

首版草稿是把兜底整体改成「白名单优先」。实测改动面 six 22 张 / empty 12 张，其中出现明显退步：

| 卡 | 旧 | 首版草稿 | 为什么退步 |
|---|---|---|---|
| #939 电肚蛙 减伤轴 | 156 睡觉 | 270 帮助 | 睡觉是唯一回复；帮助是**双打增益招，单打完全无用** |
| #872 雪吞虫 稳健联防 | 78 麻痹粉 | 270 帮助 | 麻痹粉是 100% 命中的硬控 |
| #694/#695 伞电蜥/光电伞蜥 | 97 高速移动 | 270 帮助 | 高速移动支撑「轮转补盲」的速度线 |

**约束二：白名单不许出现 270 帮助、203 挺住、182 守住、164 替身。**

- 270 帮助：双打招，单打零收益
- 203 挺住：只在致命一击时保留 1HP，价值远低于一个状态招
- 182 守住 / 164 替身：绝大多数卡已经在四招里（`_ok` 会跳过），放进白名单只剩误伤风险

第二版草稿（含 203/182/164）实际把 #363/#364 海豹球的「白雾」、#872 的「麻痹粉」、#939 的「睡觉」、#2180 的「变圆」、#2636/#2637 的「剑舞」统统换成 **203 挺住**，退步更明显，同样弃用。

**约束三：价值排序——状态 > 队医 > 减伤 > 封招 > 种子。**

最终白名单（按价值降序）：

```
[92, 86, 261, 269, 312, 215, 113, 115, 657, 73]
剧毒 电磁波 磷火 挑衅 芳香治疗 治愈铃声 光墙 反射壁 极光幕 寄生种子
```

`95 催眠术` 与 `54 白雾` 被**故意排除**：它们是有效招而非缺陷，把「睡眠换成烧伤」「挡降能力换成封招」当改善属于风格偏好，不该由一次口径收紧替用户拍板。排除后 #77/#78 小火马族的催眠术、#740/#1899 好胜毛蟹族的白雾都保持原样。

## 七、工程细节

- 字节级补丁（Python 读 bytes / decode / replace / encode），三处锚点各断言 `count(OLD)==1`。
- 插入块换行先归一 LF 再以 `\r\n` 重建，保证 CRLF 计数只按插入行数增长。
- 读写 `index.html` / `AGENTS.md` / `package.json` 一律 `newline=''`，避免 universal newlines 把 CRLF 归一成 LF。
- 补丁前备份 `%TEMP%\index_before_v4401.html`（2,084,606 B / `1DE8CCBD…`）；本版补丁反复回滚重打 4 轮（每轮都从该备份恢复并用 SHA1 核对回到 v4.400）。
- 改引擎后必跑 `make_harness.py`；`cmp_v4401.py` 按 (物种 id, 卡序 i) 精确对齐，不做全字段签名配对。

## 八、这一版学到的（长期记）

1. **同一个「兜底按 id 升序」的缺陷会在多处复现。** 加一个门槛或口径，必须 grep 该指标的全部出口 —— 本版两处（`_cd[0]` 与 `_cd9[0]`）就是 v4.391 教训的重演。修法是把黑白名单提到共用作用域，两处引用，而非各抄一份。
2. **「补一个好的白名单」比「改一个坏的条件」风险更大。** 白名单一旦混进双打招（270 帮助）、低价值招（203 挺住），改动面会立刻从 8 张膨胀到 24 张且方向反了。白名单只能放**当前口径下无条件可用**的招。
3. **探针的正确性优先于结论。** 本版第一版探针（70 项宽表）命中 1022 张全是误判；`MV[id]` 的类别位在 index 4 不在 3；`45 叫声` 在 ER 是威力 60 的特殊招不是纯减益 —— 三个坑任何一个没排掉，都会得出错误的全库数字。
