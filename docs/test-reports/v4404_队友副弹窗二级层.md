## 一、用户诉求（原文）

> 弹出的窗口信息不足，很多的都点不了，并且点击之后也不能丢失已有的弹窗。

拆成三条：

1. **信息不足**：v4.403 的队友窗只有 名字+属性+2 句为什么+一行配置 summary+四招名字。
2. **多数点不了**：窗内四招只在文字上「看着像按钮」，特性/道具/性格完全不可点。
3. **点开就丢窗**：点四招走 `mvModalById` → 复用同一个 `l1Modal` 容器，队友窗内容被**原地替换**，关掉没有回程。

## 二、根因（代码事实）

`abiModal` / `mvModalById` / `itemModalZh` / `natModalZh` 四个详情函数结构完全一致：

```js
function xxx(...){ ...拼 body...; l1Modal(标题, body); }
```

`l1Modal` 是**全局单容器**（`#l1Modal`，`.lmod` z-index 300）。所以任何一个详情调用都会覆盖上一个，天然没有"上层"概念。

### 二级层的实现（不重抄文案）

```js
function mqOpen(backLabel, fn){
  var m = mqEnsure(), orig = window.l1Modal, done = {v:0};
  window.l1Modal = function(title, html){
    done.v = 1;
    // 写到 #mqModalT / #mqModalB，并在最前面加「← 返回 队友·XX」
    ...
  };
  try{ fn() } finally { window.l1Modal = orig; }   // 立即还原
  if(!done.v) toast('这条没有可看的详情');
}
```

调用 `mqAbi('日照','队友 · 席多蓝恩')` 时，`fn` 内部照旧执行 `abiModal('日照','特性')` —— **文案、术语、判定口径全部同源**，只是落点从一级容器换到二级容器。这守住了「同名口径必须同源」这条铁律。

## 六、踩坑

1. **PowerShell 里的 python -c 引号地狱**：`python -c "... \"...\" ..."` 在 pwsh 下会被拆词（`+` 报 Unexpected token）。凡是含引号/中文的检查，一律写成 `.py` 文件再执行。
2. **补丁脚本的 `\n` vs `\r\n`**：`io.open(newline='')` 读出来的文本保留 CRLF，脚本里用 `\n` 拼的锚点必然 `count==0`（第一次就断言失败）。规则：**锚点与插入块都先 `.replace('\n','\r\n')`**；但拼接两个已转好的块时不要再整体 replace（`\r\n` 会被二次替换成 `\r\r\n`）。
3. **cu 点击落在哪**：窗口高 706px 时正文区原点 `(376,286)`，`getBoundingClientRect()` 给的是页面坐标，必须 `(376+left, 286+top)` 再 `/1920、/1080` 归一化。第一次点「← 返回」用估算坐标差 34px 落空（打到了标题行），改用 `.mqback` 的 rect 才点准。
4. **sticky 会遮内容**：`position:sticky; bottom:-2px` 让按钮常驻的同时压住最后两行四招。解决顺序是先压缩内容（删冗余行 / 把道具理由并入努力值行），再靠 sticky 兜底。
