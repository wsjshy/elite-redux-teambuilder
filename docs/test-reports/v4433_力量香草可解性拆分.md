# v4.433 力量香草：可解性单独成判据，只作并列备选

> 版本：v4.433（2026-11-25）｜用户提问：「有一个道具可以让蓄力技能不需要蓄力，你有考虑过吗」→ 确认口径：「对的，只是一个选择，肯定不是一定要带」

## 1. 起点与两处事实取证

**提问**：用户指出存在「让蓄力招不需要蓄力」的道具。

**取证一（道具本体）**：`ITM[284]` = `["284","Power Herb","力量香草","Allows immediate use of a move that charges first."]`；道具轴表 `AX_OVR` 中 `'力量香草':{burst:0.50,tech:0.50}`，`itemOneShot` 标记为一次性消耗。语义明确：**让「先蓄一回合」的招当回合打出**。

**取证二（引擎现状，关键）**：

- v4.432 的 `solarSelfSufficient(b)` 里写了「道具 = 力量香草」的免蓄力分支，但**全库 0 张卡配香草**（empty 0 / six 0），带可解蓄力招却没有香草的卡 empty 106 / six 133 → 该分支是**死代码**。
- 死代码成因：两边互相等待。①`costOf` 在评分阶段（该函数拿不到道具）先按「要多等一回合」给蓄力招扣分，使其进不了四招；②道具侧香草的 util 仅 0.4，抢不过剩饭 / 生命宝珠；③`itemScored`（≈L15950）的注释明确写「deriveBuilds 不消费 itemScored ⇒ 4680 流派零差异」——改道具权重根本不进配队卡。

**取证三（机制边界，v4.432 的口径过粗）**：v4.432 把 21 招统一当成「两回合招」。但香草只解其中**12 招**（先蓄一回合再打 / 消失一回合再命中）：

> 19 飞翔、76 日光束、143 神鸟猛击、467 暗影潜袭、566 潜灵奇袭、632 日光刃、553 冰冻伏特、554 极寒冷焰、728 流星光束、901 电光束、972 准备好了、988 剧毒俯冲

**不解僵直 9 招**（打完自己歇一回合，属攻击后的代价，不是攻击前的蓄力）：

> 63 破坏光线、307 爆炸烈焰、308 加农水炮、338 疯狂植物、416 终极冲击、439 岩石炮、722 流星突击、723 无极光束、963 幽灵夜曲

## 2. 设计（对齐用户口径：只是「一个选择」）

原则三条：

1. **只修判据，不硬推道具**。香草绝不进入「必带」逻辑，也不改动 `costOf` / 招式选择链路。
2. **只给「主攻就是那招」的进攻向卡作并列备选**。判据：主攻（本卡最高威力的伤害招）∈ 12 招 且 威力 ≥130；职责 ∈ {受队, 辅助, 肉盾} 时不给。
3. **备选排在主道具之后，文案写明一次性**。`it` 保留原主道具，香草 push 后 `slice(0,3)`；文案「让「X」当回合兑现（一次性，只够一次；要续航/常驻增伤就换剩饭/生命宝珠）」。

**量化前置（改前快照 `probe_herb3.js`）**：含可解蓄力招的卡里，蓄力招=本卡最大威力招者 empty 73 / six 95；其中爆发定位（GC 或 atk≥110 且 spd≥100）empty 10 / six 14。

## 8. 复盘：这一版真正学到的东西

1. **「写了但没生效」比「没写」更危险**。v4.432 里香草分支看起来是「已考虑」，实际是死代码——因为没有做全库计数去验证分支是否可达。「判据存在 ≠ 判据被触发」，新分支落地必须带一条可达性计数。
2. **一次性 ≠ 自足**。把香草塞进 `solarSelfSufficient`（意为「本卡不需要外界帮忙就能免蓄力」）语义上就是错的，它掩盖了「道具只能在第一次兑现」的事实，也掩盖了死代码。
3. **豁免条件必须与招式绑定，否则会串门**。R2 第一版让「晴天」去豁免全部可解蓄力招，直接把飞翔也豁免了——火神蛾只是恰好有日照特性才暴露出来。凡「特性/道具 → 招式」的豁免，条件与招式两侧都要收紧。
4. **同一份判据在一处对、在另一处死**（`it.some` vs `it[0]`）：凡是「判断这张卡有没有某道具」，主道具位与备选位必须分开表达。
