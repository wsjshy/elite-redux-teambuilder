# verify_invariants.js：名实不变量统一入口

**日期**：2026-11-17  
**引擎版本**：v4.397（本项为工具，不改引擎、不 bump 版本号）  
**产物**：`tools/headless/verify_invariants.js`（新建）

## 一、起因

用户对「后面很多时候都在打补丁，担心代码整体性降低」的诉求，v4.397 已从**数据层**处理了一半：把被各补丁块重抄 31 次的 id 表收回 `FUNC_MV` 单一真源（零漂移验证通过）。

但**断言层**还是老样子：名实一致性检查散在 9 个脚本里 —— `verify_v4391_off`（主力输出压制准入）、`verify_v4392_name`（骚扰消耗）、`verify_v4393_role`（roleTag 对齐）、`verify_v4395_wx`（手动天气招）、`verify_v4395b`（双墙/天气前缀/极光幕）、`verify_v4396`（日光招晴源）等。

**每加一条规则，就多一个脚本 + 多一块补丁 + 多一次全库遍历。** 这是「打补丁」在测试侧的形态：规则的知识散落在文件名的版本号里，没人能一眼说出「引擎现在总共承诺了哪些名实关系」。

本项把这件事收敛成一个入口：**以后加规则 = 在这里加一条 INV**，而不是再加一个脚本。

## 二、设计

- 一次 `deriveBuilds` 采集全库 **9850 张卡**（six 5645 / empty 4205），13 条不变量共用这一份数据。
- 每条不变量是纯函数 `(card) => null | 违规原因字符串`，无副作用、可单独枚举。
- 支持 `--probe`：只报告不判死，用于判据调试；正式模式全 0 才 `exit 0`。
- 可选 `scope`：给「子集作用域」的断言报告**适用卡数** —— 否则标记一旦丢失，断言会假装 0 违规（见第四节）。

## 四、判据修正（第一版探测出 3291 违规，几乎全是判据过宽）

第一版探测：8 条 PASS，5 条违规合计 3291。逐条核实后，**只有 1 条是判据之外的真残留候选**，其余 4 条是脚本口径比引擎严。

| 条 | 首版违规 | 根因 | 修正 |
|---|---|---|---|
| INV01 | 36 | `FUNC_MV.boost` 不含 74 生长，而引擎按名字认强化招 | 判据加 `BSTR` 名字正则（v4.392 同一套） |
| INV03 | 831 | 要求两面墙，但 **4 个格子常放不下两面墙**，行业惯例叫法就是一面墙 | 按 v4.395b 口径改为 ≥1 面（113 或 115），并加 `_v395NameKeep` 豁免 |
| INV09 | 11 | 未识别 `_v395NameKeep`（同物种已有同名卡，保留前缀） | 加豁免 |
| INV11 | 1025 | 误以为「流派名 → roleTag」是全库同义映射 | 见下 |
| INV13 | 1388 | 同上，且肉盾卡的性格只为取减项 | 同 INV11 |

### 最重要的一个发现：流派名与 roleTag 是**两个层次**的标签

首版把 `强化清场 → 强化`、`输出压制 → 输出` 当成全库映射，报出 897–1025 张「不符」。查引擎 `v4.393` 的实现（`index.html` L18337 起）才发现它的第一行守卫是：

```js
if(String(b.roleTag||'')!=='肉盾')return;
```

也就是说 v4.393 **只处理「肉盾 roleTag 挂着攻击向名字」这一种明显矛盾**，重算后登记 `_v393RoleAlign`。

具体例子：`#3 妙蛙花[0]「速攻强化清场」role=输出` —— 按名字看像矛盾，但它是攻击手：「速攻强化清场」说的是**战术打法**（先强化再清场），`roleTag=输出` 说的是**队伍站位**。两者本就可以不同。

所以 INV11/INV13 改为只守护 `_v393RoleAlign` 那批卡（回归防护：防止后续补丁把它们改回去），并加 `scope` 报告适用卡数。

**验证适用卡数 = 547，与 v4.393 的 aligned 547 完全一致** —— 证明断言真的在跑，不是空转 PASS。

## 六、使用纪律

1. **加规则就加 INV**，不要再新建 `verify_v43xx_xxx.js`。新脚本只用于「需要改前/改后快照对照」的漂移证明。
2. 新增 INV 必须先跑 `--probe` 看全库数字，再收紧判据 —— 首版 3291 违规里 3280 是判据错，不是代码错。
3. **子集作用域的断言必须给 `scope`**，否则标记丢失时它会永远 PASS。
4. 判据优先用「引擎已经在用的门」（`FUNC_MV`、`NEED_CFG.POWER_OK`、`_v39x` 豁免标记），其次才是新造阈值。
5. 发布前必跑（与 `gate.js` 同级），不进 `smoke.js` —— smoke 要保持秒级，本脚本全库 derive 是重活。

## 七、边界与不做

- 不改引擎、不改任何卡面：本项纯工具，全 0 是「当前引擎已经满足这 13 条」。
- 不替代既有 `verify_v43xx` 脚本：它们还承担「改前改后快照对照」的漂移证明，那是本入口不具备的能力（本入口只看当前态）。
- 不做 `verify_stall` / `verify_default` / `verify_ev` 这类「分档统计」断言 —— 它们不是名实关系，是数值分布。
- INV14（补槽兜底不落只强化自己的变化招 14/74/96/157）没有纳入：该规则的作用域是「补槽兜底」这一步，不是最终卡面（剑舞 14 作为主槽强化招完全合法），做成全局不变量会误报。
